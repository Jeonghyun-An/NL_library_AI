# round07 교본 (2) — 추출 단계: 스캔본 라우팅·VLM 쪽 병렬·ODL

> 이 교본 하나로 round07 전체를 클론코딩할 수 있어야 한다. 코드는 저장소 파일을 그대로 수록했다(`GIT_WORKFLOW.md` §개발 가이드 문서) — 새 파일은 `1a12c68` 의 전체, 있던 파일은 라운드 시작 `9798f46` 대비 diff 다. §2.5 의 `stages.py` 만 02 챕터 §2.14 이 전체 diff 를 싣는 파일의 행 범위 발췌다.

이 챕터는 적재 파이프라인의 첫 단계, **PDF → 쪽 텍스트** 를 다룬다. 1티어 ODL(opendataloader-pdf)의 결과를 쪽마다 믿을지 정하고, 못 믿는 쪽만 2티어 VLM OCR 로 보내는 2티어 라우팅이다. round07 은 여기서 처리량 하나와 결함 여럿을 고쳤다.

**1-3. 추출 흐름의 모양.**

```text
run_extract (stages.py)                       t_first 부터 잰다
├─ extract_text                               데드라인 = INGEST_EXTRACT_DEADLINE(2700초), 시작부터
│   ├─ 1티어 extract_text_opendataloader(time_budget = 데드라인 − 경과)
│   │    ├─ 원본 변환        상한 min(max(10, 쪽수 × 1.5), 남은 시간) · 자식 파이썬(새 세션) · -Xmx3g
│   │    ├─ 실패 → fitz 재저장본 변환                      odl_fallback = "resaved"
│   │    └─ 또 실패 → fitz 텍스트                           odl_fallback = "fitz"
│   │    → 쪽 구분자로 나눈 뒤 &amp; &lt; &gt; 되돌리기 · 그림만 있는 쪽은 빈 쪽으로
│   ├─ fitz 쪽 텍스트 → 되풀이 줄 · 원래 길이 · 뺀 길이 → 문서 단위 스캔본인가
│   ├─ 쪽 판정(쪽 순서) → ODL 채택 | OCR 목록(문서당 60쪽까지)
│   ├─ _ocr_pages: 동시 2건 · 렌더 잠금 · asyncio.timeout(남은 시간) · length 면 꼬리 걷기
│   └─ 쪽 순서로 조립
├─ 섹션 0개?
│   ├─ 첫 추출에 OCR 오류·데드라인 → vlm_error
│   ├─ short_kept == 0             → no_text
│   └─ 강제 OCR 재추출(남은 시간, 하한 60초) → 그래도 0개면 vlm_error | no_text
├─ PDF 메타(카탈로그 row 가 없을 때) — ODL time_budget = 남은 시간(하한 2초)
└─ meta: forced_ocr · vlm_truncated · extract_deadline_hit · ocr_errors · ocr_rejected
         · render_errors · odl_fallback · odl_seconds
```

시간 상한은 모두 추출 데드라인 하나에 묶인다.

| 시간 | 값 | 어디서 |
|---|---|---|
| 추출 데드라인 | `INGEST_EXTRACT_DEADLINE` 2,700초(`extract_text` 시작부터) | ODL 의 `time_budget`, `_ocr_pages` 의 `asyncio.timeout` |
| ODL 시도 하나 | min(max(10, 쪽수 × 1.5), 남은 시간). 2초(`_ODL_MIN_ATTEMPT_SECONDS`) 미만이면 띄우지 않는다 | `extract_text_opendataloader` |
| ODL 자식의 자기 종료 | int(상한) + 5초 | `_ODL_CHILD` |
| 강제 재추출 | 2,700 − 첫 추출 경과, 하한 60초 | `run_extract` |
| PDF 메타의 ODL | 2,700 − 첫 추출부터 경과, 하한 2초 | `run_extract` → `extract_pdf_metadata` |
| stale 판정 | `INGEST_STAGE_TIMEOUT_EXTRACT` 3,600초 | 설정이 기동 때 `2,700 + 60 + PDF_META_TIMEOUT 60 + 10 = 2,830 < 3,600` 을 본다(03 챕터 §2.29) |

이 챕터가 읽는 설정이다. 정의와 검증은 03 챕터 §2.29.

| 설정 | 기본 | 쓰는 곳 |
|---|---|---|
| `EXTRACT_MIN_CHARS_PER_PAGE`(있던 값) | 50 | 짧은 쪽 기준(`MIN_CHARS_PER_PAGE`) |
| `VLM_MAX_PAGES_PER_DOC`(있던 값) | 60 | 문서당 OCR 쪽 상한 |
| `VLM_MAX_TOKENS`(있던 값) | 4096 | VLM 응답 상한 — 다 쓰면 `finish_reason == "length"` |
| `VLM_PAGE_CONCURRENCY` | 2 | 문서 안 동시 OCR 요청 |
| `INGEST_EXTRACT_DEADLINE` | 2700 | 추출 데드라인(초) |
| `SCAN_REPEAT_LINE_RATIO` | 0.6 | 되풀이 줄 = 문서 쪽의 이 비율 이상에 나오는 줄 |
| `SCAN_SHORT_PAGE_RATIO`·`SCAN_MIN_PAGES` | 0.5·3 | 짧은 쪽 비율이 이보다 크고 이 쪽수 이상이면 스캔본 |
| `ODL_TIMEOUT_BASE_SECONDS`·`ODL_TIMEOUT_PER_PAGE_SECONDS` | 10.0·1.5 | ODL 상한 |
| `ODL_IMAGE_OUTPUT` | `off`(`off`·`embedded`·`external` 만 받는다) | ODL `image_output` |
| `ODL_JAVA_MAX_HEAP` | `3g`(`-Xmx` 크기 형식, 1g 이상만 받는다) | ODL 자식의 `JAVA_TOOL_OPTIONS` |
| `FORCED_REEXTRACT_FLOOR_SECONDS`(상수) | 60 | 강제 재추출 하한 |

## 2. 구현 (클론코딩)

### 2.1 `page_routing.py` — 쪽 판정 순수 함수

**책임.** ODL 본문이 짧은 쪽을 OCR 로 보낼지 정하고, VLM 출력의 되풀이 꼬리를 걷는다. fitz·httpx 를 import 하지 않는 순수 함수만 둔다 — `extract_text` 가 fitz 로 구한 쪽별 텍스트를 넘긴다. 그래서 판정 하나하나를 PDF 없이 테스트하고, 회귀 하네스(`research/round07-ingest-regression`)가 같은 함수를 그대로 부른다.

**함수 지도.**

| 함수 | 하는 일 | 쓰는 곳 |
|---|---|---|
| `body_len(text)` | `[그림]`·`<br>` 태그·표 구조 문자(`\|-:`)·공백을 뺀 글자 수 | 쪽 판정 전부, `trim_repetition` |
| `collapse_br_runs(text)` | 3개 이상 이어진 `<br>`(사이의 공백·탭 포함) → `<br>` 하나 | `_clean_text`·`_strip_figure_markers` |
| `repeated_lines(page_texts, ratio, max_len=40)` | 문서 쪽의 `ratio` 이상에 되풀이되는 40자 이하 줄의 키 | `extract_text` |
| `strip_lines(text, lines)` | 그 키에 해당하는 줄을 뺀다 | `extract_text` |
| `is_scan_document(short_flags, *, min_pages, ratio)` | `min_pages` 쪽 이상이고 짧은 쪽 비율 > `ratio` | `extract_text` |
| `short_page_needs_ocr(*, fitz_len_stripped, fitz_len_raw, doc_is_scan, force, min_chars)` | ODL 본문 50자 미만 쪽의 OCR 여부와 사유 | 쪽 판정 루프 |
| `trim_repetition(text)` | VLM 출력의 되풀이 꼬리를 한 벌만 남기고, 퇴화 출력인지 | `_extract_with_vlm` |

**왜 이렇게 짰나.**

- **`body_len` 은 `<br>` 를 세지 않는다.** 옛 `_body_len`(extractor 안)은 `[그림]` 과 표 구조 문자만 뺐다. 그래서 텍스트 층이 없는 쪽(fitz 0자)도 빈 표 격자 `|<br>|<br>|…` 가 50자를 넘겨 '본문 충분'으로 채택됐다. 이제 그런 쪽은 50자 미만이 되어 짧은 쪽 분기의 'fitz 0자 → OCR' 을 탄다. 칸에 글자가 있는 표는 그 글자만큼 센다(`| 본문 | 12.5 |<br>` → 6자).
- **`<br>` 연속은 `<br>` 하나로 줄인다 — 줄바꿈으로 바꾸지 않는다.** 1~2개는 표 칸 안 줄바꿈이라 둔다. 줄바꿈을 넣으면 마크다운 표 행이 쪼개진다. 멱등이다(두 번 해도 같다).
- **되풀이 줄의 키는 숫자 묶음을 `#` 하나로 접는다(`_line_key`).** 쪽 번호·연도만 다른 머리말(`한국문학연구 제3집 227`·`… 228`)과 스탬프(`Copyright (C) 2002 Nuri Media Co., Ltd.` → `Copyright (C) # Nuri Media Co., Ltd.`, 36자)를 같은 줄로 본다. 공백도 하나로 접는다. 한 쪽 안의 중복은 한 번으로 센다. 40자를 넘는 줄은 후보가 아니다 — 본문 문장이 우연히 되풀이되어도 빼지 않게. 쪽이 하나면 되풀이를 판단할 수 없어 빈 집합이고, 필요한 쪽 수는 `max(2, ceil(쪽 수 × ratio))` 다.
- **`is_scan_document` 는 '과반 초과'다.** 짧은 쪽이 정확히 절반이면 스캔본이 아니다. 쪽이 없거나 `min_pages <= 0` 인 설정에서도 0 으로 나누지 않는다.
- **`short_page_needs_ocr` 의 판정 순서**: 강제(섹션 0개 재추출) → fitz 0자(텍스트 층 없음) → 문서 단위 스캔본 → fitz **원래** 길이 50자 이상(ODL 이 놓친 본문) → 그 밖에는 '원래 짧은 쪽'(ODL 채택). 비스캔·비강제 문서에서는 옛 규칙과 칸마다 같다 — `0 < 원래 길이 < 50` 인 쪽만 ODL 채택이다. 스캔본·강제는 OCR 을 더할 뿐 빼지 않는다. `fitz_len_stripped` 는 이 판정에 쓰지 않고 시그니처만 남겼다(공통 계약). 되풀이 줄 뺀 길이는 `extract_text` 가 문서 단위 판정(`short_flags`)에만 쓴다(Q2).
- **`trim_repetition` 은 끝에서 주기를 찾는다.** `_tail_period` 가 주기 `p`(1~200자)마다 끝에서부터 `text[i] == text[i + p]` 가 이어지는 가장 앞 자리를 찾는다. 반복 구간이 `max(3p, 60)` 자 이상이고 한 벌이 공백만이 아니면 후보다. 가장 앞에서 시작하는 후보를 골라 한 벌만 남기고 자른다. 마지막 반복이 `max_tokens` 로 중간에 끊겨 있어도 주기 비교는 그대로 맞는다. 다듬은 뒤 실질 본문이 20자 미만이거나, 남은 줄이 5줄 이상이고 그 절반 이상이 앞 줄의 되풀이면 퇴화 출력이다(`| | | |` 빈 표 행 수백 줄 같은 것).

**리뷰에서 바뀐 점.**

- `2f2923b`(처음)는 `<br>` 연속을 **줄바꿈 하나**로 줄였다. `18e72e0`(Task 3 리뷰)이 `<br>` 하나로 바꿨다 — 줄바꿈이 표 칸 안 문단 사이에 끼면 표 행이 쪼개져 `paper_enricher` 의 표 추출이 줄었다(KCI_FI002990049 15 → 13개).
- 처음(`0487057`)에는 '원래 짧은 쪽'과 'ODL 이 놓친 본문'을 **되풀이 줄 뺀 길이**로 갈랐다. `5b3be2e`(Task 3 리뷰)가 본문 손실 경로를 막으려 판정 순서를 위처럼 바꾸고, 뺀 길이는 문서 단위 판정에만 쓰게 했다. `is_scan_document` 의 0 나누기도 이때 막았다.

**파일**: `app/services/ingestion/page_routing.py` (새 파일)

```python
"""추출 2티어 라우팅의 페이지 판정 — 순수 함수만 둔다.

fitz·httpx 를 import 하지 않는다. extractor.extract_text 가 fitz 로 구한 쪽별 텍스트를
넘기고, 여기서는 ODL 본문이 짧은 쪽을 OCR 로 보낼지만 정한다.
"""
import math
import re
from collections import Counter

_STRUCT_CHARS = str.maketrans("", "", "|-: \t\n\r")
_BR_TAG = re.compile(r"<br\s*/?>", re.IGNORECASE)
_BR_RUN = re.compile(r"(?:<br\s*/?>[ \t]*){3,}", re.IGNORECASE)
_WS = re.compile(r"\s+")
_DIGITS = re.compile(r"\d+")


def body_len(text: str) -> int:
    """[그림] 마커·<br> 태그·표 구조 문자·공백을 뺀 실질 본문 글자 수."""
    if not text:
        return 0
    return len(_BR_TAG.sub("", text.replace("[그림]", "")).translate(_STRUCT_CHARS))


def collapse_br_runs(text: str) -> str:
    """3개 이상 이어진 <br> 를 <br> 하나로 줄인다(1~2개는 표 칸 안 줄바꿈이라 둔다).

    줄바꿈("\\n")으로 바꾸지 않는다 — 표 칸 안 문단 사이의 <br><br><br> 가 마크다운 표 행을 쪼개
    표 추출이 줄어든다(KCI_FI002990049 15→13개).
    """
    return _BR_RUN.sub("<br>", text)


def _line_key(line: str) -> str:
    # 쪽 번호·연도만 다른 머리말·꼬리말을 같은 줄로 보려고 숫자 묶음을 '#' 하나로 접는다.
    return _DIGITS.sub("#", _WS.sub(" ", line).strip())


def repeated_lines(page_texts: list[str], ratio: float, max_len: int = 40) -> set[str]:
    """문서 쪽의 ratio 이상에 되풀이되는 max_len 자 이하 줄의 키(_line_key) 집합.

    한 쪽 안의 중복은 한 번으로 센다. 쪽이 하나뿐이면 되풀이를 판단할 수 없어 빈 집합이다.
    """
    if len(page_texts) < 2:
        return set()
    counts: Counter[str] = Counter()
    for text in page_texts:
        keys = {_line_key(line) for line in text.split("\n")}
        counts.update(k for k in keys if k and len(k) <= max_len)
    need = max(2, math.ceil(len(page_texts) * ratio))
    return {k for k, c in counts.items() if c >= need}


def strip_lines(text: str, lines: set[str]) -> str:
    """repeated_lines 가 돌려준 키에 해당하는 줄을 뺀다."""
    if not lines:
        return text
    return "\n".join(line for line in text.split("\n") if _line_key(line) not in lines)


def is_scan_document(short_flags: list[bool], *, min_pages: int, ratio: float) -> bool:
    """min_pages 쪽 이상 문서에서 짧은 쪽 비율이 ratio 를 넘으면 문서 단위 스캔본이다.

    0쪽 문서나 min_pages <= 0 설정에서도 0 으로 나누지 않는다(쪽이 없으면 스캔본이 아니다).
    """
    if not short_flags or len(short_flags) < min_pages:
        return False
    return sum(short_flags) / len(short_flags) > ratio


def short_page_needs_ocr(
    *,
    fitz_len_stripped: int,
    fitz_len_raw: int,
    doc_is_scan: bool,
    force: bool,
    min_chars: int,
) -> tuple[bool, str]:
    """ODL 본문이 min_chars 미만인 쪽을 OCR 로 보낼지와 그 사유.

    판정 순서: 강제 → fitz 0자(텍스트 층 없음) → 문서 단위 스캔본 → fitz 원래 길이가 min_chars 이상
    (ODL 이 놓친 본문) → 그 밖에는 원래 짧은 쪽이라 ODL 채택.

    비스캔·비강제 문서에서는 옛 코드와 모든 칸이 같다 — 0 < fitz 원래 길이 < min_chars 인 쪽만 ODL 을
    채택하고 나머지는 OCR 한다. 문서 전체가 스캔본(또는 강제)일 때만 그 짧은 쪽도 OCR 로 보낸다 —
    쪽 단위로 보내면 디지털 논문의 이미지 표지·간지가 다시 VLM 을 탄다.

    fitz_len_stripped(되풀이 줄을 뺀 길이)는 문서 단위 스캔 판정(extract_text 의 short_flags)에서만
    쓰고 이 판정에는 쓰지 않는다. 되풀이 줄을 빼면 짧아도 fitz 원래 길이가 길면, ODL 이 이미지 본문 쪽의
    글자를 놓친 것일 수 있어(KCI_FI003011274 1·2·8·9쪽) 옛 규칙대로 OCR 한다. 시그니처만 유지한다.
    """
    if force:
        return True, "강제 OCR(섹션 0개 재추출)"
    if fitz_len_raw == 0:
        return True, "텍스트 층 없음(fitz 0자)"
    if doc_is_scan:
        return True, "스캔본 문서(짧은 쪽 과반)"
    if fitz_len_raw >= min_chars:
        return True, "ODL 이 놓친 본문"
    return False, "원래 짧은 쪽"


def _tail_period(text: str, *, max_unit: int, min_repeats: int, min_span: int) -> tuple[int, int] | None:
    # 끝에서부터 text[i] == text[i + p] 가 이어지는 가장 앞 자리를 주기 p 마다 찾는다.
    # 마지막 반복이 중간에 잘려 있어도(max_tokens 소진) 주기 비교는 그대로 맞는다.
    n = len(text)
    best: tuple[int, int] | None = None
    for p in range(1, min(max_unit, n // min_repeats) + 1):
        i = n - p - 1
        while i >= 0 and text[i] == text[i + p]:
            i -= 1
        start = i + 1
        if n - start >= max(p * min_repeats, min_span) and text[start:start + p].strip():
            if best is None or start < best[0]:
                best = (start, p)
    return best


def trim_repetition(text: str) -> tuple[str, bool]:
    """VLM 이 max_tokens 까지 같은 줄·구절을 되풀이한 꼬리를 걷어 낸다.

    returns (다듬은 텍스트, 퇴화 출력인가). 되풀이는 한 번만 남긴다. 다듬은 뒤 실질 본문이
    20자 미만이거나, 남은 줄(5줄 이상)의 절반 이상이 앞 줄의 되풀이면 퇴화 출력이다.
    """
    found = _tail_period(text, max_unit=200, min_repeats=3, min_span=60)
    trimmed = text[: found[0] + found[1]].rstrip() if found else text.rstrip()
    if body_len(trimmed) < 20:
        return trimmed, True
    lines = [line.strip() for line in trimmed.split("\n") if line.strip()]
    if len(lines) >= 5 and (len(lines) - len(set(lines))) / len(lines) >= 0.5:
        return trimmed, True
    return trimmed, False
```

**(가) `<br>`·`[그림]` 정리와 `_adopt_odl` (spec 14).** `_clean_text` 는 맨 앞에서 `collapse_br_runs` 를 부른다 — 빈 표 격자의 `<br>` 수천 개가 섹션 본문을 채우지 않게. `_strip_figure_markers` 는 `[그림]` 을 지운 뒤 한 번 더 줄인다. `[그림]<br><br>[그림]` 반복 격자는 사이의 `<br>` 가 2개씩이라 첫 정제로는 안 줄고, 마커를 지워야 긴 연속이 되기 때문이다. `_adopt_odl` 은 "ODL 결과를 이 쪽의 최종 결과로 쓴다"를 한 곳에 모았다. 본문 채택·원래 짧은 쪽뿐 아니라 OCR 결과가 없는 쪽(VLM 60쪽 상한·요청 실패·퇴화·렌더링 실패·데드라인)과 fitz 로 안 열리는 파일도 이 길을 탄다. 예전에는 상한에 걸린 쪽과 OCR 이 실패한 쪽이 마커를 남긴 채 채택됐다. 옛 `_STRUCT_CHARS`·`_body_len` 은 `page_routing.body_len` 으로 옮겨 지운다.

**(나) 쪽 판정 — 문서 단위 스캔본 (spec 7).** `extract_text` 는 fitz 로 문서를 연 뒤, 판정 루프 전에 쪽마다 fitz 텍스트를 한 번 받는다(`fitz_texts`). 쪽 하나의 `get_text` 가 실패하면(`too many nested graphics states` 등) 그 쪽만 빈 텍스트로 두고 오류를 남긴다 — 쪽 하나의 파싱 실패가 문서 전체 추출을 막지 않게. 이 텍스트로 세 가지를 만든다. 문서 전체의 되풀이 줄(`repeated`), 쪽별 원래 길이(`fitz_raw_lens`), 되풀이 줄 뺀 길이(`fitz_stripped_lens`)다. 쪽마다 'ODL 본문 < 50 이고 뺀 길이 < 50' 이면 짧은 쪽이고(`short_flags`), `is_scan_document` 가 문서 단위 스캔본을 정한다.

**(다) VLM 잘림 (spec 11).** `_extract_with_vlm` 은 thinking 재시도까지 마친 뒤, 비추론 모드에서도 `finish == "length"` 를 본다. 잘렸으면 `trim_repetition` 으로 되풀이 꼬리를 걷고 `PageResult.truncated=True` 로 표시한다. 걷어도 퇴화면 `VlmDegenerateOutput` 을 던져 호출부가 그 쪽의 ODL 결과를 쓰게 한다. 렌더링은 `_render_png_b64` 로 뺐다. `get_pixmap` 예외(예: FzErrorLimit)는 `PageRenderError` 로 바꾼다 — 다시 해도 같은 결정적 실패라 요청 실패와 따로 센다.

**(라) 문서 안 OCR 병렬과 추출 데드라인 (spec 2·16).** `_ocr_pages` 가 `ocr_jobs` 를 받는다.

- 요청은 `asyncio.Semaphore(max(1, VLM_PAGE_CONCURRENCY))` 안에서 동시에 나간다. 0 이하 설정이면 세마포어가 막혀 데드라인까지 아무 쪽도 OCR 하지 못하므로 최소 1이다. httpx 클라이언트는 하나를 나눠 쓴다.
- 렌더링은 `_render_page` 가 `asyncio.Lock` 안에서 이벤트 루프 스레드로 한다. PyMuPDF 는 다중 스레드를 지원하지 않는다. 잠금은 동시에 도는 코루틴이 한 번에 한 쪽만 렌더하게 지키는 자리다.

- 데드라인. `remaining`(데드라인 − 경과)이 0 이하면 렌더링도 요청도 하지 않는다. 아니면 `asyncio.timeout(remaining)` 으로 `gather` 를 감싼다. 넘으면 `deadline_hit` 이고 끝내지 못한 쪽 수를 오류로 남긴다. `finally` 에서 남은 태스크를 취소하고 회수한다 — 데드라인·바깥 취소·예외 어느 쪽이든. 바깥 취소의 `CancelledError` 는 잡지 않아 그대로 올라간다.

### 2.5 `stages.py` 의 `run_extract` — 섹션 0개·데드라인·meta (발췌)

**책임.** 섹션 0개를 추출 성공으로 넘기지 않는다. 다시 해도 같은 실패(`no_text`)와 다시 하면 달라질 수 있는 실패(`vlm_error`)를 가르고, 추출 단계 전체를 데드라인 안에 묶고, 카나리에서 셀 값을 아이템 meta 로 낸다. `no_text` 를 재시도하지 않고(attempt 를 한도로) `vlm_error` 를 체크포인트 `pending`·백오프(120·600초)로 다시 집는 것은 잡 런타임의 몫이다.

**섹션 0개 결정표** (위에서부터 먼저 맞는 줄):

| 상황 | 결과 |
|---|---|
| 쪽이 하나도 없음. OCR 실패가 거절·렌더링 실패뿐(OCR 오류·데드라인 없음) | `no_text` — "텍스트 추출 실패 — 본문 없음(N쪽)" + 사유 |

| 섹션 0개. 첫 추출에 `ocr_errors` 또는 `deadline_hit` | `vlm_error` — 강제 재추출 없음 |
| 섹션 0개. `short_kept == 0` | `no_text` — 강제 OCR 로 바뀔 쪽이 없다 |

- **`_deterministic_ocr_cause`.** `no_text` 메시지 끝에 ` · VLM 거절 N쪽·렌더링 실패 M쪽: [오류 앞 3개]` 를 붙인다(0 인 칸은 뺀다). 실패한 아이템은 meta 가 남지 않아 사유가 `last_error` 에만 남는다. VLM·DPI·`max-model-len` 을 고친 뒤 `last_error` 에 `거절` 이 든 `no_text` 만 골라 다시 보낸다.

# 쪽 판정의 입력(ODL 본문 길이·fitz 원래 길이·되풀이 줄 뺀 길이·표 셀 충전율·문서 단위 스캔본 여부·강제)을

MIN_CHARS = 50


class _FakePage:
    def __init__(self, number: int, text: str = "", error: Exception | None = None):
        self.number = number
        self._text = text
        self._error = error

    def get_text(self, *_a, **_kw) -> str:
        if self._error is not None:
            raise self._error
        return self._text


class _FakeDoc:
    def __init__(self, pages: list[_FakePage]):
        self._pages = pages

    def __len__(self) -> int:
        return len(self._pages)

    def __iter__(self):
        return iter(self._pages)

    def __getitem__(self, i: int) -> _FakePage:
        return self._pages[i]

    def load_page(self, i: int) -> _FakePage:
        return self._pages[i]

    def close(self) -> None:
        pass


class _NullClient:
    """httpx.AsyncClient 대용 — 목 VLM 은 클라이언트를 안 쓰고, 진짜는 만들 때마다 TLS 컨텍스트를 읽어 느리다."""

    async def __aenter__(self):
        return self

    async def __aexit__(self, *_exc):
        return False


def _patch_fakes(monkeypatch) -> dict:
    """extract_text 의 fitz 문서·ODL·VLM·httpx 를 목으로 바꾸고, 호출마다 채우는 상태 dict 를 돌려준다."""
    state: dict = {"pages": [], "odl": {}, "fill": {}, "ocr": []}

    async def fake_odl(file_path, book_id, *, file_bytes=None, max_pages=None, time_budget=None):
        res = ExtractionResult(book_id=book_id, total_pages=len(state["odl"]))
        res.pages = [PageResult(n, t, "opendataloader", 0.95) for n, t in sorted(state["odl"].items())]
        res.table_fill_ratios = dict(state["fill"])
        return res

    async def fake_vlm(page, client, *, prompt_type="ocr", **_kw):
        state["ocr"].append(page.number)
        return PageResult(page.number, f"VLM 본문 {page.number}", "vlm", 0.9)

    monkeypatch.setattr(extractor, "extract_text_opendataloader", fake_odl)
    monkeypatch.setattr(extractor, "_extract_with_vlm", fake_vlm)
    monkeypatch.setattr(extractor.cfg, "OCR_ENGINE", "vlm")
    monkeypatch.setattr(extractor.fitz, "open", lambda *_a, **_kw: _FakeDoc(state["pages"]))
    monkeypatch.setattr(extractor.httpx, "AsyncClient", _NullClient)
    return state


def _legacy_sends_to_ocr(odl_len: int | None, raw: int, fill: float | None) -> bool:
    """문서 단위 스캔본 판정을 넣기 전 extract_text 의 쪽 분기를 그대로 옮긴 옛 판정(d85df93·0df3001·8b1511a 이후) — OCR 로 가는가."""
    if odl_len is None:  # ODL 누락
        return True
    if fill is not None and fill < 0.30:  # 표 셀 충전율 낮음
        return True
    if odl_len >= MIN_CHARS:  # CMap 손상 의심: fitz 원래 길이가 ODL 의 2배를 넘으면
        return raw > odl_len * 2
    return not 0 < raw < MIN_CHARS  # 원래 짧은 쪽(0 < fitz < 50)만 ODL 채택, fitz 0자·50자 이상은 OCR


def _expected_ocr(odl_len: int | None, raw: int, fill: float | None, *, scan: bool, force: bool) -> bool:
    if _legacy_sends_to_ocr(odl_len, raw, fill):
        return True
    # 옛 규칙이 ODL 을 채택하던 칸 — 짧은 쪽(ODL < 50)만 스캔본 문서·강제에서 OCR 로 바뀐다
    return odl_len < MIN_CHARS and (scan or force)


def _chunks(n: int, ch: str, width: int = 30) -> list[str]:
    """ch 를 n 글자 모은 줄들 — 한 줄이 40자 이하라야 되풀이 줄 후보가 된다."""
    return [ch * min(width, n - i) for i in range(0, n, width)]


def _build_case(
    state: dict, odl_len: int | None, raw: int, stripped: int, fill: float | None, *, scan: bool
) -> None:
    """쪽 0 이 검사 대상(ODL 길이 odl_len — None 이면 ODL 누락, fitz 원래 길이 raw, 되풀이 줄 뺀 길이 stripped).

    쪽 1~4 는 채움 쪽이다: 머리말(문서 전체에 되풀이되는 줄)을 만들고, scan 이면 짧은 쪽이 과반이 되게
    텍스트 층에는 되풀이 줄(머리말 + 쪽 0 에는 없는 60자 스탬프)뿐·ODL 은 그림뿐인 쪽으로 — fitz 원래
    길이는 50자를 넘어도 되풀이 줄을 빼면 0이라 짧은 쪽이다 — 아니면 본문이 충분한 쪽으로 채운다.
    """
    header = _chunks(raw - stripped, "나")
    stamp = _chunks(60, "라")
    pages = [_FakePage(0, "\n".join(_chunks(stripped, "가") + header))]
    odl: dict[int, str] = {}
    if odl_len is not None:
        odl[0] = "다" * odl_len if odl_len else "[그림]"
    for k in range(1, 5):
        if scan:
            pages.append(_FakePage(k, "\n".join(stamp + header)))
            odl[k] = "[그림]"
        else:
            body = chr(0xB300 + k)
            pages.append(_FakePage(k, "\n".join(_chunks(60, body) + header)))
            odl[k] = body * 60
    state["pages"] = pages
    state["odl"] = odl
    state["fill"] = {} if fill is None else {0: fill}


def test_decision_table_matches_legacy_rule_outside_scan_and_force(monkeypatch):
    """비스캔·비강제 문서의 모든 칸은 옛 규칙과 같고, 스캔본·강제 문서는 ODL < 50 인 짧은 쪽만 OCR 가 더해진다."""

    raws = [0, 1, 30, 49, 50, 51, 60, 100, 101, 120, 121, 260, 261]
    fills = [None, 0.29, 0.30]
    harness_errors: list[str] = []
    mismatches: list[str] = []
    checked = 0

    async def sweep() -> None:
        nonlocal checked
        for odl_len in odl_lens:
            for raw in raws:

                    for fill in fills:

                            _build_case(state, odl_len, raw, stripped, fill, scan=scan)

                            lens = _lens([extractor._clean_text(p.get_text()) for p in state["pages"]])
                            flags = [
                                page_routing.body_len(state["odl"].get(n, "")) < MIN_CHARS and lens[1][n] < MIN_CHARS
                                for n in range(5)
                            ]
                            is_scan = page_routing.is_scan_document(
                                flags, min_pages=extractor.cfg.SCAN_MIN_PAGES, ratio=extractor.cfg.SCAN_SHORT_PAGE_RATIO
                            )
                            if (lens[0][0], lens[1][0], is_scan) != (raw, stripped, scan):
                                harness_errors.append(
                                    f"odl={odl_len} raw={raw} stripped={stripped} scan={scan}: "
                                    f"만들어진 값 raw={lens[0][0]} stripped={lens[1][0]} scan={is_scan}"
                                )
                                continue
                            for force in (False, True):
                                state["ocr"] = []
                                await extractor.extract_text(
                                    None, "T_TABLE", file_bytes=b"x", force_ocr_short_pages=force
                                )
                                got = 0 in state["ocr"]
                                want = _expected_ocr(odl_len, raw, fill, scan=scan, force=force)
                                checked += 1
                                if got != want:
                                    mismatches.append(

                                        f"scan={scan} force={force}: OCR {got}, 기대 {want}"
                                    )

    asyncio.run(sweep())
    assert not harness_errors, "\n".join(harness_errors[:10])
    assert checked > 2000
    assert not mismatches, f"{len(mismatches)}/{checked} 칸이 다르다:\n" + "\n".join(mismatches[:15])

def _sleeping_grandchild_script(pid_file: Path) -> str:
    """잠자는 손자(java 자리)를 띄워 pid 를 남기고 자기도 잠드는 자식 — pid 는 다 쓴 뒤 이름을 바꿔 반쯤 쓴 파일이 없다."""
    tmp = str(pid_file) + ".tmp"
    return (
        "import os, subprocess, sys, time\n"
        "p = subprocess.Popen([sys.executable, '-c', 'import time; time.sleep(20)'])\n"
        f"open({tmp!r}, 'w').write(str(p.pid))\n"
        f"os.replace({tmp!r}, {str(pid_file)!r})\n"
        "time.sleep(20)\n"
    )


def _wait_for_pid_file(pid_file: Path, seconds: float = 5.0) -> int:
    for _ in range(int(seconds / 0.05)):
        if pid_file.exists():
            return int(pid_file.read_text())
        time.sleep(0.05)
    pytest.fail(f"{seconds:g}초 안에 손자 pid 를 받지 못했다")


def _gone(pid: int) -> bool:
    """프로세스가 끝났는가 — 없거나, 회수 전 좀비(Z)이거나, 확인하는 사이 /proc 에서 사라졌다(리눅스)."""
    try:
        os.kill(pid, 0)
    except ProcessLookupError:
        return True
    try:
        with open(f"/proc/{pid}/stat") as f:
            return f.read().rsplit(")", 1)[1].split()[0] == "Z"
    except FileNotFoundError:
        return True

BODIES = [
    ["Alpha chapter reviews the archival record of royal court", "appointments and the ranks given to envoys from abroad."],

def _pdf(pages: list[list[str]]) -> bytes:
    doc = fitz.open()
    for lines in pages:
        page = doc.new_page(width=420, height=595)
        for i, line in enumerate(lines):
            page.insert_text((36, 60 + 14 * i), line, fontsize=9)
    data = doc.tobytes()
    doc.close()
    return data


def _route(monkeypatch, pdf: bytes, odl_texts: dict[int, str], **kwargs) -> tuple[list[int], ExtractionResult]:
    async def fake_odl(file_path, book_id, *, file_bytes=None, max_pages=None, time_budget=None):
        res = ExtractionResult(book_id=book_id, total_pages=len(odl_texts))
        res.pages = [PageResult(n, t, "opendataloader", 0.95) for n, t in sorted(odl_texts.items())]
        return res

    ocr_calls: list[int] = []

    async def fake_vlm(page, client, *, prompt_type="ocr", **_kw):
        ocr_calls.append(page.number)
        return PageResult(page.number, f"VLM 본문 {page.number}", "vlm", 0.9)

    monkeypatch.setattr(extractor, "extract_text_opendataloader", fake_odl)
    monkeypatch.setattr(extractor, "_extract_with_vlm", fake_vlm)
    monkeypatch.setattr(extractor.cfg, "OCR_ENGINE", "vlm")
    result = asyncio.run(extractor.extract_text(None, "T_KEPT", file_bytes=pdf, **kwargs))
    return sorted(ocr_calls), result


def test_short_kept_counts_exactly_the_pages_forced_ocr_changes(monkeypatch):
    """디지털 문서의 간지 2쪽(0 < fitz < 50)은 '원래 짧은 쪽'으로 ODL 채택 → short_kept 2. 강제 OCR 은 그 2쪽만 더 보낸다."""
    pdf = _pdf(BODIES + [["Part Two"], ["Part Three"]])
    odl = {**{n: " ".join(BODIES[n]) for n in range(3)}, 3: "Part Two", 4: "Part Three"}
    ocr, result = _route(monkeypatch, pdf, odl)
    assert (ocr, result.short_kept) == ([], 2)
    forced_ocr, forced = _route(monkeypatch, pdf, odl, force_ocr_short_pages=True)
    assert (forced_ocr, forced.short_kept) == ([3, 4], 0)


def test_scan_document_keeps_no_short_page(monkeypatch):
    """스캔본(텍스트 층 없음)은 짧은 쪽을 모두 OCR 로 보내 short_kept 0 — 강제 재추출이 바꿀 쪽이 없다."""
    pdf = _pdf([[]] * 4)
    ocr, result = _route(monkeypatch, pdf, {n: "[그림]" for n in range(4)})
    assert (ocr, result.short_kept) == ([0, 1, 2, 3], 0)

| 묶음 | 문서 | 스캔본 판정 | OCR 쪽 비율 옛 → 새 | 문서당 늘어난 쪽 |

- 실패 블록 318건은 모두 스캔본으로 잡혔다. 새 규칙은 6,844쪽을 OCR 로 보내고, 그중 7쪽은 61·66쪽 문서 둘의 VLM 60쪽 상한에 걸려 실제로는 6,837쪽이 OCR 된다.
- **비스캔 문서는 OCR 에서 빠진 쪽도, 새로 OCR 된 쪽도 0이다.** 규칙이 갈린 쪽은 모두 스캔본 안이다. 표지 OCR 도 옛·새가 같다 — 이미지가 표지 전체를 덮고 글자가 24자인 KCI_FI002252358(316쪽)도 둘 다 ODL 채택.
- 같은 모양이 다른 학술지에도 흩어져 있다 — 2004년 이전 200건 중 10건, 2005년 이후 200건 중 3건이 옛 규칙으로는 OCR 0쪽인 스캔본이었다.
- 경계 사례 KCI_FI003011274 의 1·2·8·9쪽(원래 60~61자, 뺀 42~43자)과 KCI_FI001141801 의 4쪽은 OCR 로 남는다.
- 이 하네스는 ODL 본문을 fitz 로 근사해 `<br>` 격자 쪽을 못 본다. 실제 ODL 로 돌린 계획 근거 ②(186건)는 OCR 쪽 비율이 2015년 이후 0.8% → 3.8%, 2004년 이전 47.7% → 59.5% 였다. 실제는 두 값 사이로 보고, spec 의 '총 처리 시간 +2~4%' 추정보다 클 수 있어 카나리에서 다시 잰다.

**3-3. opendataloader-pdf 2.5.0 대 2.5.9 — `research/round07-odl-259-recheck/README.md`.** 같은 45건을 두 버전으로 돌려 round07 의 판정이 같은지 봤다.

## 4. 면접식 Q&A

**Q1. 스캔본을 왜 쪽 단위 이미지 규칙이 아니라 문서 단위로 판정하나?**
A. 쪽 하나만 보면 '스탬프만 남은 스캔 본문 쪽'과 '스탬프만 남은 이미지 표지'가 같은 모양이다. 둘 다 쪽을 덮는 이미지에, 텍스트 층은 매 쪽 되풀이되는 스탬프 한 줄이다. 쪽 면적 이미지 규칙이나 '되풀이 줄을 빼면 0자인 쪽은 OCR' 같은 쪽 단위 규칙은 디지털 논문의 이미지 표지·간지를 다시 VLM 으로 보낸다. 그건 d85df93 이 고친 것(50자 미만 트리거가 예전 VLM 호출의 90% 이상)을 되돌린다. 문서 단위면 둘이 갈린다 — 스캔본은 거의 모든 쪽이 짧고, 디지털 논문은 표지 한두 쪽만 짧다. 그래서 3쪽 이상 문서에서 짧은 쪽이 과반일 때만 그 문서의 짧은 쪽을 OCR 한다. 회귀 하네스에서 실패 블록 318건은 모두 스캔본으로 잡혔고(OCR 0 → 6,837쪽), 비스캔 문서는 OCR 에서 빠진 쪽도 새로 OCR 된 쪽도 0이었다. 3쪽 미만 스캔본은 이 규칙 밖인데, 섹션 0개 강제 재추출이 받친다. (§2.1·§2.2·§2.5)

**Q2. 되풀이 줄을 뺀 길이를 왜 문서 단위 판정에만 쓰고, 쪽별 'ODL 이 놓친 본문' 판정에는 원래 길이를 쓰나?**
A. 되풀이 줄을 빼는 까닭은 같은 것끼리 견주기다. ODL 은 json header/footer 로 머리말·꼬리말을 지우므로, fitz 쪽도 지워야 '짧음'을 같은 잣대로 센다. 그런데 Task 3 첫 구현(`0487057`)은 쪽별 판정까지 뺀 길이로 했다. 그러자 본문이 이미지뿐이고 텍스트 층에 머리말·꼬리말만 남은 쪽(KCI_FI003011274 1·2·8·9쪽 — 원래 60~61자, 빼면 42~43자)이 '원래 짧은 쪽'이 되어 빈 ODL 본문이 채택됐다. 리뷰가 스마트미디어저널 로컬 278건 중 83건·291쪽에서 본문을 잃는 것을 찾았다. `5b3be2e` 가 판정 순서를 강제 → fitz 0자 → 스캔본 → 원래 길이 50자 이상 → 채택으로 바꿔, 비스캔·비강제 문서는 모든 칸이 옛 규칙과 같게 했다. 원칙은 '새 규칙은 OCR 을 더할 뿐 빼지 않는다'다. 결정표 전수 열거 테스트(2,000칸 넘게)와 길이 0~130 전수 테스트가 이것을 못 박는다. (§2.1·§2.6)

**Q3. 쪽 병렬에서 렌더링은 왜 잠금 안에서 한 쪽씩, 요청만 동시에 보내나? 동시 수는 왜 2인가?**
A. 쪽당 14초가 거의 VLM 요청(13.7초)을 기다리는 시간이다. 그 사이 다른 쪽 요청을 보내면 된다. 렌더링(`get_pixmap`)은 PyMuPDF 가 다중 스레드를 지원하지 않아 `to_thread` 로 빼지 않는다. 이벤트 루프 스레드에서 동기로 하고, `asyncio.Lock` 으로 동시에 도는 코루틴이 한 번에 한 쪽만 렌더하게 한다. 렌더링은 짧고 요청은 길어 이것으로 충분하다. 2는 자리 계산이다 — 추출 워커 4칸 × 2 = 8 = VLM `max-num-seqs`. VLM 은 평균 1.9/8석만 쓰고 있었다. 기대는 스캔본 시간당 약 50건 → 80~100건인데, GPU 를 함께 쓰므로 2배까지는 안 갈 수 있다(추정). 판정은 쪽 순서대로 그대로 한다 — VLM 60쪽 상한을 모으는 순서로 세기 때문이다. 결과는 끝나는 순서가 뒤섞이므로 `{쪽 번호: 결과}` 로 모아 쪽 순서로 조립한다. 설정을 0 으로 잘못 넣어도 `max(1, …)` 라 데드라인까지 막히지 않는다. (§2.2)

**Q4. 섹션 0개를 왜 `no_text` 와 `vlm_error` 로 나누나? 첫 추출에 OCR 오류·데드라인이 있으면 왜 강제 재추출을 건너뛰나?**
A. 같은 입력에 같은 결과가 나오는 실패를 재시도하면 시도 한도만 태운다 — 10-01 의 실패는 같은 일을 세 번 되풀이해 1~2분 만에 끝났다. 그래서 결정적이면 `no_text`(재시도 안 함), 다시 하면 달라질 수 있으면 `vlm_error`(추출부터 백오프 재시도)다. 강제 OCR 이 판정을 바꾸는 쪽은 '원래 짧은 쪽'으로 ODL 을 채택한 쪽(`short_kept`)뿐이다. 0이면 다시 추출해도 같으므로 바로 `no_text` 다. 첫 추출에 VLM 요청 실패나 데드라인이 있었으면 지금 강제 OCR 을 해도 같은 장애·시간 부족을 되풀이한다. 게다가 첫 추출이 2,700초를 다 쓴 뒤 또 2,700초를 쓰면 stale 판정 3,600초를 넘어 중복 체인이 열린다. 그래서 바로 `vlm_error` 이고, 강제 재추출에도 남은 시간만 준다(하한 60초). 'VLM 요청 실패'의 범위도 좁혔다. 퇴화 출력·렌더링 실패·400·413·422 거절은 다시 해도 대개 같아 세지 않는다. 401·403·404 는 모델 이름·경로·키가 틀린 서버 전체 장애라 센다 — 거절로 세면 모든 스캔본이 조용히 `no_text` 가 된다(`88aea31`). (§2.2·§2.5)

**Q5. ODL 변환 상한을 왜 max(10, 쪽수 × 1.5)초로 두나?**
A. 고정값이면 긴 문서에는 짧고, 짧은 손상 문서에는 길다. 그래서 쪽수에 비례시키고 하한을 둔다. 하한 10초는 JVM 기동 몫이다. 쪽당 1.5초는 동시 변환 실측에서 나왔다. 첫 구현은 5초·쪽당 0.5초였다. 그런데 리뷰가 24스레드 PC 에서 재 보니, 표가 많은 37쪽 문서(KCI_FI001930485, 상한 18.5초)가 혼자 12초, 4건 동시 28초, 8건 동시 47초였다. `celery-cpu` 4칸이 함께 변환하면 상한을 넘어 재저장본 재시도 뒤 fitz 텍스트로 떨어지고, 표 구조와 머리말 제거를 잃는다. 쪽당 1.5초(55.5초)면 4건 동시가 상한의 0.51, 8건 동시가 0.84 다(사용자 결정, `9cc502d`). 상한이 길어진 만큼 추출 데드라인에 묶었다. 시도마다 상한을 남은 시간으로 줄이고, 2초도 안 남으면 띄우지 않는다. 병리 문서 KCI_FI001238691(26쪽)은 옛 코드에서 877초가 지나도 안 끝났지만(java 8.9GB), 이제 시간 초과 두 번 뒤 fitz 텍스트로 간다(2.5.0 에서 39초 × 2 — 2.5.9 는 힙 상한에 먼저 걸려 12.8초). (§2.2)

**Q6. ODL 자식은 왜 SIGALRM 으로 스스로 끄고, compose 의 `init: true` 는 왜 필요한가?**
A. 보통은 부모가 끈다. `wait_for` 가 시간을 넘기면 `os.killpg` 로 자식 파이썬과 java 손자를 함께 끈다. 자식은 `start_new_session=True` 로 띄워 그룹 id 가 자기 pid 라 워커는 다치지 않는다. 그런데 부모(Celery 풀 자식)가 먼저 죽으면(`revoke(terminate=True)` 등) 시간을 넘겨도 끌 사람이 없어 java 가 끝없이 돈다. 그래서 자식이 `signal.alarm(int(상한) + 5)` 를 걸고, 울리면 `os.killpg(0, SIGKILL)` 로 자기 그룹을 끈다. 알람은 상한보다 5초 늦게 울리므로, 부모가 살아 있으면 부모의 `killpg` 가 먼저 끈다. 남는 문제는 거두기다. 부모를 잃은 java 는 PID 1 로 넘어가는데, 컨테이너의 PID 1(uvicorn·celery master)은 남의 자식을 거두지 않아 시간 초과마다 좀비가 남는다. `init: true` 로 tini 를 PID 1 에 두면 거둔다. SIGTERM 은 그대로 넘기므로 celery warm shutdown 은 같다(`97ca88c`). 운영 이미지에서 자기 종료는 기대 13초, 14.6초에 모두 사라졌다. Windows 는 `alarm` 이 없어 건너뛴다(개발 PC 한정). (§2.2, §3-3)

**Q7. markdown 이스케이프를 왜 `html.unescape` 가 아니라 `&amp;`·`&lt;`·`&gt;` 셋만, 그것도 쪽을 나눈 뒤에 되돌리나?**
A. 되돌리기는 ODL 이 한 변환의 정확한 역이어야 한다. 2.5.1+(#637)의 markdown 은 본문의 `&`·`<`·`>` 셋만 바꾼다. 2.5.9 jar 의 `MarkdownGenerator` 에 그 셋의 상수만 있고, 원본 markdown 을 세니 `&lt;` 433·`&gt;` 248·`&amp;` 82 뿐이었다(2.5.0 은 0). ODL 이 `&` 를 모두 바꾸므로 셋을 한 번의 치환으로 되돌리면 정확한 역이다 — 원문의 글자 `&lt;` 는 `&amp;lt;` 로 나와 `&lt;` 에서 멈춘다. `html.unescape` 는 모든 HTML 엔티티를 푼다. 출력에 ODL 이 이스케이프로 만들지 않은 엔티티 모양(`&quot;` 등)이 있으면 그것까지 바꿔, 검증 기준인 2.5.0 의 글자와 달라진다. 셋만 되돌리자 2.5.0 과 본문이 같은 문서가 26 → 35건이 됐다. 쪽을 나눈 뒤에 하는 까닭은 구분자다. 본문에 구분자 모양 글자가 있으면 ODL 은 그것도 `&lt;&lt;&lt;ODL_PAGE_BREAK_9&gt;&gt;&gt;` 로 이스케이프해 낸다. 먼저 되돌리면 그 글자가 진짜 구분자가 되어 쪽이 갈라진다. 되돌린 글자는 json(이스케이프하지 않는다)의 머리말 문자열과도 같아 머리말 제거가 맞는다. 되돌리기는 조건 없이 돌아, 이스케이프하지 않는 판으로 바뀌면 원문의 `&amp;` 를 잘못 푼다. 그래서 requirements 의 고정값을 테스트가 본다. (§2.2·§2.4·§2.7)

**Q8. java 힙 상한을 왜 `JAVA_TOOL_OPTIONS` 로, 그것도 ODL 자식의 환경에만 거나?**
A. 상한이 없으면 JVM 은 컨테이너가 보는 메모리의 1/4 까지 쓴다. 병리 문서 하나가 개발 PC(42GB)에서 10.5GB 까지 갔고, 운영 서버(251GB)면 하나당 약 63GB 다. `celery-cpu` 4칸이 겹치면 서버를 다 쓸 수 있다. java 명령은 패키지의 `run_jar` 가 직접 만들고(`java -Djava.awt.headless=true … -jar <jar> 인자`), JVM 인자를 넣을 자리가 없다. 명령을 베끼면 패키지 버전이 바뀔 때 깨진다. JVM 이 기동 때 읽는 `JAVA_TOOL_OPTIONS` 에 `-Xmx` 를 붙이면 명령을 건드리지 않는다. 이 변수는 `_odl_child_env` 가 ODL 자식에게만 준다 — 이미 있는 값 뒤에 붙이고, 워커 자신의 환경은 그대로다. 그러면 상한이 ODL 변환에만 걸리고, 테스트가 워커의 `os.environ` 이 그대로인지 본다. 값은 compose 에 `JAVA_TOOL_OPTIONS` 를 직접 쓰지 않고 앱 설정 `ODL_JAVA_MAX_HEAP` 으로 받는다. 그래야 기동 때 형식(`^([1-9][0-9]*[mMgG])?$`)과 하한 1g 를 검사한다 — `2gb` 면 java 가 뜨지 않고 `3m` 이면 변환이 모두 실패해, 어느 쪽이든 모든 문서가 조용히 fitz 텍스트가 된다. 3g 는 실측으로 골랐다. 무거운 61건은 2·3g 에서 결과가 상한 없을 때와 같았고, 일반 688건은 2g 에서 3건이 메모리 부족이었으며 3g 로 살아나는 것은 그중 1건이다. java RSS 는 상한보다 0.2~0.3GB 커서 4칸 최악이 약 13GB 다(운영 가용 131GB). (§2.2, §3-4)
