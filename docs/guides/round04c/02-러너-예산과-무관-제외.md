## 이 챕터의 자리

하위질문 하나를 도는 루프(`runner.explore_subquestion`)에 **몫(예산)**·**무관 제외**·**늘리기만 하는 근거 번호**를 넣고, 그 결과를 보고서(`synthesizer.assemble_report`)와 한계 문장(`build_limitations`)이 읽게 한다. 상태 객체(`state.py`)는 새 필드를 스냅샷 왕복과 옛 스냅샷 복원까지 책임진다. 모든 파일이 round04b 끝(`d845b8b`) 대비 diff 다.

회차 하나에서 근거가 지나는 길:

```text
explore_fn(query) → hits, meta
  └ build_evidence(hits) 의 후보마다
      ├ 이 하위질문이 뺀 논문(subq.excluded_cnts)        → 건너뜀
      ├ 이미 풀에 있는 논문                                → 재사용 링크(몫·상한을 쓰지 않는다)
      ├ 이 하위질문 몫이 찼다(own >= subq_budget)          → budget_capped 에 셈
      ├ 전체 상한이 찼다(len(evidence) >= max_evidence)    → capped 에 셈
      └ 새 근거: id = evidence_id(state.evidence_seq), seq += 1, made 에 넣음
  └ emit("counters", research_stats)                       ← 이번 회차 제외 전의 수
  └ critique_fn(subq, 근거[evidence_ids 순서]) → Verdict(off_topic=[목록 번호])
  └ exclude_off_topic=1: _exclude_off_topic  → evidence_ids·청크·점수에서 빼고, 다른 하위질문이
                                                안 쓰면 풀에서도 지움, excluded_cnts·서지 요약 남김
    exclude_off_topic=0: _newly_flagged      → 빼지 않고 처음 가리킨 논문의 서지만
  └ own 다시 셈 → 막힌 수는 그 상한이 아직 차 있을 때만 → _recheck_query(own=…)
  └ subq.rounds.append({…, excluded, excluded_papers, flagged, flagged_papers})
  └ emit("critique", {… 같은 값 …})                        ← 워커가 이때 단계 result 를 저장한다
```

**DB 구조는 바꾸지 않았다**(spec Q7). 새 값은 전부 JSONB 안에서만 는다 — `research_jobs.state_snapshot`(상태), `research_steps.result`(회차 기록·카운터), `research_jobs.report`(trail·stats). 워커(`research_tasks.py`)와 API 코드도 바꾸지 않았다. 워커는 `subq.rounds` 를 단계 result 에 복사하고 `critique` 이벤트를 그대로 중계하며 카운터는 `research_stats` 로 만든다. API 는 잡 파라미터를 `merge_params` 로 검증·합쳐 저장한다. 그래서 새 필드가 거기까지 저절로 닿는다 — §2.15·§2.16 의 테스트가 그 경로를 고정한다.

## 2. 구현 (클론코딩)

### 2.8 `state.py` — 기본값 90·켜고 끄기·새 필드·번호·제외 수

**파라미터 둘.**

- `max_evidence` 60 → **90** (`92b08a7`). 하위질문 6개면 몫이 15편이다. 60 이면 10편씩이라 첫 검색(보통 8~10편)만으로 몫이 차 자기점검의 재검색이 헛돈다(spec Q2). `_PARAM_BOUNDS` 상한 200 은 그대로다.
- `exclude_off_topic` — `(int, 0, 1)`, 기본 1(`43e66cc`). 운영에서 결과가 나쁘면 재배포 없이 잡 파라미터 0 으로 끈다. 검증은 기존 `_validate_param` 이 한다 — `True`(int 의 서브클래스)·`"0"`·`0.0`·`2`·`-1` 은 거부된다(§2.12).

**`SubQuestion` 새 필드 둘과 주석 하나.**

- `budget_capped: int = 0` — 몫 때문에 싣지 못한 후보 수. 기존 `capped`(전체 상한)와 따로 센다. **풀리는 방법이 달라서다** — 몫은 하위질문을 줄이면 커지고, 전체 상한은 `max_evidence` 를 올려야 풀린다. 한 수로 합치면 한계 문장이 잘못된 처방을 낸다.
- `excluded_cnts: list[str]` — 이 하위질문이 무관하다고 뺀 논문. 같은 하위질문의 다음 회차 검색에 다시 걸려도 넣지 않는다 — 넣으면 같은 논문을 또 판정받고 또 빼며 회차를 태운다. 다른 하위질문은 막지 않는다.
- `rounds` 주석 — 회차 dict 에 `excluded`·`excluded_papers`·`flagged`·`flagged_papers` 가 더해졌다. 보강 전 잡의 회차에는 없다.

**`ResearchState.evidence_seq`** (`f8cc0c1`). 다음 근거 번호다. 원래 `evidence_id(len(state.evidence))` 로 매겼는데, 무관 근거를 풀에서 지우면 개수가 줄어 **새 근거가 남아 있는 번호를 다시 받는다.** E1·E2·E3 중 E2 를 지우면 개수 2 → 다음 근거가 `E3` 을 받아 남아 있던 E3 을 덮어쓴다. 그러면 보고서의 인용칩 `[E3]` 이 다른 논문을 가리킨다. 늘리기만 하는 번호면 겹칠 수 없다.

**스냅샷.** `snapshot_state` 는 `SubQuestion` 을 `asdict` 로 담으므로(round04a) 새 필드 둘은 저절로 실린다. `restore_state` 도 없는 키를 dataclass 기본값으로 채우므로(`_known_fields`) 옛 스냅샷의 `budget_capped`·`excluded_cnts` 는 0·빈 목록이 된다. `evidence_seq` 만 손이 간다 — 옛 스냅샷에는 키가 없고, **근거 수로 되살리면 위와 같은 덮어쓰기가 재개한 잡에서 난다.** 그래서 가장 큰 번호(E<n> 의 n)로 되살린다(`_restored_evidence_seq`). `evidence_id(n)` 이 `E{n+1}` 이므로 E9 가 가장 크면 다음 근거는 E10 이다.

**`research_stats.excluded`** (`de7d0a6`). 모든 하위질문 회차 기록의 `excluded` 합이다. 진행 카운터·단계 result·보고서 stats 가 이 한 함수를 본다(round04b — 진행 중 본 숫자와 보고서 숫자가 어긋나지 않게). 재검색 수처럼 회차 기록에서 얻으므로 재개한 잡에서도 같은 값이 나온다. **하위질문별 판단의 수**라는 점이 중요하다 — 같은 논문을 두 하위질문이 빼면 두 번 세고, 한 하위질문이 뺀 논문을 다른 하위질문이 채택하면 `evidence_adopted` 에도 든다. 그래서 검토·채택 수와 더해 맞지 않고, 화면 서론은 "편"이 아니라 "건"으로 적는다(03 챕터 §2.19, 00-개요 Q15).

`evidence_adopted = len(state.evidence)` 는 이제 **줄 수 있다** — 무관 근거를 풀에서 지우기 때문이다. round04b 의 카운터 합치기는 "카운터는 줄지 않는다"를 전제로 필드별 큰 값을 남겼는데, 그 전제가 깨져 화면 쪽을 고쳤다(03 챕터 §2.18 `reconcileCounters`).

운영 보고서에서 먼저 탐색한 HPC 하위질문이 60편 중 32편을 가져갔고 질문의 핵심인 "컴퓨팅 자원 관리"는 2편(후보 3편은 상한에 막힘)이었다(spec §1). round04a 가 이월한 "상한이 선착순이라 뒤 하위질문이 굶는다"는 문제다(round04a 교본 Q23).

- **새 파라미터를 만들지 않는다.** 기존 두 값(`max_evidence`·`min_evidence_per_subq`)과 하위질문 수로 정해진다. 계획 승인 화면에서 하위질문을 지우면 남은 하위질문의 몫이 저절로 커진다.
- **1편 아래로 내리지 않는다** (`e10f873`). 전체 상한이 하위질문 수보다 작고 최솟값이 0 이면(둘 다 허용 범위) 몫이 0 이 되어, 어느 하위질문도 근거를 만들지 못한 채 절 0개짜리 보고서가 `completed` 로 끝났다.
- 최솟값이 몫을 끌어올리면 몫의 합이 전체 상한을 넘을 수 있다. 그때는 전체 상한이 먼저 막는다 — 그래서 두 상한을 따로 센다(②).

**② 후보 루프 — 몫은 "지금 남아 있는, 내가 만든 근거"로 센다.**

- `made` 는 이 하위질문이 새로 만든 근거 id 집합이고, 몫 사용량 `own` 은 `made ∩ 지금의 subq.evidence_ids` 다. **재사용 링크는 몫을 쓰지 않는다** — 다른 하위질문이 이미 만든 근거에 잇는 것은 전체 풀을 늘리지 않는다. **하위질문에서 빠진 근거는 자리를 돌려준다** — 무관 제외로 빼면 `own` 이 줄어 재검색이 새 근거를 만들 수 있다. 몫을 줄지 않는 누적 카운터로 세면 `test_freed_budget_lets_the_subquestion_search_again` 이 실패해서 드러난다.
- **몫을 전체 상한보다 먼저 본다.** 몫을 다 쓴 하위질문은 풀이 남아 있어도 못 만든다. 그걸 전체 상한 탓(`capped`)으로 적으면 한계 문장이 `max_evidence` 를 올리라는 잘못된 신호가 된다.
- 막힌 후보도 `break` 가 아니라 `continue` 다(round04a) — 뒤에 재사용 후보가 섞여 있다.
- 새 근거 id 는 `evidence_id(state.evidence_seq)` 로 받고 `seq` 를 1 늘린다.
- 앞 회차에 몫·상한에 막혔던 후보가 무관 제외로 빈 자리에 실리면 막힌 집합에서 뺀다(`discard`) — 남기면 한계 문장이 실린 논문까지 "싣지 못했다"고 쓴다.

**③ 자기점검 뒤 — 빼거나(켠 잡) 세기만(끈 잡).**

`_exclude_off_topic(state, subq, numbers)` (`44e28a2`, 서지는 `b6d4496`):

- 번호(1부터)를 `subq.evidence_ids[n - 1]` 로 되돌린다. critic 에게 넘긴 목록이 `subq.evidence_ids` 순서 그대로이기 때문이다(01 챕터 §2.5 ①). 빼기 **전에** 전부 바꾼다 — 빼면서 바꾸면 뒤 번호가 밀린다.
- 이 하위질문의 `evidence_ids`·`evidence_chunks`·`chunk_scores` 에서 지운다.
- **다른 하위질문이 링크하지 않은 근거만 풀(`state.evidence`)에서도 지운다.** 남기면 어느 절에도 실리지 않을 논문이 전체 상한만 차지한다. 다른 하위질문이 쓰는 근거는 둔다 — 그쪽에서는 관련 있을 수 있다.
- `excluded_cnts` 에 cnts_id 를 남기고, 뺀 논문의 **서지 요약**(`_paper_brief` — cnts_id·제목·저자·발행일)을 돌려준다. 풀에서 지운 뒤에는 이것 말고 무엇을 뺐는지 알 길이 없다. 이 요약이 회차 기록·`critique` 이벤트·보고서 trail 을 거쳐 타임라인·보고서·문서의 "제외한 논문" 목록이 된다(spec §11-1).
- **spec 과 다르게 한 점** — spec §4 는 순위 보조값 `relevance`·`leaders` 도 지우라고 했다. 그런데 `_rank_order` 는 `evidence_ids` 에 남은 id 만 보고, 번호를 다시 쓰지 않으므로(`evidence_seq`) 남은 값이 새 논문에 붙을 일도 없다. 지워도 결과가 같은 코드라 넣지 않았다(docstring 에 이유).

`_newly_flagged(state, subq, numbers)` (`43e66cc` → `be606eb`) — 끈 잡은 빼지 않고, 그 하위질문에서 **처음 가리킨** 논문의 서지만 남긴다. 빼지 않은 논문은 다음 회차 목록에 남아 또 가리켜진다. 회차마다 세면 켠 잡(한 번 뺀 논문은 다시 들지 않는다)보다 부풀고, 회차들이 서로 다른 논문을 의심한 것처럼 읽힌다(§11 최종 리뷰). 근거·몫·막힌 수는 건드리지 않는다.

**④ 막힌 수는 회차 끝에, 그 상한이 아직 차 있을 때만** (`e10f873`). 회차를 열 때 세던 것을 자기점검 뒤로 옮겼다. 무관 제외로 자리가 났는데 다음 검색이 막혔던 후보를 다시 찾지 못하면, 싣지 못한 것은 검색어가 바뀐 탓이지 상한 탓이 아니다. 그대로 세면 한계 문장이 "'엣지 컴퓨팅' 은 근거 1편으로 결론이 약하다(하위질문당 근거 상한(2편)에 닿아 …)" 처럼 스스로 모순된다. 집합은 지우지 않는다 — 다음 회차가 자리를 다시 채우면 그 후보들은 다시 상한에 막힌 것이다.

**⑤ `_recheck_query(..., own)` — 몫을 다 쓰면 재검색하지 않는다.** 전체 상한과 같은 이유다 — 새 근거가 생길 수 없으면 재검색은 검색·LLM 호출만 태운다. 무관 제외로 자리가 비면 `own` 이 줄어 다시 할 수 있다.

**⑥ 회차 기록·이벤트.** `subq.rounds` 와 `critique` 이벤트에 같은 네 값(`excluded`·`excluded_papers`·`flagged`·`flagged_papers`)을 싣는다. 이벤트에도 싣는 이유는 화면 쪽 사정이다 — 워커의 `_save_progress` 는 `critique` 이벤트를 받을 때 단계 result 를 저장하고 step 이벤트를 보내는데, **저장에 실패하면 step 이벤트를 보내지 않는다.** 이벤트에 값이 없으면 그때 새로고침 전까지 목록을 펼칠 수 없다(safeguards plan "계획 조립 때 정한 것"). `adopted` 는 뺀 뒤의 수다 — 화면의 채택 수와 한계 문장이 같은 값을 본다.

### 2.11 `synthesizer.py` — 한계 문장·보고서 evidence·trail

**① 한계 문장 — 두 상한을 나눠 적고, 조사를 받침에 맞춘다** (`25b9c0d`).

- `_capped_clause(state, sq, noun)` 가 "하위질문당 근거 상한(15편)에 닿아 후보 N편을" / "전체 근거 상한(90편)에 닿아 후보 N편을" 을 쉼표로 잇는다. 둘 다면 둘 다 적는다. 몫은 `subq_budget` 을 그대로 부른다 — 몫 계산을 한 곳에 두려고 `synthesizer` 가 `runner` 를 import 한다. `runner` 는 `synthesizer` 를 import 하지 않아 순환이 없다.
- `_topic(text)` 가 `'{text}' {josa(text, '은는')}` 를 만든다. `'…' 에 대해서는` 은 받침과 무관해 그대로 둔다.
- 분기 순서 — 오류(근거 있음) → 오류 → **0편이고 무관 제외가 있었음** → 0편이고 상한에 막힘 → 0편 → 부족. 무관 제외 분기는 최종 리뷰(`e10f873`)에서 생겼다. 자기점검이 실제 근거를 읽고 모두 뺐는데, 상한 분기로 보내면 그 원인과 note 가 가려지고 "근거를 찾지 못했다"(코퍼스 빈틈)로 쓰면 찾아서 읽은 사실이 사라진다. 상한에도 막혔으면 괄호로 덧붙인다.

**② 보고서 `evidence` 에는 절에 실린 근거만** (`96577d1`). 절은 하위질문마다 앞 5편(`PAPERS_PER_SECTION`)만 쓴다. 나머지는 어느 칩도 가리키지 않는데 보고서 JSON 에는 다 실렸다 — 상한을 90 으로 올리면 그만큼 분다. `_cited(state, section)` 이 다듬은 절의 인용(대표 논문·도입의 `[E#]`·향후 과제)을 모으고, `assemble_report` 가 절마다 모은 집합으로 `_serialize_evidence(state, cited)` 를 거른다. 채택 수는 `stats.evidence_adopted` 가 그대로 센다.

- `_cited` 는 원래 `section_evidence`(round04b 절 미리보기) 안에 있던 코드를 떼어 낸 것이다. 도입의 마커는 `bind_markers(...).used` 로 읽는다 — 정규식을 여기서 다시 쓰면 마커 문법이 두 곳으로 갈라진다.
