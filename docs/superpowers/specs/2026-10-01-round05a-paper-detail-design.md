## 3. 주소 규칙 (`utils/detailSource.ts` 신규 — 순수 함수, Vitest)

**상세 주소의 쿼리**

| 키 | 출처 | 뜻 |
|---|---|---|
| `from` | 공통 | `search` \| `research`. 없으면 출처 없음 — 다만 `h`·`q` 가 있으면 검색 출처로 읽는다(출처를 싣기 전의 옛 상세 주소 `?q=&h=` 가 열린 탭·방문 기록·북마크에 남아 있다) |
| `h`, `q` | search | 기록 id, 결과의 검색어(입력창 글자가 아님). round04b 규칙 그대로 |
| `job` | research | 딥리서치 잡 id |
| `e` | research | 인용 근거 번호(E#) — 배너용. 연관 논문으로 넘어가면 뗀다 |
| `at`, `y` | 공통 | 돌아갈 때 맞출 요소 앵커와 그 요소의 화면 높이(px, 정수). 출처 주소로 그대로 넘긴다 |
| `score` | search | 관련도(기존). 연관 논문으로 넘어가면 뗀다 |
| `chat` | 공통 | `1` 이면 DeepRead 열기(기존) |

**함수**
- `readDetailSource(query) → DetailSource` — `{ kind: 'search', h, q } | { kind: 'research', job, e } | { kind: 'none' }` + `at`·`y`. 모양이 틀린 값은 버린다(`job`·`h` 는 UUID 모양만, `y` 는 0 이상 정수, `at` 은 아래 앵커 문법만).
- `detailUrl(cntsId, source, extra?)` — 상세 주소. 연관 논문은 `relatedDetailUrl(cntsId, source)`(`e`·`score` 를 뗀다).
- `backTarget(source) → { label, to }` — search: "검색 결과로" + `/papers?h=&q=&at=&y=`, research: "딥리서치 보고서로" + `/research/<job>?at=&y=`, none: "검색으로" + `/`.
- `shouldGoBack(historyBack: string | null, target)` — vue-router 의 `history.state.back` 경로가 target 의 경로·`h`/`job` 과 같으면 true(`at`·`y` 는 비교하지 않는다).
- 앵커 문법: 보고서 인용칩 `c-<절 순번>-<E#>`(같은 절에 같은 칩이 여러 번이면 `-<n>` 순번), 보고서·타임라인 제외 목록 `x-<cnts_id>`, 검색 결과 카드 `p-<cnts_id>`. `parseAnchor`/`anchorSelector` 로 DOM 의 `data-anchor` 속성과 맞춘다.

## 4. 떠날 때 · 돌아올 때

**떠날 때**
- 인용칩 팝오버의 [논문 상세](`CitationChip.vue`): 잡 id·절 순번은 `ReportView` 가 provide 하고 칩이 inject 한다. 칩 요소에 `data-anchor`, 링크는 `detailUrl(cnts, {kind:'research', job, e}, {at, y})` — `y` 는 클릭 순간 칩의 `getBoundingClientRect().top` 반올림.
- 보고서·타임라인의 "제외한 논문" 링크(`ReportView.vue`·`ProgressPanel.vue`, 새 탭): 같은 방식(`at = x-<cnts>`, `e` 없음).
- 검색 결과 카드(`pages/papers/index.vue` `detailUrl`, `pages/index.vue` 논문 분기): `from=search` + `h`(있을 때) + 결과 검색어 `q` + `at = p-<cnts>` + `y`.

**돌아올 때** (`composables/useRestorePosition.ts` 신규)
- `/research/<job>` 과 `/papers` 가 `at`·`y` 를 받으면, 내용(보고서 또는 복원한 결과 목록)이 그려진 뒤 `anchorSelector(at)` 요소를 찾아 `window.scrollBy` 로 그 요소의 화면 높이를 `y` 로 맞춘다(즉시, `behavior: 'auto'`). 요소가 없으면(보고서 재생성·결과 변경) 아무것도 하지 않는다. 인용칩이면 `focus({ preventScroll: true })` — 칩의 초점 열림(round04b)으로 팝오버가 다시 열린다. 끝나면 `router.replace` 로 `at`·`y` 를 지운다.
- 내용이 그려지기를 기다리는 조건은 화면이 준다(보고서: `reportState==='ready'` 또는 초안이 그려진 뒤, 검색: 기록 복원 완료). 최대 대기 시간을 두고 넘기면 포기한다.
- (최종 검토에서 더함) **맞춘 뒤 붙잡기**: 사용자가 움직이기 전까지(최대 15초) 그 요소를 같은 화면 높이에 붙잡는다 — 요약이 끝나기 전에 떠난 검색 기록은 돌아올 때 AI 요약을 다시 받아 펼치고 인용 논문을 맨 위로 올리며, 작성 중 초안의 절은 올라오며 나타나 맞춘 요소가 밀린다.
- (최종 검토에서 더함) **자리를 그 기록에 남기기**: 주소에서 `at`·`y` 를 지울 때 같은 자리를 그 기록의 `history.state`(`skxSpot`)에 남기고, 주소에 자리가 없으면 그것을 읽는다. 상세 기록의 `history.state.back` 은 처음 주소(at·y 포함)를 그대로 들고 있어, 한 번 돌아온 뒤 앞으로 갔다 다시 [돌아가기]·뒤로 가기를 하면 `router.back()` 이 자리 없는 기록으로 와 맨 위에 섰다. 사용자가 움직이면 남긴 자리를 지운다(그 뒤로는 그 요소가 읽던 자리가 아니다). 마우스 앞/뒤 버튼·Alt+화살표·새로고침 키는 움직임으로 보지 않는다. 세로가 앞서지 않는 휠(가로 스와이프의 관성)도 움직임으로 보지 않는다.

## 6. 원문 뷰어 (`components/PdfViewer.vue` — S6-1·5·6)

- **Esc 로 닫기**, 닫으면 연 버튼으로 초점을 돌려준다. 열려 있는 동안 배경 스크롤 위치는 그대로.
- **머리**: 제목 · 현재 쪽/전체 쪽 · 쪽 넘기기 · (대목 목록을 받았을 때만) "인용 대목 1/3 ‹ ›" · 닫기. pdf.js 뷰어가 같은 출처(`/pdfjs/web/viewer.html`)라 `iframe.contentWindow.PDFViewerApplication` 의 `page`·`pagesCount` 를 읽고 쓴다(로드 이벤트를 기다린다).
- **열기 전 확인**(S6-6): 상세·배너에서 열 때 `GET /api/books/{id}/pdf` 로 먼저 확인해(딥리서치 인용 팝오버의 `pdfCheckProblem` 을 공용 유틸로) 없으면 그 자리에서 "원문 파일이 없습니다", 5xx 는 "원문을 불러오지 못했습니다"(round04b 문구).
- **쪽 번호**: 대목 → 쪽은 `utils/citations.ts` 의 `pdfPage` 한 규칙.
- pdf.js 기본 도구 줄 정리·대목 위치 강조는 검토만(범위 밖).
- **보안 설정**(최종 검토에서 더함): 고정본 pdf.js 4.0.379 는 CVE-2024-4367(글꼴로 임의 스크립트 실행, 4.2.67 에서 수정) 범위이고 뷰어가 앱과 같은 출처다. 뷰어가 부모 문서에 보내는 `webviewerloaded` 에서 `isEvalSupported=false` 로 끈다. 같은 자리에서 PDF 안의 외부 링크를 새 탭으로 연다(`externalLinkTarget=BLANK` — 끼운 뷰어의 기본은 `_top` 이라 SKOVIX 탭이 넘어갔다). 저장된 설정이 링크 대상을 덮어쓰므로 `disablePreferences=true` 도 준다.

| 사이드바 | `activeKindForPath`/`activeIdFor` 가 상세의 `from=research&job=` 을 딥리서치·그 잡으로, `from=search&h=` 를 논문·그 기록으로 |
| 공통 | `npx vitest run`, `npx nuxi typecheck`, `npm run build`, 백엔드 변경 없음 확인 |
| **화면(운영 API 미리보기 `frontend-prod-api`)** | ① 보고서 중간의 인용칩 → [논문 상세] → [딥리서치 보고서로] → 같은 칩이 같은 높이, 팝오버 열림 ② 같은 흐름을 브라우저 뒤로 가기로 ③ 상세 → 연관 논문 2편 → [딥리서치 보고서로] → 처음 칩 자리 ④ 새 탭으로 연 제외 논문 → 돌아가기 → 보고서의 그 항목 자리 ⑤ 검색 결과 중간 카드 → 상세 → [검색 결과로] → 재검색 없이 그 카드 자리 ⑥ 메인 논문 탭에서 같은 흐름 ⑦ 주소 직접 입력 → "검색으로" → 홈 ⑧ 사이드바 강조·탭 제목 ⑨ 상세 → 뒤로 → 앞으로 시 AI 요약·연관 이유 재생성 없음(네트워크) ⑩ 원문 뷰어 Esc·초점·쪽 표시·인용 대목 넘기기·PDF 없음 안내 ⑪ 배치 A/B 둘 다 |

## 10. 위험과 대응

| 위험 | 대응 |
|---|---|
| 앵커 요소를 못 찾음(보고서가 다른 시도로 바뀜·결과가 바뀜) | 아무것도 하지 않는다(맨 위). 오류를 띄우지 않는다 |
| 주소에 `y` 등 쿼리가 늘어 지저분함 | 복원 뒤 `at`·`y` 를 지운다. 상세 주소의 출처 쿼리는 새 탭·새로고침에 필요하다 |
| pdf.js 내부 API(`PDFViewerApplication`) 변경 | 같은 저장소의 고정 버전(`public/pdfjs`)이다. 못 읽으면 머리의 쪽 표시만 숨긴다 |
| 기획자 시안과의 병합 | 동작·데이터 위주로 바꾸고 클래스 구조는 유지한다 |
| 같은 제외 논문이 보고서 제외 목록과 탐색 타임라인(회차마다)에 함께 있음 — 앵커 `x-<cnts>` 가 여럿 | 알려진 한계. DOM 순서상 보고서 쪽 항목으로 맞추고, 펼칠 때 그 논문이 든 회차를 모두 펼친다. 배치 A 의 타임라인은 자체 스크롤이라 창 스크롤로는 맞출 수 없다. 담는 곳별 앵커(`t-…`)는 다음 라운드 |
| pdf.js 4.0.379 고정본의 알려진 취약점 | §6 보안 설정으로 막는다. iframe 없이 `/pdfjs/web/viewer.html?file=` 을 주소로 바로 열면 부모가 없어 걸리지 않으므로, 근본 해결은 `public/pdfjs` 를 4.2.67 이상으로 올리는 것(다음 라운드) |
