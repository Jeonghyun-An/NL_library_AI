# 참고문헌 목록 조각 거르기 — 운영 근거 회귀 확인 (2026-10-14)

딥리서치 보고서·이어가기의 근거 대목이 논문 끝 참고문헌 목록 조각인 문제(인용칩에 서지 목록이 뜨고 '겹치는 대목 문장을
찾지 못했습니다', 생성이 참고문헌 항목을 논문 내용처럼 씀, 참고문헌 속 제목만 맞은 무관 논문이 근거가 됨)를
`app/services/research/bibliography.py` 의 `looks_like_bibliography` 로 `explorer.is_source_passage` 에서 거른다.
이 폴더는 그 규칙을 운영 보고서 48개의 근거 청크에 돌려 본 1회성 확인이다. DB·Milvus 에 쓰지 않고, 운영에는 GET 만 보낸다.

| 파일 | 역할 |
|---|---|
| `count_bibliography_evidence.py` | GET `/api/research/{job_id}` 응답 폴더를 읽어 근거별·청크별로 참고문헌 판정을 센다. `--fetch <주소>` 면 `job_ids.txt` 의 잡을 먼저 받는다 |
| `job_ids.txt` | docs·research 에 적힌 연구 id 가운데 보고서가 있는 48개 |
| `result.txt` | 이 브랜치 규칙으로 센 결과와 걸린 청크 161개 목록(앞 70자) |

조사 초안에서 두 군데를 더 좁혔다 — 본문으로 남기는 쪽으로 기운 것이다(놓친 참고문헌은 지금과 같고, 잘못 거른 본문은 근거를 잃는다).

1. 머리 없는 목록은 **서로 다른 서지 꼴이 둘 이상**일 때만 참고문헌으로 본다. 꼴 하나만 되풀이되는 본문 — 연구문제 번호 목록
   `- 1) 공공도서관…어떠한가?`(밴쿠버 `- 49) Camacho` 와 같은 꼴), 영문 본문의 번호 인용 ` [3] `(IEEE `- [30]` 과 같은 꼴),
   법률 번호 `법률 제8029호` — 를 초안은 걸렀다(`app/tests/test_research_bibliography.py` 의 합성 본문 4개 모두 초안에서는 걸린다).
   대가로 꼴 한 가지만 있는 한국어 목록 4개를 놓친다: `KCI_FI001414097__0026`·`KCI_FI002065605__0042`·`KCI_FI002065605__0043`·
   `KCI_FI002537295__0024`.
2. 서지의 `연도.` 꼴에서 날짜 `2006. 10. 4.` 를 뺐고, 머리 낱말에서 단수 `Reference`(`Reference service` = 참고봉사)를 뺐다.
   운영 표본에서는 바뀐 판정이 없다.

새로 걸린 청크는 없다(초안 158개 ⊃ 커밋 154개). 조사 보고의 사례 — d60a5dc1 E2·E4·E10·E11·E13·E16·E8 둘째 대목, 85d2bc0e E11(수협)·
E13(특화도서관), 이어가기 prior.g1·gap 의 참고문헌 대목 8건 — 은 모두 걸린다.

검토 반영(10-14) 뒤 다시 세어도 그때의 `result.txt`(154개)가 글자 하나 바뀌지 않았다. 고친 것은 본문 쪽으로만 더 기운다 — 서술 종결이
'다' 와 마침표 사이의 괄호 인용(`…하였다(김철수, 2012: 45-67).`)·마침표 뒤에 붙은 각주 번호(`.12)`)·닫는 따옴표를 넘어
세어 본문 청크 234개의 서술 수가 늘었고(걸린 154개는 0개), 청크 첫머리 머리는 뒤에 소문자 낱말(`Bibliography instruction`)이나
띄어 쓴 한글 낱말 둘(`참고문헌 분석에 관한`)이 이으면 머리로 보지 않으며(표본에서 바뀐 청크 0개), 머리 갈래도 영어 서술을 센다.

### 짧은 조각·초록 머리 갈래 (10-14 운영 확인 뒤)

랜딩 예시 질의('다문화가정 아동의 언어 발달…')의 보고서 5개·6개 절에서 `KCI_FI001488939__0033`(193자 순수 서지)이 E5 의 유일한
대목이었고 요약 6개 중 5개가 참고문헌 항목을 논문 내용처럼 썼다('파라다이스복지재단에서 발간한 자료와 … 석사학위논문을
참고하였다'). 630e0d65 E14 는 `KCI_FI001378107__0030`(참고문헌 꼬리 + 다음 쪽 영문 제목·`<Abstract>`)의 앞 400자가 서지라
요약이 비었다. 둘 다 머리가 없고 서지 꼴이 2개뿐이라 머리 갈래·목록 갈래 어디에도 안 걸렸다. 갈래 둘을 더했다.

1. 짧은 조각 — 300자 이하·서술 0·서로 다른 서지 꼴 둘 이상이 떨어진 두 자리(40자 안에 붙은 꼴은 한 자리 — 학술지 첫 쪽 머리
   `2016, Vol. 32, No. 4, pp. 183～204.` 를 지킨다). 새로 걸림: `KCI_FI001488939__0033`·`KCI_FI001378107__0029`·
   `KCI_FI001267084__0028`·`KCI_FI001486279__0064`, 630e0d65 근거의 `KCI_FI001917858__0050`.
2. 서지 꼬리 + 영문 초록 머리 — 제 줄에 혼자 있는 `Abstract` 앞이 서술 0·서지 꼴 두 종류 이상이고, 첫 제목 줄(`#`) 앞에 저자
   이니셜 뒤(또는 청크 맨 앞)의 `(YYYY).` 가 있을 때. 첫 쪽 인용 안내 `Citation: Hong, G. D. (2017). …` 는 논문 제목 뒤라 걸리지
   않는다(합성 테스트). 새로 걸림: `KCI_FI001378107__0030`·`KCI_FI001414097__0031`·`KCI_FI002538124__0051`.

869개(48개 보고서)에서 154 → 161, 630e0d65 근거·절 발췌를 더한 881개에서 154 → 162. 풀려난 청크는 없고 새로 걸린 8개는 모두
서지다(눈으로 확인). 300자 이하이고 서술이 0인 비표 청크 32개 가운데 본문은 2개(키워드 줄·표)뿐이고 둘 다 서지 꼴이 0개다.
`Abstract` 줄이 있는 청크 13개 중 첫 쪽 머리는 모두 남는다.

검토 반영(10-14 저녁) — 본문 쪽으로 두 군데를 더 좁혔다. 짧은 조각 갈래는 학술지 권호(`제45권 제2호`·`Vol. 45, No. 2`)를
세지 않는다: 문장이 잘린 본문 조각에서 쪽 머리글의 권호와 직접 인용의 `p. 23` 이 40자 넘게 떨어져 꼴 두 종류·두 자리가 됐다.
초록 머리 갈래는 첫 쪽 인용 안내 줄(`Citation:`·`How to cite this article:` 등)을 지우고 본다: 인용 안내가 논문 제목 줄보다
앞에 있거나 제목 줄이 없으면 그 청크의 초록까지 걸렸다. 두 꼴 모두 운영 표본에는 없어 합성 테스트로 고정했고, 881개 판정과
`result.txt` 는 글자 하나 바뀌지 않았다(권호를 빼서 짧은 조각 갈래 24개에서 빠지는 `KCI_FI000862072__0056` 은 머리
갈래가 잡는다).

## 남은 것

- 놓침: 서지 꼴 한 종류뿐인 목록(위 4개와 `KCI_FI001003146__0035`), 꼴이 한 자리에 몰린 짧은 조각(`KCI_FI001701466__0025`·
  `KCI_FI002535440__0039`·`KCI_FI002180204__0066`), 한국어 저자-연도 꼬리 + 영문 초록. 지금보다 나빠지지는 않는다.
- 짧은 조각 갈래는 출처 줄 두 개뿐인 300자 이하 조각(서술 0)도 거른다. 근거로서의 값은 거의 없다.
- 본문 한 문장 + 참고문헌인 청크(`KCI_FI000965838__0050`·`KCI_FI001267084__0022`)는 걸려 맺음 한 문장을 잃는다.
- 영어 논문 비중이 큰 질의는 표본이 적다. 배포 뒤 예시 질문 1~2개로 근거 수·소요 시간(critic insufficient → 재검색)을 본다.
