# round07 실제 PDF 라우팅 회귀 (Task 11, 1회성)

이 PC 의 KCI PDF(`D:/SKOVIX/KCI/pdf`)를 fitz 로만 읽어, ODL 본문이 짧은 쪽을 OCR(VLM)로 보낼지의 판정을
**옛 규칙**(round07 이전 운영 코드)과 **새 규칙**(이 브랜치 HEAD)으로 각각 내려 쪽 단위로 비교한다.
VLM·ODL·서버에는 요청하지 않는다. 코드를 고치는 도구가 아니라 재는 도구이며, 결과는 아래 통과 기준으로 판정한다.

실행: `python research/round07-ingest-regression/route_compare.py --per-group 200 --workers 8` (시드 20261001 — `--workers` 기본값은 min(6, CPU 수)라 이 실행은 8 을 줬다).
첫 실행 511초(디스크 캐시 없음), 다시 돌리면 59초이고 두 실행의 결과는 같다. 표본 752건(고유 PDF 747건 — 이름 오른 문서가 다른 묶음과 겹친다).
결과는 이 PC 의 PyMuPDF 1.28.0 으로 냈다(`summary.json` 의 `meta.pymupdf`). 운영 이미지는 1.24.10 을 고정한다(`app/requirements.txt`) — 라우팅 단위 테스트는 1.24.10 에서도 돌렸지만, 이 하네스의 수치는 1.28.0 의 fitz 텍스트로 낸 것이라 버전에 따라 텍스트가 달라지면 달라질 수 있다.

## 두 규칙 (ODL 본문이 50자 미만인 쪽)

| | 옛 규칙 | 새 규칙 |
|---|---|---|
| 출처 | `0df3001` 의 `extractor.py:416-434` (round07 이전 마지막 상태, `0487057` 의 부모와 같다) | HEAD 의 `page_routing.short_page_needs_ocr` + `is_scan_document` (5b3be2e 이후) |
| 판정 | `0 < fitz < 50` 이면 ODL 채택, 그 밖(fitz 0자·fitz 50자 이상)은 OCR | 강제 · fitz 0자 · **문서 단위 스캔본** · fitz 원래 길이 50자 이상(ODL 이 놓친 본문) 중 하나면 OCR, 그 밖에는 ODL 채택 |
| 본문 길이 | 옛 `_body_len` (`<br>` 를 글자로 센다) | `body_len` (`<br>` 도 뺀다) |

ODL 본문이 50자 이상인 쪽(CMap 2배 분기)은 두 규칙이 같다. 되풀이 줄(머리말·꼬리말·스탬프)을 뺀 길이는 **문서 단위 스캔본 판정**
(3쪽 이상 문서에서 짧은 쪽이 과반)에만 쓴다. 그래서 비스캔·비강제 문서에서는 두 규칙이 칸마다 같고, 문서 전체가 스캔본일 때만 그 문서의 짧은 쪽이 OCR 로 늘어난다.

## 근사와 놓치는 것

ODL 은 부르지 않고 ODL 본문 길이를 'fitz 텍스트에서 문서 전체에 되풀이되는 줄을 뺀 `body_len`' 으로 근사한다. 두 규칙 모두 VLM 쪽수 상한(60쪽)을 적용한다.

- **`<br>` 격자·`[그림]` 마커** — fitz 텍스트에는 없다. 그래서 새 규칙이 길이에서 `<br>` 를 빼서 판정이 바뀌는 쪽(표의 `<br> 길이만의 변화`)은 구조상 0 이고 실제 ODL 의 값이 아니다.
  계획서 근거 ②(실제 ODL, 비스캔 118건)에서 그런 쪽은 KCI_FI001343547 의 2·13쪽(`<br>` 를 빼니 ODL 본문이 줄어 CMap 2배 분기 → OCR) 두 쪽이었다.
  `<br>` 제외는 ODL 길이를 줄이기만 하므로 옛 규칙에서 OCR 이던 쪽은 새 규칙에서도 OCR 이다 — 실제 ODL 에서도 OCR 에서 빠지는 쪽은 만들 수 없고 늘기만 한다.
- **CMap 손상**(ODL 이 fitz 보다 글자를 잃는 쪽) — 근사에서는 ODL ≈ fitz 라 CMap 2배 분기는 머리말·꼬리말이 길 때만 걸린다(`cmap_pages`). 두 규칙에 똑같이 걸려서 비교에는 영향이 없다.
- **표 셀 충전율·ODL 누락 쪽** — 쓰지 않는다(두 규칙에 똑같이 걸리는 분기).

## 통과 기준 판정 (`summary.json` 의 `checks` 41개 모두 통과)

1. **스캔본이 아닌 문서는 OCR 에서 빠지는 쪽이 0** — 모든 묶음에서 새로 OCR 되는 쪽도 0 이다(VLM 상한 전·후 모두). 이 표본에서 규칙이 갈린 쪽은 모두 스캔본 문서 안의 쪽이다.
2. **스캔본(텍스트 층에 스탬프·머리말만 남은 문서)은 OCR 가 늘어난다** — `fail_block` 318건이 모두 스캔본으로 잡히고 옛 규칙으로는 OCR 0쪽이었다. 새 규칙은 6,844쪽을 OCR 로 보내고, 그중 7쪽은 61·66쪽 문서 둘의 VLM 60쪽 상한에 걸려 6,837쪽이 OCR 된다.
   같은 모양이 다른 학술지에도 흩어져 있다: 2004년 이전 200건 중 10건, 2005년 이후 200건 중 3건(KCI_FI001314298·KCI_FI001030932·KCI_FI001107507)이 옛 규칙으로는 OCR 0쪽이다.
   늘어난 쪽은 모두 텍스트 층이 1~49자(스탬프·머리말)인 쪽이다. 비용은 2005년 이후 문서당 +0.36쪽(5.3% → 6.8%), 2004년 이전 +1.63쪽(50.9% → 59.8%)이다.
3. **디지털 논문의 이미지 표지·간지는 ODL 채택 그대로** — 비스캔 문서의 표지(0쪽) OCR 은 옛·새가 같고(2004년 이전 4/4, 나머지 0/0), 이미지 쪽의 OCR 도 묶음마다 같다.
   KCI_FI002252358(316쪽)의 표지는 이미지가 쪽 전체를 덮고 글자가 24자인데 옛·새 모두 ODL 채택이다.
4. **알려진 경계 사례는 옛 규칙대로** — KCI_FI003011274 의 1·2·8·9쪽(본문이 이미지라 텍스트 층은 머리말·꼬리말 60~61자, 되풀이 줄을 빼면 42~43자)과 KCI_FI001141801 의 4쪽(fitz 51자, 쪽 번호 줄을 빼면 48자)은 OCR 로 남는다.
   KCI_FI001667569(5·11·12쪽)·KCI_FI001158431(29·30·34쪽)도 같다. 쪽 번호는 `pages.csv` 의 `page`(0부터)이고 계획서의 쪽 번호와 같은 기준이다.
