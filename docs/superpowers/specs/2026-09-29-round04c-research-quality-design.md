## 0. 사용자 요청 (paraphrase)

> 운영에서 돌린 딥리서치 보고서("컴퓨팅 자원에 대한 연구가 궁금해")를 같은 질문의 DBpia AI 답변과 비교했다. 화면은 우리가 낫지만 내용은 DBpia 가 낫다. 추천 순서대로 품질을 올리자 — 먼저 A(하위질문별 근거 예산)·B(관련 없는 논문 걸러내기)·C(계획을 질문의 핵심 개념 중심으로)·G(문체 통일), 그다음 D(핵심 요약·주제 종합)·E(이어서 물어보기)·F(화면 참고문헌)를 따로 한다.

이 spec 은 **A·B·C·G** 만 다룬다. D·E·F 는 다음 묶음(별도 spec 절 또는 라운드)이다.

## 2. 결정

| # | 결정 | 근거 |
|---|---|---|
| Q1 | **하위질문별 근거 예산 = `max_evidence // 하위질문 수`**(최소 `min_evidence_per_subq`). 새 근거를 **만드는** 것만 센다 — 다른 하위질문이 이미 만든 근거를 재사용하는 것은 전체 풀을 늘리지 않으므로 예산에서 빼지 않는다. 전체 상한은 그대로 둔다 | 한 하위질문이 풀을 독식하지 못한다. 계획에서 하위질문을 지우면 남은 하위질문의 몫이 저절로 커진다. 새 파라미터 없이 기존 두 값으로 정해진다 |
| Q2 | **`max_evidence` 기본값 60 → 90** | 6개 기준 15편씩. 첫 검색이 보통 8~10편을 채우므로 재검색이 보탤 자리가 남는다. 60 이면 10편씩이라 첫 검색만으로 차 자기점검의 재검색이 헛돈다 |
| Q3 | **보고서의 `evidence` 에는 절에 실린 근거만 담는다** | 상한을 올려도 보고서 JSON 이 불지 않는다. 채택 수는 `stats` 로 그대로 남는다(`evidence_adopted = len(state.evidence)`) |
| Q4 | **critic 이 무관한 근거의 번호를 돌려주고, 러너가 그 하위질문에서 뺀다** | 같은 단어·다른 뜻 논문(엣지)을 걸러낼 수 있는 곳은 발췌를 읽는 critic 뿐이다. 점수 하한은 데이터 없이 정하면 추측이다(§8) |

## 3. A — 하위질문별 근거 예산 (`app/services/research/runner.py`, `state.py`, `synthesizer.py`)

- 예산 계산: `subq_budget(state) = max(1, params["min_evidence_per_subq"], params["max_evidence"] // max(1, len(state.subquestions)))`. 순수 함수로 두고 테스트한다. 1편 아래로는 내리지 않는다 — 전체 상한이 하위질문 수보다 작고 최솟값이 0 이면(둘 다 허용 범위) 몫이 0 이 되어 절 0개짜리 보고서가 completed 로 끝난다.
- `explore_subquestion` 은 이 하위질문이 **새로 만든** 근거 수를 센다. 새 근거를 만들 때 (a) 전체 상한 또는 (b) 하위질문 예산에 닿으면 만들지 않고 후보를 센다. 재사용 링크는 두 상한과 무관하게 허용한다(지금 `continue` 규칙 유지).
- 막힌 후보 수를 원인별로 나눈다: 전체 상한 → 기존 `SubQuestion.capped`, 하위질문 예산 → 새 `SubQuestion.budget_capped: int = 0`. 스냅샷 왕복·옛 스냅샷 복원(없으면 0)을 테스트한다. 막힌 수는 회차가 끝날 때 그 상한이 아직 차 있을 때만 싣는다 — 무관 제외(§4)로 자리가 났는데 다음 검색이 그 후보를 다시 찾지 못하면 싣지 못한 것은 상한 탓이 아니다(그대로 세면 "근거 1편 … 상한(2편)에 닿아"처럼 한계 문장이 스스로 모순된다).
- 재검색(`_recheck_query`)은 전체 상한에 닿았거나 **이 하위질문 예산을 다 썼으면** 하지 않는다 — 새 근거가 생길 수 없다. 단 무관 제외(§4)로 자리가 비면 다시 할 수 있다(예산은 "지금 이 하위질문에 남아 있는, 이 하위질문이 만든 근거 수"로 센다).
- 한계 문장(`build_limitations`): 원인을 구분한다 — "하위질문당 근거 상한(15편)에 닿아 후보 N편을 더 싣지 못했다" / "전체 근거 상한(90편)에 닿아 …". 둘 다면 둘 다 적는다. 상한 때문에 0편인 경우의 문장도 같은 규칙.
- 기본값: `DEFAULT_PARAMS["max_evidence"] = 90`(`_PARAM_BOUNDS` 상한 200 그대로). 화면 `DEFAULT_MAX_SUBQUESTIONS` 등 프론트 상수는 바꾸지 않는다.
- 보고서 근거 정리(`assemble_report`): `evidence` 는 절(`sections[].papers[].evidence`·도입·향후 과제의 인용)에 나온 근거만 싣는다. `stats` 는 지금처럼 전체 상태에서 센다. `trail[].evidence_count` 는 그대로(하위질문이 채택한 수). round04b 의 절 미리보기 근거(`section_evidence`)는 원래 절 단위라 영향 없다. 프론트는 `report.evidence` 를 인용 조회에만 쓴다(없는 `stats` 의 옛 보고서 폴백은 옛 보고서에만 닿는다) — 구현 때 소비처를 grep 으로 재확인한다.

## 4. B — 무관한 근거 걸러내기 (`critic.py`, `research_critique.yaml`, `runner.py`, `state.py`, 화면 타임라인)

**critic**
- `format_evidence_list` 가 목록 앞에 번호를 붙인다: `[1] 제목 (연도) — 발췌`. 번호는 critic 에게 넘긴 순서(상위 `_MAX_LISTED`=20)다.
- 응답 JSON 에 `"off_topic": [번호, …]` 를 더한다. 프롬프트: "발췌가 하위질문의 핵심 개념을 다루지 않는 근거(같은 단어를 다른 뜻으로 쓴 논문 포함)의 번호. 없으면 빈 배열." 형식 예시는 **빈 배열** `[]` 로만 보인다(개수를 베끼지 않게).
- `Verdict.off_topic: list[int]`. `parse_verdict` 는 정수(또는 정수 문자열, 목록 표기 그대로인 `"[3]"`)만, 1..목록 길이 범위만, 중복 제거해 받는다. 배열이 아니면 빈 목록. 버린 값이 있으면 원본을 경고 로그에 남긴다(운영에서 "제외 0"의 원인을 가를 곳이 여기뿐이다). 판정 실패(`parse_failed`)면 빈 목록 — 판정을 못 읽었는데 근거를 지우면 안 된다.
- note 에 남은 목록 번호(`[2]`·`[2, 3]`·`[2-4]`)는 그 논문 제목(「…」)으로 바꾼다. 사용자는 목록을 보지 못하고 보고서(.docx)는 인용을 `[n]` 으로 렌더해 참고문헌 번호로 읽힌다. 괄호 안 번호가 하나라도 보인 목록 밖이면 그 괄호는 그대로 둔다.

**러너**
- critic 이 돌려준 번호를 그 회차 목록의 근거 id 로 바꾼다(목록 순서 = `subq.evidence_ids` 앞 20개).
- 각 무관 근거: 이 하위질문에서 뺀다(`evidence_ids`·`evidence_chunks`·순위 보조 `relevance`·`leaders`). **다른 하위질문이 링크하지 않은 근거면 `state.evidence` 에서도 지운다**(전체 풀을 비운다). 이 하위질문의 제외 목록(`SubQuestion.excluded_cnts: list[str]`)에 cnts_id 를 남겨 같은 하위질문의 다음 회차 검색에서 다시 걸려도 넣지 않는다. 다른 하위질문은 막지 않는다(그쪽에서는 관련 있을 수 있다).
- 판정·note 는 제외 전 목록을 보고 내린 것이다. 보인 근거(목록 앞 20편)를 모두 off_topic 에 넣고도 sufficient 라고 답하면 `parse_verdict` 가 insufficient 로 읽고 note 는 싣지 않는다(뒤집은 판정의 이유다) — 빼고 나면 남는 것은 0편이거나 발췌를 보이지 않은 목록 밖 근거뿐이다. 그래서 재검색 한도·상한 규칙 안에서 다시 찾고, 다시 찾지 못하고 끝나도 회차 기록·이벤트·trail 의 판정이 "충분·0편"이 되지 않는다 — 근거 없는 "충분"은 없다. 프롬프트도 모두 뺐으면 insufficient 로 하라고 요구한다.
- 한계 문장: 무관 제외로 0편이 된 하위질문은 "'…' 에 대해서는 모은 논문 N편이 모두 하위질문과 무관해 근거에서 뺐다"로 쓴다(상한에도 막혔으면 괄호로 덧붙이고 note 를 잇는다). 상한 분기("…에 닿아 검색된 논문 N편을 싣지 못했다")나 "근거를 찾지 못했다"로 보내면 critic 이 근거를 읽고 뺀 사실이 가려진다.
- **근거 번호**: 지금 `evidence_id(len(state.evidence))` 로 매겨 삭제하면 번호가 겹친다. `ResearchState.evidence_seq: int`(다음 번호)를 두고 늘리기만 한다. 스냅샷에 저장하고, 없는 옛 스냅샷은 기존 근거 번호의 최댓값+1 로 복원한다.
- 회차 기록·이벤트: `subq.rounds[]` 와 `critique` 이벤트에 `excluded`(이번 회차에 뺀 수)를 더한다. `research_stats` 의 `evidence_adopted` 는 지운 근거를 세지 않는다(현재 풀 크기).
- 보고서 `trail[]` 에 `excluded`(하위질문에서 뺀 총수)를 더한다.

**화면 (round04b 화면 위에 작게)**
- 탐색 타임라인 회차 줄(`ProgressPanel.vue` 의 `rs-round__stat`)에 `excluded > 0` 이면 "무관 N편 제외"를 붙인다. 자기점검이 실제로 걸러낸 장면이 보여야 한다(round04b spec §7-4 — 인터랙티브함). 옛 잡(필드 없음)은 표시하지 않는다.
- 타입(`types/research.ts`)·이벤트 합치기(`researchEvents.ts`)는 새 필드를 통과시킨다. 문서 부록(§14 의 탐색 경로)에도 "무관 N편 제외"를 적는다.

## 5. C — 계획 프롬프트 (`research_plan.yaml`)

규칙을 더한다(예시 없이):
- 모든 하위질문은 원 질문의 **핵심 개념** 안에 머문다. 원 질문의 주제와 이웃한 기술·분야를 나열하는 식으로 나누지 않는다.
- 질문이 넓으면 핵심 개념의 **측면**으로 나눈다 — 개념·정의, 방법·기법, 적용 분야, 성과·평가, 한계·과제 중 질문에 맞는 것.
- 각 하위질문에 원 질문의 **핵심어**를 그대로 넣는다(검색이 주제를 벗어나지 않게).
- 하위질문 수는 최대 `{{ limit }}` 개 — 핵심 개념이 좁으면 더 적어도 된다(지금 규칙 유지·명시).

프롬프트 렌더 테스트로 규칙 문구가 들어갔는지, `limit` 이 들어가는지 확인한다. 실제 분해 품질은 운영 전후 비교(§7)로 본다.

## 6. G — 문체·조사 (`research_synthesize.yaml`, `research_critique.yaml`, `synthesizer.py`)

- 종합 프롬프트: "모든 문장은 '~다'로 끝나는 문어체 평서문으로 쓴다('~합니다'·'~입니다' 금지)" — intro·summaries·future 모두.
- critic 프롬프트: note 도 같은 문체(한계 섹션에 그대로 실린다).
- 한계 문장의 주제 조사: `_topic(text)` 가 마지막 글자의 받침으로 '은/는'을 고른다. 한글이 아니면(영문·괄호로 끝남) 마지막 한글 음절이 아니라 **읽는 소리**를 알 수 없으므로 '는'이 아니라 `'…'(은)는` 을 쓴다 — 틀린 조사보다 병기가 낫다. `'…' 에 대해서는` 은 조사가 받침과 무관하므로 그대로 둔다. note 의 목록 번호를 제목으로 바꿀 때(§4) 바로 뒤 조사(은/는·이/가·을/를·과/와)도 같은 규칙(`hangul.josa`)으로 제목 끝 받침에 맞춘다 — 모델은 번호를 읽는 소리([1]=일)에 맞춰 조사를 붙인다.
- 모델이 "~합니다"를 섞어 쓰는 것을 코드로 고치지는 않는다(뜻이 바뀔 수 있다). 프롬프트 규칙으로 막고 운영 비교로 본다.

## 11. 보완 — 결과가 줄어 보이지 않게 (2026-09-29 추가, 사용자 승인)

### 11-0. 사용자 우려 (paraphrase)

> 무관 제외로 결과 양이 줄어드는 건 치명적이다. 시간은 늘어나는데 결과는 줄어든다는 게 크리티컬하다.

판단: 절마다 실리는 논문은 최대 5편 그대로이고, 줄어드는 것은 절에 실리지 않던 근거와 같은 단어·다른 뜻 논문이다. 다만 사용자에게는 "숫자가 줄었다"로 보이고, 걸러낸 논문이 사라지면 무엇을 왜 뺐는지 알 수 없다. 그래서 걸러낸 것을 **버리지 않고 보여 주고**, 운영에서 나쁘면 **재배포 없이 끌 수 있게** 한다.

### 11-1. 제외한 논문을 버리지 않고 보여 주기

- **백엔드**: 러너가 근거를 뺄 때(`_exclude_off_topic`) 그 논문의 서지 요약 `{cnts_id, title, personal_author, pub_date}` 를 회차 기록 `subq.rounds[].excluded_papers` 에 남긴다(풀에서 지워도 무엇을 뺐는지는 남는다). 보고서 `trail[]` 에는 하위질문에서 뺀 논문 전체를 `excluded_papers` 로 싣는다(회차 순, 중복 없음). 옛 스냅샷·옛 회차 기록은 없으면 빈 목록.
- **이유**: critic 은 논문마다 이유를 쓰지 않는다(출력 토큰·파싱 위험). 화면은 그 회차의 판단 근거(`note`)를 함께 보여 준다 — "자기점검이 이 하위질문의 핵심 개념과 무관하다고 판단" + note.
- **화면 — 타임라인**: 회차 줄의 "무관 N편 제외"를 누르면(버튼, `aria-expanded`) 그 회차에 뺀 논문 목록(저자 외 (연도) 「제목」, 누르면 `/papers/<cnts_id>` 새 창)과 그 회차의 note 가 펼쳐진다. 키보드로 열고 닫는다. 목록이 없는 옛 잡은 지금처럼 글자만.
- **화면 — 보고서**: 한계 섹션 뒤에 접힌 섹션 "관련성이 낮아 제외한 논문 (N)" — 하위질문별로 묶어 보인다. 제외가 없으면 섹션을 그리지 않는다. 초안(작성 중)에는 탐색 타임라인 데이터로 같은 목록을 만든다.
- **문서(Word·PDF)**: 부록 "탐색 경로" 뒤에 "관련성이 낮아 제외한 논문" 목록(하위질문별). 참고문헌 번호는 매기지 않는다 — 인용한 근거가 아니다.

### 11-2. 카운터에 "제외"

- `research_stats` 에 `excluded`(모든 하위질문에서 뺀 논문 수, 같은 논문을 두 하위질문이 뺐으면 두 번 센다 — 하위질문별 판단의 수) 를 더한다. counters 이벤트·단계 result·보고서 `stats` 가 같은 함수를 본다.
- 화면 카운터: "검토한 논문 · 채택한 근거 · **제외** · 재검색". 값이 없으면(옛 잡) 제외 칸을 그리지 않는다.
- 보고서 서론 한 줄(`reportIntro`)은 제외가 있으면 "…근거로 삼았다(무관한 N편은 걸러냈다)"를 덧붙인다.

### 11-3. 무관 제외 켜고 끄기 — `exclude_off_topic`

- 잡 파라미터 `exclude_off_topic`(int, 0 또는 1, 기본 1). `_PARAM_BOUNDS` 에 `(int, 0, 1)`. 잡을 만들 때 API 가 합쳐 저장하므로 `nl-lib-fastapi` 도 새 이미지여야 한다(이미 배포 대상).
- 0 이면 critic 은 그대로 번호를 돌려주지만 러너는 빼지 않는다. 대신 회차 기록에 `flagged`(무관하다고 본 수)를 남겨, 켠 잡과 끈 잡을 나란히 비교할 때 "끈 잡에서도 이만큼을 무관하다고 봤다"를 알 수 있게 한다. 끈 잡의 화면은 "무관 의심 N편(제외 안 함)"으로 보인다.
- 끄는 방법(화면 입력 없음 — 운영자가 API 로): `curl -s -X POST http://<서버>:92/api/research -H 'Content-Type: application/json' -d '{"question":"…","params":{"exclude_off_topic":0}}'`.

### 11-4. 운영 합격 기준

배포 뒤 기준 잡(2026-09-29 10:20, "컴퓨팅 자원에 대한 연구가 궁금해", 6절 27편)과 같은 질문을 기본 파라미터로 돌려 비교한다. 가능하면 `exclude_off_topic: 0` 잡도 하나 돌려 셋을 나란히 본다.

| 기준 | 합격 |
|---|---|
| 보고서에 실린 논문 수(`sections[].papers`) | **27편 이상** |
| 질문의 핵심 하위질문(자원 관리·할당 쪽)의 근거 수 | 기준 잡의 2편보다 늘어남 |
| 걸린 시간(`finished_at - started_at`) | 기준 잡보다 크게 늘지 않음(1.5배 이내) |
| 같은 단어·다른 뜻 논문 | 절 본문에서 빠지고 "제외한 논문"에 보임 |

어긋나면: 제외 기준 문구를 "명백히 무관한 것만"으로 좁히거나(`research_critique.yaml`), 잡 파라미터로 끈다. 비교 쿼리:

```sql
select id, left(question, 20) as q, finished_at - started_at as took,
       jsonb_array_length(report->'sections') as sections,
       (select sum(jsonb_array_length(s->'papers')) from jsonb_array_elements(report->'sections') s) as papers,
       report->'stats' as stats, params->'exclude_off_topic' as excl
from research_jobs where status = 'completed' order by created_at desc limit 5;
```

하위질문별로는 `select t->>'subquestion', t->>'evidence_count', t->>'excluded' from research_jobs, jsonb_array_elements(report->'trail') t where id = '<잡 id>';`.
