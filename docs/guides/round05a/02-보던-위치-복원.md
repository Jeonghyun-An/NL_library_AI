## 이 챕터의 자리

사용자 결정은 "상세에서 돌아갈 때 **보던 곳의 위치로까지 그대로**"다(spec §0·D4). 그런데 보고서와 검색 결과는 돌아온 화면이 마운트된 뒤 비동기로 다시 그린다 — 보고서는 `GET /api/research/{id}` 를 받아서, 검색 결과는 기록(`/api/history/<h>`)을 받아서. 브라우저의 스크롤 복원과 Nuxt 의 기본 스크롤은 그 전에 끝나서 화면은 맨 위에 선다(00 §1-1 의 7번).

그래서 **복원을 화면이 직접 한다.** 떠날 때 누른 요소의 앵커와 화면 높이를 주소에 싣고, 돌아와서 내용이 그려진 뒤 그 요소를 같은 높이에 즉시 맞춘다.

```text
떠날 때 (출처 화면)
  클릭 → spotOf(요소, 앵커) = { at, y: 그 요소의 지금 화면 높이 }
       → useDetailLeave.leave(url, spot): ① router.replace(이 주소 + at·y)  ② navigateTo(상세 주소)
  새 창 제외 논문 링크 → stampExcludedLink: 누르는 순간 href 에 y 를 싣는다(이 화면 주소는 그대로)

돌아올 때 (출처 화면이 새로 마운트)
  setup      자리 = 주소의 at·y, 없으면 그 기록의 history.state.skxSpot   ← 들어온 순간만 본다
  page meta  scrollToTop = !holdsReturnSpot(…) → Nuxt 의 스크롤을 끈다
  onMounted  맨 위로(instant) · 사용자 입력 듣기 · watch(ready)
  ready      기한 = 지금 + maxWait → nextTick → rAF → tryAlign
  tryAlign   보이는 그 요소? ─ 있음 → scrollBy(요소 top − 목표 높이, instant), 칩이면 focus(preventScroll)
                             │        → finish(요소) → hold(요소)
                             ├ 없음·기한 전 → 100ms 뒤 다시
                             └ 기한 넘김   → finish(null): 맨 위 그대로, 자리 지움
  finish     router.replace(at·y 를 뗀 주소, state.skxSpot = 자리)
  hold       매 프레임 그 요소를 목표 높이에 붙잡는다(1px 이상 밀릴 때만, 최대 15초)
  사용자 입력(세로 휠·터치·키·누르기 — 뒤로·앞으로·새로고침 손짓은 빼고)
             맞추기 전 → 멈추고 자리 지움 / 맞춘 뒤 → 붙잡기를 멈추고 state 의 자리 지움
```

쓰는 화면은 둘이다 — 딥리서치 보고서(`pages/research/[id].vue` — 인용칩·제외 목록 항목)와 논문 검색 결과(`pages/papers/index.vue` — 결과 카드). 판단과 계산은 `utils/restorePosition.ts` 의 순수 함수(§2.9), DOM·라우터·타이머는 `composables/useRestorePosition.ts`(§2.10)가 맡는다.

**화면 규칙(plan).** 자동 스크롤로 끌고 가지 않는다 — 복원은 즉시 이동이고, 사용자가 먼저 움직이면 맞추지 않는다. 키보드·aria·`prefers-reduced-motion` 을 지킨다.

## 2. 구현 (클론코딩)

### 2.9 `utils/restorePosition.ts` — 복원 계산과 주소·state 의 자리

**책임.** 복원에 드는 계산과 판단을 DOM 없이 한다. 다섯 묶음이다.

| 묶음 | 함수·상수 | 뜻 |
|---|---|---|
| 기다림·붙잡기 | `RESTORE_MAX_WAIT_MS`(2000)·`RESTORE_RETRY_MS`(100)·`RESTORE_HOLD_MS`(15000)·`restoreStep` | 늦게 붙는 목록(탐색 타임라인의 이벤트 재생 등)을 2초까지 100ms 마다 찾는다. 맞춘 뒤 15초까지 붙잡는다 |
| 굴릴 양 | `scrollDelta`·`holdDelta`·`targetTop` | 요소 top − 목표 높이. 붙잡는 동안은 1px 이상 밀릴 때만. 목표 높이는 떠날 때의 `y`, 창이 줄어 화면 밖이면 요소가 48px 은 보이게, 모르면 화면 위쪽 1/3 |
| 떠날 때 | `spotOf`·`isPlainClick` | 누른 요소의 지금 화면 높이(반올림, 위로 넘쳤으면 0). 수식 키 없는 왼쪽 클릭만 이 탭에서 옮긴다 |
| 사용자 움직임 | `isUserMove`(+ 안의 `isHistoryGesture`) | 휠은 세로가 앞설 때만, 뒤로·앞으로·새로고침 손짓은 움직임이 아니다 |
| 주소·state 의 자리 | `hasSpot`·`withSpot`·`withoutSpot`·`SPOT_STATE_KEY`·`spotFromState`·`spotState`·`stateWithSpot`·`stateWithoutSpot`·`holdsReturnSpot`, 그리고 `pageOfItem` | 주소 쿼리와 `history.state` 에 자리를 싣고 떼기, 검색 결과의 쪽 찾기 |

**왜 이렇게 짰나.**

- **목표 높이는 떠날 때의 높이 그대로**(`targetTop`). 사용자 눈에 "누른 칩이 눌렀던 그 높이에 있다"가 복원이다. 창이 줄어 그 높이가 화면 밖이면 그대로 두면 요소가 안 보이므로 `innerHeight − 48` 로 당긴다. 새 창 제외 링크를 높이 없이 연 경우(`y` 없음)는 위쪽 1/3 이다.
- **`holdDelta` 의 1px 문턱.** 붙잡기는 매 프레임 요소 위치를 잰다. 레이아웃은 소수점 단위라 0.4px 같은 차이가 늘 있다. 문턱이 없으면 매 프레임 `scrollBy` 를 부른다.
- **`isUserMove` — 무엇을 움직임으로 보지 않나**(`4e8ea36`). 맞춘 자리는 그 기록에 남겨 상세로 **앞으로** 갔다 돌아올 때 다시 쓴다. 그런데 앞으로 가는 손짓 자체가 입력 이벤트다 — 마우스 옆 버튼(button 3·4), Alt+←/→, Cmd+[ ], F5·Ctrl/Cmd+R, 수식 키만 누르기. 이것을 움직임으로 치면 떠나는 순간 자리를 지워 다음에 돌아올 때 잃는다. 휠은 **세로가 앞설 때만** 움직임이다 — 맥 트랙패드의 두 손가락 뒤로 가기가 남긴 가로 관성 휠이 돌아온 화면에 떨어져 맞추기를 취소했다.
- **`history.state` 에 남기는 자리(`skxSpot`)는 주소의 `at`·`y` 와 같은 문자열 모양이다**(`{ at: string; y?: string }`). 그래서 `spotFromState` 는 모양만 보고, 값의 검증은 `readReturnSpot` 이 주소와 똑같이 한다 — 검증이 한 곳이다. `y` 가 숫자인 state 는 틀린 모양으로 버린다(테스트).
- **`router.replace` 에는 조각(`spotState`)만 넘긴다.** vue-router 는 `replace` 의 `state` 를 지금 기록의 `history.state` 위에 덮어 자기 열쇠(`back`·`current`·`forward`·`position`·`scroll` 등)를 지킨다. 지금 state 를 통째로 넘기면 옛 `current`(at·y 를 실은 주소)가 새 주소를 덮는다.
- **지울 때는 열쇠를 빼지 않고 `null` 로 둔다**(`stateWithoutSpot`). vue-router 의 `push` 는 떠나는 기록에, 자기가 쥔 state 사본 위에 지금 `history.state` 를 덮어 다시 적는다. 우리가 `window.history.replaceState` 로 열쇠를 빼 버리면 덮을 값이 없어 사본에 남은 옛 자리가 되살아난다. `null` 이면 `null` 이 덮는다.
- **`holdsReturnSpot(query, state)`** — 주소나 state 중 한 곳에라도 자리가 있으면 Nuxt 의 스크롤을 끈다. Nuxt 가 `scrollToTop` 을 부를 때의 `history.state` 는 들어갈 기록의 것이다(뒤로·앞으로는 브라우저가 이미 바꿨고, push 는 `pushState` 뒤에 스크롤을 정한다).
- **`withSpot`·`withoutSpot` 은 원본을 고치지 않는다.** `route.query` 는 라우터의 것이라 복사본을 만든다.
- **`pageOfItem`** — 검색 결과는 쪽으로 나뉜다. 누른 카드가 셋째 쪽이면 그 쪽을 열어야 요소가 생긴다(§2.16).

**리뷰에서 바뀐 점.** 처음(`9970e84`)은 기다림·굴릴 양·떠날 때·주소의 자리·`pageOfItem` 뿐이었다. 최종 검토(`4e8ea36`)가 붙잡기(`RESTORE_HOLD_MS`·`holdDelta`), 사용자 움직임 판정(`isUserMove`), state 의 자리(`SPOT_STATE_KEY` 와 그 함수들), Nuxt 스크롤 판단(`holdsReturnSpot`)을 더했다.

**파일**: `frontend/utils/restorePosition.ts` — 전체(새 파일)

```ts
// frontend/utils/restorePosition.ts
import type { ReturnSpot } from "~/utils/detailSource";

// 내용이 준비된 뒤에도 늦게 붙는 목록(탐색 타임라인의 이벤트 재생 등)을 이만큼 기다린다
export const RESTORE_MAX_WAIT_MS = 2000;
export const RESTORE_RETRY_MS = 100;
// 맞춘 요소를 사용자가 움직이기 전까지 붙잡아 두는 한도. 검색 결과로 돌아와 끝나지 않았던 AI 요약을 다시 받으면 스트림이
// 끝날 때까지 위쪽 요약이 자라고 끝에 인용 논문을 목록 맨 위로 올려, 그 스트림이 걸리는 만큼(길면 이 정도) 카드가 밀린다
export const RESTORE_HOLD_MS = 15000;
// 창이 줄어 떠날 때의 높이가 화면 밖이면 요소가 이만큼은 보이게 올린다
const KEEP_VISIBLE_PX = 48;
// 맞춘 자리를 그 기록의 history.state 에 남기는 열쇠 — 값은 주소의 at·y 와 같은 문자열이라 readReturnSpot 이 그대로 읽는다
export const SPOT_STATE_KEY = "skxSpot";
// 브라우저의 뒤로·앞으로·새로고침 손짓에 쓰이는 키
const MODIFIER_KEYS = new Set(["Alt", "Control", "Meta", "Shift"]);
const HISTORY_KEYS = new Set(["ArrowLeft", "ArrowRight", "[", "]"]);

export type QueryValue = string | null | (string | null)[];
export type RestoreStep = "align" | "retry" | "give-up";
export type SpotQuery = { at: string; y?: string };
export type SpotState = Record<typeof SPOT_STATE_KEY, SpotQuery | null>;
// 사용자 입력 이벤트에서 움직임을 가리는 데 보는 값 — 이벤트 종류마다 있는 것만 온다
export type UserInput = {
  type: string;
  deltaX?: number;
  deltaY?: number;
  button?: number;
  key?: string;
  altKey?: boolean;
  ctrlKey?: boolean;
  metaKey?: boolean;
};

export function scrollDelta(elementTop: number, targetY: number): number {
  return Math.round(elementTop - targetY);
}

// 붙잡는 동안은 1px 넘게 밀렸을 때만 되돌린다 — 소수점 아래 차이로 매 프레임 굴리지 않게
export function holdDelta(elementTop: number, targetY: number): number {
  const off = elementTop - targetY;
  return Math.abs(off) >= 1 ? Math.round(off) : 0;
}

// 떠날 때 높이를 모르면(새 창 링크를 높이 없이 연 경우) 화면 위쪽 1/3 에 둔다
export function targetTop(y: number | null, viewportHeight: number): number {
  if (y === null) return Math.round(viewportHeight / 3);
  return Math.min(y, Math.max(0, viewportHeight - KEEP_VISIBLE_PX));
}

export function restoreStep(found: boolean, now: number, deadline: number): RestoreStep {
  if (found) return "align";
  return now < deadline ? "retry" : "give-up";
}

export function spotOf(el: Pick<Element, "getBoundingClientRect">, at: string): ReturnSpot {
  return { at, y: Math.max(0, Math.round(el.getBoundingClientRect().top)) };
}

// 새 창·새 탭으로 여는 클릭(수식 키·가운데 버튼)은 브라우저에 맡긴다
export function isPlainClick(e: Pick<MouseEvent, "button" | "ctrlKey" | "metaKey" | "shiftKey" | "altKey">): boolean {
  return e.button === 0 && !e.ctrlKey && !e.metaKey && !e.shiftKey && !e.altKey;
}

// 브라우저의 뒤로·앞으로·새로고침(마우스 옆 버튼, Alt·Cmd+방향키·대괄호, F5·Ctrl+R, 수식 키만 누름) — 화면 안에서
// 자리를 옮기는 손짓이 아니다. 움직임으로 치면 맞춘 자리를 지워 앞으로 갔다 다시 돌아올 때 그 자리를 잃는다
function isHistoryGesture(e: UserInput): boolean {
  if (e.type === "pointerdown") return e.button === 3 || e.button === 4;
  if (e.type !== "keydown" || e.key === undefined) return false;
  if (MODIFIER_KEYS.has(e.key) || e.key === "F5") return true;
  if ((e.altKey || e.metaKey) && HISTORY_KEYS.has(e.key)) return true;
  return !!(e.ctrlKey || e.metaKey) && e.key.toLowerCase() === "r";
}

// 사용자가 화면을 움직이려는 입력인지. 휠은 세로가 앞설 때만 — 맥 트랙패드의 두 손가락 뒤로 가기가 남긴 가로 관성 휠이
// 돌아온 화면에 떨어져도 맞추기를 취소하지 않게
export function isUserMove(e: UserInput): boolean {
  if (e.type === "wheel") {
    const dy = Math.abs(e.deltaY ?? 0);
    return dy > 0 && dy >= Math.abs(e.deltaX ?? 0);
  }
  return !isHistoryGesture(e);
}

export function hasSpot(query: Readonly<Record<string, unknown>>): boolean {
  return "at" in query || "y" in query;
}

function isRecord(v: unknown): v is Record<string, unknown> {
  return typeof v === "object" && v !== null && !Array.isArray(v);
}

// 모양만 본다 — 앵커·높이의 값은 readReturnSpot 이 주소의 at·y 와 똑같이 가린다
export function spotFromState(state: unknown): SpotQuery | null {
  const v = isRecord(state) ? state[SPOT_STATE_KEY] : null;
  if (!isRecord(v) || typeof v.at !== "string") return null;
  if (v.y === undefined) return { at: v.at };
  return typeof v.y === "string" ? { at: v.at, y: v.y } : null;
}

// router.replace 의 state 로 넘기는 조각 — vue-router 는 이것을 지금 기록의 state 위에 덮어 자기 열쇠(back·current·
// position 등)를 지킨다. 지금 state 를 통째로 넘기면 옛 current(at·y 를 실은 주소)가 새 주소를 덮는다
export function spotState(spot: ReturnSpot | null): SpotState {
  if (!spot?.at) return { [SPOT_STATE_KEY]: null };
  return { [SPOT_STATE_KEY]: spot.y === null ? { at: spot.at } : { at: spot.at, y: String(spot.y) } };
}

export function stateWithSpot(state: unknown, spot: ReturnSpot | null): Record<string, unknown> {
  return { ...(isRecord(state) ? state : {}), ...spotState(spot) };
}

// 열쇠를 빼지 않고 null 로 둔다 — vue-router 의 push 는 떠나는 기록에 자기가 쥔 state 사본 위에 history.state 를 덮어
// 다시 적어, 열쇠를 빼면 사본에 남은 옛 자리가 되살아난다
export function stateWithoutSpot(state: unknown): Record<string, unknown> {
  return stateWithSpot(state, null);
}

// 돌아왔을 때 맞출 자리가 주소나 그 기록의 state 에 있는지 — 있으면 Nuxt 는 굴리지 않고 화면이 직접 맞춘다.
// Nuxt 의 scrollToTop 이 불리는 때의 history.state 는 들어갈 기록의 것이다(뒤로·앞으로는 브라우저가 이미 바꿨고,
// push 는 pushState 뒤에 스크롤을 정한다)
export function holdsReturnSpot(query: Readonly<Record<string, unknown>>, state: unknown): boolean {
  return hasSpot(query) || spotFromState(state) !== null;
}

export function withoutSpot(query: Readonly<Record<string, QueryValue>>): Record<string, QueryValue> {
  const out = { ...query };
  delete out.at;
  delete out.y;
  return out;
}

export function withSpot(query: Readonly<Record<string, QueryValue>>, spot: ReturnSpot): Record<string, QueryValue> {
  const out = withoutSpot(query);
  if (spot.at) {
    out.at = spot.at;
    if (spot.y !== null) out.y = String(spot.y);
  }
  return out;
}

export function pageOfItem(ids: readonly string[], id: string, pageSize: number): number | null {
  const i = ids.indexOf(id);
  return i < 0 ? null : Math.floor(i / pageSize) + 1;
}
```

### 2.10 `composables/useRestorePosition.ts` — 맞추기·붙잡기와 떠날 때 자리 싣기

**책임.** 셋을 내보낸다.

- `useRestorePosition(ready, opts?)` → `{ pending, anchor }` — 돌아온 화면에서 맞추고 붙잡는다. `pending` 은 맞추는 중인지(화면이 쪽 바꿈 맨 위 이동·제외 목록 펼치기를 이것으로 정한다), `anchor` 는 해석한 앵커(어느 쪽을 열지·어느 논문을 펼칠지).
- `useDetailLeave()` → `{ leave(url, spot) }` — 떠날 때 이 화면 주소에도 자리를 싣고 상세로 간다.
- `stampExcludedLink(e, job, cnts)` — 새 창 제외 논문 링크의 `href` 에 누르는 순간의 높이를 싣는다.

**흐름을 따라 읽기.**

1. **들어온 순간의 자리만 본다**(setup). `given` 은 주소에 `at`·`y` 가 있으면 그 쿼리, 없으면 그 기록의 state 에 남긴 자리다. 반응형으로 지켜보지 않는다 — 이 화면을 떠나기 직전 `useDetailLeave` 가 주소에 `at`·`y` 를 다시 싣는데, 그때 반응하면 떠나는 중에 맞춘다. `pending` 은 선택자를 만들 수 있을 때(앵커 문법이 맞을 때)만 참이다.
2. **마운트**(`onMounted`). 자리가 있었는데 모양이 틀렸으면(`given !== null` 인데 `pending` 이 거짓 — 손으로 고친 주소 등) `scrollToTop` 이 Nuxt 의 스크롤을 이미 껐으므로 직접 맨 위로 올리고 자리를 뗀다(`4e8ea36`). 맞출 자리가 있으면 맨 위에 두고(내용을 기다리는 동안), 사용자 입력을 듣고, `ready` 를 지켜본다(`immediate` — 이미 준비됐으면 바로).
3. **잴 때**(`schedule`). 기한은 **내용이 준비된 때부터** 센다 — 느린 응답 시간은 기한에 넣지 않고, 준비된 뒤 늦게 붙는 목록만 기다린다. `nextTick` 으로 Vue 가 DOM 을 고친 뒤, `requestAnimationFrame` 으로 그 프레임의 배치가 끝난 다음에 잰다 — 같은 틱에 펼친 제외 목록(§2.14) 같은 변화까지 반영된 위치다.
4. **맞추기**(`tryAlign`). 같은 앵커가 여럿일 수 있다(같은 제외 논문이 보고서 목록과 타임라인 회차에). `isShown`(`getClientRects().length > 0`)으로 **보이는 첫 요소**를 고른다 — 접힌 목록 안의 사본(`display:none`)은 높이가 없다. 찾으면 `window.scrollBy({ top: 요소 top − 목표 높이, behavior: "instant" })`. 인용칩이면 `focus({ preventScroll: true })` — 칩은 초점을 받으면 팝오버를 연다(round04b 의 `@focusin="show"`). `preventScroll` 이 없으면 초점 이동이 방금 맞춘 자리를 다시 굴린다.
5. **끝내기**(`finish`). 맞췄으면 `rememberSpot` — 주소에서 `at`·`y` 를 떼고 같은 자리를 그 기록의 state 에 싣는다(`router.replace({ query, state })`). 새로고침·링크 복사에 옛 자리가 따라가지 않되, 상세로 앞으로 갔다 돌아와도 같은 요소로 온다. 자리를 state 에서 읽었으면 주소는 이미 깨끗하므로 `history.replaceState(…, "")` 로 state 만 고친다(url 인자를 생략해 주소는 그대로). 못 맞췄으면 `dropSpot` 으로 주소와 state 의 자리를 모두 비운다 — 다음에 돌아와 엉뚱한 데로 끌지 않게.
6. **순서 지키기.** `replace` 는 비동기다. 그 사이 사용자가 움직이면 `moved` 를 세우고, **다 적은 뒤에** 지운다(`finally` 의 `forgetSpot`). 먼저 지우면 늦게 끝난 `replace` 가 자리를 다시 싣는다.
7. **붙잡기**(`hold`). 맞춘 뒤 15초 동안 매 프레임 그 요소의 위치를 재서 1px 이상 밀렸으면 되돌린다. 목표 높이는 맞출 때 한 번 정한 것을 쓴다. 필요한 경우가 둘이다 — 요약이 끝나기 전에 떠난 검색 기록은 돌아오면 AI 요약을 다시 받아 위쪽 요약 칸이 자라고 끝에 인용 논문을 목록 맨 위로 올리며, 작성 중 초안의 절은 올라오며 나타난다. 요소가 사라지면(`isShown` 거짓) 멈춘다. 맞추는 프레임과 붙잡는 프레임은 차례로 돌아 `frame` 하나만 쥔다.
8. **사용자 움직임**(`onUserMove`). `wheel`·`touchstart`·`keydown`·`pointerdown` 을 캡처·passive 로 듣는다(`scroll` 은 듣지 않는다 — 우리가 굴린 것도 `scroll` 을 낸다). `isUserMove` 가 참이면 듣기와 프레임을 멈추고, 맞추기 전이면 맞추지 않고 끝내며(자리 지움), 맞춘 뒤면 붙잡기를 멈추고 state 의 자리를 지운다 — 움직인 뒤에는 그 요소가 더는 읽던 자리가 아니다.
9. **떠날 때 정리**(`onBeforeUnmount`). `disposed` 를 세우고 프레임·타이머·듣기를 걷는다. 화면을 떠난 뒤 늦게 도는 프레임이 새 화면의 주소·스크롤을 건드리지 않게(`4e8ea36`).

**`useDetailLeave` — 왜 replace 를 먼저 하고 push 하나.** vue-router 는 `push` 할 때 새 기록의 `state.back` 에 **그 순간의 지금 위치**를 적는다. 먼저 이 화면 주소에 `at`·`y` 를 실어 두면(`replace`) 상세 기록의 `back` 이 자리를 실은 출처 주소가 된다. 그러면 상세의 [돌아가기]가 `shouldGoBack` 으로 `router.back()` 을 고르거나 사용자가 브라우저 뒤로 가기를 눌러도, 도착하는 기록의 주소에 맞출 자리가 있다(spec §7 ②). 순서를 바꾸면 도착한 기록에 자리가 없다.

**`stampExcludedLink` — 새 창 링크.** 제외 논문은 새 창으로 연다(round04c). 이 화면은 그대로 남으니 이 화면 주소를 고칠 필요가 없고, 새 창 주소에만 누르는 순간의 높이를 싣는다. `click` 뿐 아니라 `auxclick`(가운데·오른쪽 버튼)과 `contextmenu` 에서도 싣는다 — 오른쪽 클릭 메뉴의 "새 탭에서 열기"도 같은 자리를 받게. 메뉴가 `auxclick` 보다 먼저 뜨는 브라우저가 있다(`4e8ea36`).

**쓰는 화면의 규약.** `definePageMeta({ scrollToTop: (to) => !holdsReturnSpot(to.query, import.meta.client ? window.history.state : null) })`. Nuxt 의 기본 스크롤(페이지 로딩이 끝난 다음 프레임에 맨 위나 저장 위치로)과 경합하지 않게 끈다. `definePageMeta` 는 컴파일 때 꺼내지는 매크로라 그 함수는 setup 의 지역 변수를 쓸 수 없다 — 그래서 import 한 순수 함수(`holdsReturnSpot`)만 부른다. 서버 렌더에는 `window` 가 없어 `import.meta.client` 로 가린다.

**리뷰에서 바뀐 점.** 처음(`9970e84`)은 140줄이었다 — 주소의 자리만 읽고, 맞추면(또는 포기하면) 주소에서 `at`·`y` 를 떼고 끝냈다. 사용자 입력은 곧바로 `finish` 였다. 최종 검토(`4e8ea36`)가 찾은 것과 고친 것이다.

| 찾은 것 | 고친 것 |
|---|---|
| 한 번 돌아와 맞춘 뒤 상세로 앞으로 갔다 다시 돌아오면 맨 위 — 상세 기록의 `state.back` 은 처음 주소(자리 포함)를 들고 있어 `router.back()` 은 오는데, 그 기록의 주소는 이미 깨끗하다 | 자리를 그 기록의 state(`skxSpot`)에 남기고, 주소에 자리가 없으면 그것을 읽는다. 움직이면 지운다 |
| 검색 기록이 AI 요약을 다시 받거나 초안 절이 나타나며 맞춘 카드·칩이 밀린다 | 맞춘 뒤 붙잡기(`hold`, 15초) |
| 모양이 틀린 `at` 이면 Nuxt 스크롤만 꺼진 채 직전 화면의 높이에서 시작하고 주소에도 남는다 | 맨 위에서 시작하고 자리를 뗀다 |
| 가로 스와이프의 관성 휠·마우스 옆 버튼·Alt+화살표가 맞추기를 취소하거나 남긴 자리를 지운다 | `isUserMove` 로 가린다 |
| 오른쪽 클릭 메뉴의 "새 탭에서 열기"에 자리가 실리지 않는다 | `contextmenu` 에서도 싣는다(`stampExcludedLink`·`CitationChip`) |
| 화면을 떠난 뒤 늦게 도는 프레임이 새 화면 주소를 건드릴 수 있다 | `disposed`·`cancelFrames` |

**파일**: `frontend/composables/useRestorePosition.ts` — 전체(새 파일)

```ts
// frontend/composables/useRestorePosition.ts
import { nextTick, onBeforeUnmount, onMounted, ref, watch, type ComputedRef, type Ref } from "vue";
import {
  anchorSelector,
  excludedAnchor,
  excludedDetailUrl,
  parseAnchor,
  readReturnSpot,
  type Anchor,
  type ReturnSpot,
} from "~/utils/detailSource";
import {
  RESTORE_HOLD_MS,
  RESTORE_MAX_WAIT_MS,
  RESTORE_RETRY_MS,
  hasSpot,
  holdDelta,
  isUserMove,
  restoreStep,
  scrollDelta,
  spotFromState,
  spotOf,
  spotState,
  stateWithSpot,
  stateWithoutSpot,
  targetTop,
  withSpot,
  withoutSpot,
} from "~/utils/restorePosition";

// 사용자가 먼저 움직이면 맞추지 않고, 맞춘 뒤 움직이면 더 붙잡지 않는다 — 읽기 시작한 화면을 끌고 가지 않게.
// scroll 은 넣지 않는다 — 맞추며 직접 굴린 것도 scroll 을 낸다
const USER_MOVES = ["wheel", "touchstart", "keydown", "pointerdown"] as const;

// 서버 렌더에는 history 가 없다. 두 화면 모두 내용을 마운트 뒤에 받아 pending 이 서버 렌더 결과를 바꾸지 않는다
function entryState(): unknown {
  return import.meta.client ? window.history.state : null;
}

// 접힌 목록 안의 사본(display:none)은 높이가 없다
function isShown(el: HTMLElement): boolean {
  return el.isConnected && el.getClientRects().length > 0;
}

/**
 * 상세에서 돌아온 화면에서, 떠날 때 누른 요소를 같은 화면 높이에 즉시 맞추고 사용자가 움직이기 전까지 붙잡아 둔다.
 * 자리는 주소의 at·y 에서, 없으면 그 기록의 history.state 에 남긴 자리(한 번 맞춰 주소를 비운 뒤 앞으로 갔다 다시
 * 돌아온 경우)에서 읽는다. ready 는 그 요소가 든 내용(보고서·복원한 결과 목록)이 그려질 준비가 됐는지 — 화면이 정한다.
 * 쓰는 화면은 definePageMeta({ scrollToTop: (to) => !holdsReturnSpot(to.query, history.state) }) 로 Nuxt 의 스크롤을 끈다
 */
export function useRestorePosition(
  ready: Ref<boolean> | ComputedRef<boolean>,
  opts: { maxWaitMs?: number } = {},
): { pending: Readonly<Ref<boolean>>; anchor: Anchor | null } {
  const route = useRoute();
  const router = useRouter();
  // 들어온 순간의 자리만 본다 — 이 화면을 떠나기 직전 주소에 at·y 를 다시 싣는데(useDetailLeave) 그때 맞추면 안 된다
  const given = hasSpot(route.query) ? route.query : spotFromState(entryState());
  const spot = readReturnSpot(given ?? {});
  const selector = spot.at ? anchorSelector(spot.at) : null;
  const anchor = spot.at ? parseAnchor(spot.at) : null;
  const pending = ref(selector !== null);
  let deadline = 0;
  let scheduled = false;
  let timer: ReturnType<typeof setTimeout> | null = null;
  // 맞추는 프레임과 붙잡는 프레임은 차례로 돌아 하나만 쥔다
  let frame = 0;
  // 맞춘 자리를 그 기록의 state 에 다 적었는지, 그 전에 사용자가 움직였는지
  let remembered = false;
  let moved = false;
  let disposed = false;

  function listen(): void {
    for (const type of USER_MOVES) window.addEventListener(type, onUserMove, { capture: true, passive: true });
  }

  function unlisten(): void {
    for (const type of USER_MOVES) window.removeEventListener(type, onUserMove, true);
  }

  function cancelFrames(): void {
    if (timer) clearTimeout(timer);
    timer = null;
    if (frame) cancelAnimationFrame(frame);
    frame = 0;
  }

  // 맞춘 뒤 처음 움직이면 더 붙잡지 않고 남긴 자리도 지운다 — 움직이기 전까지는 앞뒤로 오가거나 새로고침해도 같은
  // 요소로 돌아와야 하지만, 움직인 뒤에는 그 요소가 더는 읽던 자리가 아니다
  function onUserMove(e: Event): void {
    if (!isUserMove(e)) return;
    unlisten();
    cancelFrames();
    if (pending.value) {
      finish(null);
      return;
    }
    moved = true;
    if (remembered) forgetSpot();
  }

  function finish(aligned: HTMLElement | null): void {
    if (!pending.value) return;
    pending.value = false;
    if (!aligned) {
      unlisten();
      dropSpot();
      return;
    }
    // 다 적은 뒤에야 지운다 — 먼저 지우면 늦게 끝난 replace 가 자리를 다시 싣는다
    void rememberSpot().finally(() => {
      remembered = true;
      if (moved && !disposed) forgetSpot();
    });
  }

  // 맞춘 자리를 그 기록의 state 에 남기고 주소에서는 뗀다 — 새로고침·링크 복사에 옛 자리가 따라가지 않되, 상세로 앞으로
  // 갔다 돌아와도 같은 요소로 온다. 상세의 [돌아가기]가 고르는 router.back() 은 이 기록의 깨끗한 주소로 온다
  function rememberSpot(): Promise<unknown> {
    if (hasSpot(route.query)) return router.replace({ query: withoutSpot(route.query), state: spotState(spot) });
    window.history.replaceState(stateWithSpot(window.history.state, spot), "");
    return Promise.resolve();
  }

  // 맞추지 못했으면(요소가 없음·사용자가 먼저 움직임·모양이 틀림) 남긴 자리도 비운다 — 다음에 돌아와 엉뚱한 데로 끌지 않게
  function dropSpot(): void {
    if (hasSpot(route.query)) void router.replace({ query: withoutSpot(route.query), state: spotState(null) });
    else forgetSpot();
  }

  // 주소는 그대로 두고(url 인자 생략) state 의 자리만 지운다
  function forgetSpot(): void {
    if (spotFromState(window.history.state)) window.history.replaceState(stateWithoutSpot(window.history.state), "");
  }

  function visibleTarget(): HTMLElement | null {
    return Array.from(document.querySelectorAll<HTMLElement>(selector!)).find(isShown) ?? null;
  }

  function tryAlign(): void {
    timer = null;
    frame = 0;
    if (!pending.value) return;
    const el = visibleTarget();
    switch (restoreStep(el !== null, Date.now(), deadline)) {
      case "retry":
        timer = setTimeout(tryAlign, RESTORE_RETRY_MS);
        return;
      case "align": {
        const top = targetTop(spot.y, window.innerHeight);
        window.scrollBy({ top: scrollDelta(el!.getBoundingClientRect().top, top), behavior: "instant" });
        // 인용칩은 초점을 돌려 주면 칩의 초점 열림으로 팝오버가 다시 열린다
        if (anchor?.kind === "cite") el!.focus({ preventScroll: true });
        finish(el);
        hold(el!, top);
        return;
      }
      case "give-up":
        // 보고서가 다른 시도로 바뀌었거나 결과가 바뀌어 요소가 없다 — 오류 없이 맨 위에 둔다
        finish(null);
        return;
    }
  }

  // 맞춘 뒤 사용자가 움직이기 전까지 그 요소를 같은 화면 높이에 붙잡는다 — 위쪽의 AI 요약을 다시 받아 펼치거나 인용 논문을
  // 맨 위로 올릴 때, 초안 절이 올라오며 나타날 때 밀린 만큼 즉시 되돌린다. 목표 높이는 맞출 때 한 번 정한 것을 쓴다
  function hold(el: HTMLElement, top: number): void {
    const until = Date.now() + RESTORE_HOLD_MS;
    const step = (): void => {
      frame = 0;
      if (Date.now() >= until || !isShown(el)) return;
      const delta = holdDelta(el.getBoundingClientRect().top, top);
      if (delta !== 0) window.scrollBy({ top: delta, behavior: "instant" });
      frame = requestAnimationFrame(step);
    };
    frame = requestAnimationFrame(step);
  }

  // 내용이 DOM 에 붙은 뒤(nextTick) 배치가 끝난 다음 프레임에 잰다. 기한은 내용이 준비된 때부터 센다 —
  // 늦게 붙는 목록은 기다리되 느린 응답 시간은 기한에 넣지 않는다
  function schedule(): void {
    if (!pending.value || scheduled) return;
    scheduled = true;
    deadline = Date.now() + (opts.maxWaitMs ?? RESTORE_MAX_WAIT_MS);
    void nextTick(() => {
      if (pending.value) frame = requestAnimationFrame(tryAlign);
    });
  }

  onMounted(() => {
    if (!pending.value) {
      // 자리는 있었지만 모양이 틀렸다(손으로 고친 주소 등) — scrollToTop 이 Nuxt 의 스크롤을 껐으니 맨 위에서 시작한다
      if (given !== null) {
        window.scrollTo({ top: 0, left: 0, behavior: "instant" });
        dropSpot();
      }
      return;
    }
    // Nuxt 가 맞추지 않으므로(scrollToTop) 내용을 기다리는 동안은 맨 위에 둔다
    window.scrollTo({ top: 0, left: 0, behavior: "instant" });
    listen();
    watch(
      ready,
      (ok) => {
        if (ok) schedule();
      },
      { immediate: true },
    );
  });

  // 화면을 떠난 뒤 늦게 도는 프레임·타이머가 새 화면의 주소·스크롤을 건드리지 않게
  onBeforeUnmount(() => {
    disposed = true;
    pending.value = false;
    cancelFrames();
    unlisten();
  });

  return { pending, anchor };
}

/**
 * 상세로 떠날 때 이 화면 주소에도 자리(at·y)를 실어 둔다 — 상세의 [돌아가기]가 router.back() 을 고르거나
 * 브라우저 뒤로 가기로 돌아와도 그 기록의 주소에 맞출 자리가 남아 있다
 */
export function useDetailLeave(): { leave: (url: string, spot: ReturnSpot) => Promise<void> } {
  const route = useRoute();
  const router = useRouter();

  async function leave(url: string, spot: ReturnSpot): Promise<void> {
    await router.replace({ query: withSpot(route.query, spot) });
    await navigateTo(url);
  }

  return { leave };
}

// 오른쪽 버튼(auxclick)·메뉴(contextmenu)에서도 실어 두면 메뉴의 "새 탭에서 열기"도 같은 자리를 받는다 — 메뉴가
// auxclick 보다 먼저 뜨는 브라우저가 있다
export function stampExcludedLink(e: MouseEvent, job: string, cnts: string): void {
```

### 2.13 `components/research/CitationChip.vue` — [논문 상세]가 출처와 자리를 싣고 떠난다

**책임.** 인용칩과 그 팝오버(round04b). 이 라운드는 칩 버튼에 `data-anchor` 를 달고, 팝오버의 [논문 상세]가 출처(`from=research&job&e`)와 자리를 싣고 떠나게 한다.

- **`NuxtLink` 대신 `<a>` 와 직접 이동.** 주소에 **누르는 순간의** 칩 높이(`y`)를 실어야 한다. `NuxtLink` 의 `to` 는 미리 정해진다.
- **높이는 링크가 아니라 칩의 높이다**(`spotOf(chip.value!, props.anchor)`). 돌아와서 맞출 요소는 칩이다 — 팝오버의 링크는 초점이 옮겨 가면 사라진다.
- **세 이벤트.** `click`(수식 키 없는 왼쪽 클릭이면 `preventDefault` 하고 `leave`), `auxclick`(가운데 버튼 — 새 탭)과 `contextmenu`(메뉴의 "새 탭에서 열기")는 `href` 만 자리를 실은 주소로 바꿔 브라우저에 맡긴다. `contextmenu` 를 먼저 가르는 것은, 키보드의 메뉴 키로 연 메뉴는 왼쪽 클릭 모양(button 0)이라 `isPlainClick` 으로는 구별되지 않아서다.
- **처음 `href` 는 `detailHref(cnts, null)`** — 높이 없이 앵커만 실은 주소다. 스크립트 없이 따라가도 출처는 맞다.
- **잡 id 는 `inject(REPORT_JOB)!`** — 이 칩은 보고서(`ReportView`) 안에서만 쓰인다. 절·본문 부품을 거치지 않고 받는다(01 §2.1).

### 2.14 `components/research/ReportView.vue` · `ProgressPanel.vue` — 제외 논문 링크·앵커·펼치기

**책임.** 보고서의 접힌 "관련성이 낮아 제외한 논문 (N)" 목록과 탐색 타임라인 회차의 "무관 N편 제외 ▾" 목록(round04c)의 링크에 출처·앵커를 달고, 돌아왔을 때 그 항목이 든 목록을 펼친다.

- **링크** — `excludedDetailUrl(job, cnts)`(`e` 없음, `at=x-<cnts>`)를 `href` 로, `data-anchor="x-<cnts>"` 를 달고, `click`·`auxclick`·`contextmenu` 에서 `stampExcludedLink` 로 높이를 싣는다. 새 창이라 이 화면은 그대로다.
- **`revealExcluded` prop** — 화면(§2.15)이 "맞추는 중이고 앵커가 제외 항목이면 그 논문 id" 를 넘긴다. 접힌 목록 안의 항목은 높이가 없어 맞출 수 없으므로(§2.10 ④) 펼쳐야 자리가 생긴다. `ReportView` 는 그 논문이 든 제외 목록을, `ProgressPanel` 은 그 논문을 뺀 **회차를 모두** 펼친다.
- **목록이 바뀔 때도 다시 본다**(`watch([revealExcluded, 목록], …, { immediate: true })`). 초안이 같은 자리에서 최종본으로 바뀌면 목록이 바뀌고, 타임라인은 이벤트를 다시 받으며 늦게 채워진다.
- **맞추는 동안만** — 맞추고 나면 화면이 `revealExcluded` 를 `null` 로 돌려 사용자가 다시 접은 목록을 또 펼치지 않는다.
- **`REPORT_JOB` provide** — `ReportView` 가 `jobId` prop 을 받아 칩까지 내린다.

**알려진 한계**(spec §10). 같은 논문이 보고서 목록과 타임라인 회차마다 있어 `x-<cnts>` 가 여럿이다. 보이는 첫 요소를 고르므로 DOM 순서상 본문 열의 보고서 쪽에 맞춘다. 배치 A 의 타임라인(옆 열)은 자체 스크롤이라 창 스크롤로는 맞출 수 없다. 담는 곳별 앵커(`t-…`)는 다음 라운드다.

**책임.** 논문 검색 결과에서 카드를 눌러 상세로 가고, 돌아오면 그 카드가 든 쪽을 열어 같은 높이에 맞춘다. 이 diff 에는 ⑧의 초안 채우기(`fillResearchDraft`, 03 챕터 §2.19)와 DeepRead 이름(01 §2.6)도 있다.

## 면접 Q&A (02 — 보던 위치 복원)

**Q1. 왜 스크롤 픽셀이 아니라 "요소 앵커 + 그 요소의 화면 높이"인가? 목표 높이는 어떻게 정하나?**
A. 돌아온 화면의 문서 높이가 떠날 때와 다를 수 있어서다 — 배치 A/B, 창 크기, 초안 → 최종본, 위쪽 AI 요약의 길이가 모두 요소의 문서 위치를 바꾼다. 요소 기준이면 "그 요소의 지금 화면 위치 − 떠날 때의 화면 높이"만큼만 굴리면 되고(`scrollDelta`), 위에서 무엇이 늘거나 줄었든 사용자 눈에는 같은 자리다. 목표 높이는 떠날 때의 `y` 그대로이고, 창이 줄어 그 높이가 화면 밖이면 요소가 48px 은 보이게 당기며, 높이를 모르면(새 창 링크를 높이 없이 연 경우) 위쪽 1/3 이다. 요소를 못 찾으면 오류 없이 맨 위다. 같은 앵커가 여럿이면 보이는 첫 요소를 고른다 — 접힌 사본은 높이가 없다. (§2.9·§2.10)

**Q2. 언제 재나? 왜 `ready` 뒤에 `nextTick` → `requestAnimationFrame` 인가? Nuxt 의 스크롤은 어떻게 껐나?**
A. "내용이 그려질 준비"는 화면만 안다 — 보고서는 잡을 읽고 보고서 자리가 정해졌을 때, 검색 결과는 기록을 복원하고 로딩이 끝났을 때. 그래서 composable 은 `ready` 를 받는다. 준비가 되면 `nextTick` 으로 Vue 가 DOM 을 고치기를 기다리고, `requestAnimationFrame` 으로 그 프레임의 배치가 끝난 뒤 잰다. 같은 틱에 제외 목록을 펼치는 것 같은 변화도 반영된다. 요소가 아직 없으면 100ms 마다 다시 찾되, 기한은 준비된 때부터 센다 — 느린 응답 시간이 기한을 먹지 않게. Nuxt 는 기본으로 페이지 로딩이 끝난 다음 프레임에 맨 위나 저장 위치로 굴리는데, 이것이 우리의 맞추기와 경합한다. 그래서 쓰는 페이지가 `definePageMeta({ scrollToTop })` 에서 자리가 있으면(주소나 state) 거짓을 돌려 끈다. 끈 만큼 화면이 직접 맨 위로 올려 기다린다. (§2.10)

**Q3. 맞춘 뒤 왜 주소에서 `at`·`y` 를 지우나? 그런데 왜 `history.state` 에는 남기나? 지울 때 왜 `null` 로 두나?**
A. 주소에 남기면 새로고침·링크 복사·즐겨찾기에 옛 자리가 따라가, 한참 읽다가 새로고침하면 처음 누른 칩으로 끌려간다. 그래서 맞춘 뒤 `router.replace` 로 뗀다. 그런데 떼기만 하면 한 번 돌아온 뒤 상세로 **앞으로** 갔다 다시 돌아올 때 자리를 잃는다 — 상세 기록의 `state.back` 은 처음 주소를 들고 있어 `router.back()` 은 오지만 도착한 기록의 주소는 이미 깨끗하다. 그래서 같은 `replace` 에서 그 기록의 state 에 `skxSpot` 으로 남긴다. state 는 그 기록에만 붙고 주소에 보이지 않으며 새 탭으로 복사되지 않는다. 사용자가 움직이면 지운다 — 그 뒤로는 그 요소가 읽던 자리가 아니다. 지울 때 열쇠를 빼지 않고 `null` 로 두는 것은 vue-router 때문이다. `push` 는 떠나는 기록을 자기가 쥔 state 사본 위에 지금 `history.state` 를 덮어 다시 적는데, 열쇠를 빼면 덮을 값이 없어 사본의 옛 자리가 되살아난다. `replace` 에 조각만 넘기는 것도 같은 이유다 — 통째로 넘기면 옛 `current` 가 새 주소를 덮는다. (§2.9·§2.10)

**Q4. `useDetailLeave` 는 왜 이 화면 주소를 `replace` 한 다음에 상세로 `push` 하나?**
A. vue-router 는 `push` 할 때 새 기록의 `state.back` 에 그 순간의 위치를 적는다. 자리를 먼저 이 화면 주소에 실어 두면 상세 기록의 `back` 이 "자리를 실은 출처 주소"가 되고, 상세의 [돌아가기]가 `router.back()` 을 골라도, 사용자가 브라우저 뒤로 가기를 눌러도 도착한 기록의 주소에 맞출 자리가 있다. 상세 주소에도 같은 자리가 있으니 `shouldGoBack` 은 같은 화면인지만 보면 된다. 순서를 바꾸면(push 뒤 replace) 이미 떠난 화면을 고칠 수 없다. 새 창 링크는 반대로 이 화면을 고치지 않는다 — 이 화면은 그 탭에 그대로 남으므로 새 창 주소에만 높이를 싣는다(`stampExcludedLink`). (§2.10)

**Q5. 붙잡기(hold)는 왜 필요하고, 언제 멈추나? 사용자 움직임은 어떻게 가리나?**
A. 맞춘 순간 뒤에도 위쪽 내용이 바뀌기 때문이다. 요약이 끝나기 전에 떠난 검색 기록은 돌아오면 AI 요약을 다시 받아 요약 칸이 자라고 끝에 인용 논문을 맨 위로 올리고, 작성 중 보고서는 초안 절이 올라오며 나타난다. 그래서 맞춘 뒤 매 프레임 그 요소의 위치를 재 1px 이상 밀리면 되돌린다. 멈추는 때는 셋 — 15초가 지났을 때(요약 스트림이 걸리는 만큼), 요소가 사라졌을 때, 사용자가 움직였을 때. 움직임은 `wheel`·`touchstart`·`keydown`·`pointerdown` 을 캡처로 듣고 `isUserMove` 로 가린다. `scroll` 은 듣지 않는다 — 우리가 굴린 것도 `scroll` 을 낸다. 움직임에서 빼는 것도 있다. 마우스 옆 버튼·Alt+화살표·F5 같은 뒤로·앞으로·새로고침 손짓은 화면 안에서 자리를 옮기려는 것이 아니고, 움직임으로 치면 떠나는 순간 자리를 지워 다음에 돌아올 때 잃는다. 휠은 세로가 앞설 때만 움직임이다 — 트랙패드로 뒤로 간 뒤의 가로 관성 휠이 돌아온 화면에 떨어진다. (§2.9·§2.10)

**Q6. 왜 `behavior: "instant"` 인가? "자동 스크롤로 끌고 가지 않는다"는 원칙과 어떻게 맞나?**
A. 원칙이 막는 것은 사용자가 읽는 동안 화면을 굴려 데려가는 것이다. 복원은 사용자가 보기 전에 한 번에 자리를 옮기는 것이라 다르다 — 돌아온 화면은 처음부터 그 자리에서 보인다. 그래서 즉시여야 한다. spec §4 는 `behavior: 'auto'` 라 적었지만 `auto` 는 "CSS 의 `scroll-behavior` 를 따른다"는 뜻이라 페이지에 `scroll-behavior: smooth` 가 붙으면 부드럽게 굴러간다. `instant` 는 CSS 와 상관없이 즉시다(plan Task 3, 계획 검토에서 까닭을 적었다). 그리고 사용자가 먼저 움직이면 맞추지 않고, 맞춘 뒤 움직이면 붙잡기를 멈춘다 — 읽기 시작한 화면은 끌고 가지 않는다. 검색 결과의 쪽 바꿈은 원래 부드럽게 맨 위로 올리는데, 복원 중에는 그것도 멈춘다. (§2.10·§2.16)

**Q7. 검색 결과 둘째 쪽에서 누른 카드는 어떻게 그 자리로 돌아오나?**
A. 세 가지가 맞물린다. (1) 기록에 그 카드가 있어야 한다 — 논문 기록 축약을 20편에서 바이트 예산(180KB)으로 바꿔 최대 60편을 모두 담는다(01 §2.7). (2) 그 카드가 든 쪽을 연다 — 기록을 적용할 때 정렬·필터를 정한 뒤 화면 목록 순서에서 `pageOfItem` 으로 쪽을 찾는다. 정렬·필터 전에 찾으면 다른 순서라 틀린 쪽을 연다. (3) 쪽을 여는 동안 쪽 바꿈의 맨 위 이동을 멈추고, 목록이 한 번에 그려지므로 첫 프레임에 카드가 없으면 기다리지 않는다(`maxWaitMs: 0`). 이 셋은 Task 5 품질 검토가 찾았다 — 처음 구현은 21번째 이후 카드에서 2초를 기다린 뒤 첫 쪽 맨 위에서 끝나고 목록도 20편으로 줄었다. 화면 확인에서 둘째 쪽 카드 왕복과 재검색 없음을 봤다. (§2.16)
