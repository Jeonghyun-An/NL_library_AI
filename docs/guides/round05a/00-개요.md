## 0. 사용자 프롬프트 (paraphrase)

> 논문 상세를 다시 구현하기로 했는데 아직 안 됐다. 딥리서치를 넣으면서 뒤로 가기와 주소가 꼬였다. 상세에서 돌아갈 때는 딥리서치 화면에서 **보던 위치까지 그대로** 돌아가기로 했었다. A안(돌아가기·주소·위치 복원 먼저, 같은 라운드에서 03 화면 나머지와 원문 뷰어까지)으로 진행한다.

기준은 UI 고도화 기능 명세서의 **03 논문 상세**(와이어 ①~⑧)와 **S6 끊기지 않는 근거 동선**이다. 2026-10-01 운영 API 에 붙인 로컬 화면(round04c 가 더한 미리보기 `frontend-prod-api`)으로 지금 동작을 재현해 문제 일곱 개를 짚었고(§1-1), 사용자가 A안을 골랐다. dev `3dfeb45`(round04c 머지)에서 `feat/round05a-paper-detail` 을 따서 2026-10-01~02 에 22커밋을 쌓았고, 2026-10-02 사용자 승인으로 dev 에 머지했다(`f293e0e` — round07b 머지 `5fa1a38` 위의 `--no-ff`, 충돌 없음).

즉 **재현 → 설계(D1~D9) → 계획(13 태스크, 코드 블록을 사본에 기계적으로 적용해 검증) → 태스크별 구현·spec 검토·품질 검토 → 최종 검토(3영역) → 화면 확인(일부) → dev 머지** 순서로 이어진 라운드다. **백엔드는 바꾸지 않았다**(D9) — 배너는 기존 `GET /api/research/{id}`, 원문 확인은 기존 `GET /api/books/{id}/pdf` 를 쓴다. 배포 대상은 `nl-lib-nuxt` 하나다.

### 1-2. 핵심 결정

| 결정 | 버린 대안 | 이유 |
|---|---|---|
| **출처를 상세 주소에 싣는다**(`from=search`+`h`·`q` / `from=research`+`job`·`e`) | "어디서 왔나"를 sessionStorage·전역 상태에 둔다 | 새 탭·새로고침·링크 복사에도 주소만으로 돌아갈 곳·사이드바·배너·AI 요약 기준이 정해진다. round04b 의 "주소가 정본" 원칙을 상세까지 넓힌 것이다 (Q2) |
| **연관 논문으로 넘어가도 처음 출처와 자리를 잇고 `e`·`score` 만 뗀다** | 직전 논문을 새 출처로 | 몇 편을 넘겨 봐도 [돌아가기]는 처음 화면의 그 자리로 간다. 직전 논문은 브라우저 뒤로 가기가 맡는다 (01 Q5) |
| **돌아가기 = 직전 기록이 그 출처면 `router.back()`, 아니면 그 출처 주소로 `router.push`** | 늘 `back` / 늘 `push` | `back` 만이면 새 탭·직접 진입에서 갈 곳이 없고, `push` 만이면 기록이 한 칸씩 쌓이고 브라우저가 쥔 그 기록의 상태를 못 쓴다 (01 Q2) |
| **보던 위치 = 누른 요소의 앵커 `at` + 그 요소의 화면 높이 `y`** | 페이지 스크롤 픽셀 | 배치(A/B)·창 크기·초안→최종본으로 문서 높이가 바뀌어도 같은 요소를 같은 높이에 둔다 (Q3·02 Q1) |
| **즉시 이동(`behavior: "instant"`)**, 사용자가 먼저 움직이면 맞추지 않는다 | 부드럽게 굴려 데려가기 | "자동 스크롤로 끌고 가지 않는다"(plan 화면 규칙). spec 의 `'auto'` 는 CSS `scroll-behavior: smooth` 가 붙으면 굴러간다 (02 Q6) |
| **맞춘 뒤 주소에서 `at`·`y` 를 지우고 그 기록의 `history.state.skxSpot` 에 남긴다** | 주소에 남긴다 / 지우기만 한다 | 새로고침·링크 복사에 옛 자리가 따라가지 않되, 상세로 앞으로 갔다 다시 돌아와도 같은 요소로 온다 (02 Q3) |
| **맞춘 뒤 사용자가 움직이기 전까지(최대 15초) 그 요소를 붙잡는다** | 한 번 맞추고 끝 | 돌아온 검색 결과가 AI 요약을 다시 받아 펼치거나 초안 절이 올라오면 맞춘 요소가 밀린다 (02 Q5) |
| **AI 글은 sessionStorage 캐시, 키 = 논문 + 기준 질문, `[DONE]` 까지 받은 글만, 서버의 실패 문구는 빼고** | 받는 대로 저장 / localStorage | 끊긴 글·실패 문구가 탭을 닫을 때까지 다시 보이지 않게. 문제는 "오갈 때 재생성"이라 탭 범위면 된다 (03 Q1) |
| **원문 보기는 늘 원문 뷰어, KCI 는 보조 링크, 열기 전 확인은 `usePdfOpener` 하나** | `paper.url` 이 있으면 외부로 | S6-4. 확인 없이 열면 pdf.js 의 영문 오류 화면이 뜬다 (03 Q6) |
| **pdf.js 보안 설정 — `isEvalSupported=false`·`externalLinkTarget=BLANK`·`disablePreferences=true`** | 지금 pdf.js 를 올린다 | 고정본 4.0.379 가 CVE-2024-4367 범위이고 뷰어가 앱과 같은 출처다. 업그레이드는 다음 라운드 (03 Q3) |
| **순수 로직은 `utils/`, 화면 접착은 composable 둘, 페이지·컴포넌트는 부르기만** | 컴포넌트 마운트 도구(`@vue/test-utils`·DOM 환경) 추가 | 의존성 추가 금지, Vitest 는 `environment: "node"` 다. 판단을 함수로 빼면 node 에서 경계값까지 시험된다 (Q4) |
| **백엔드 변경 없음**(D9) | 배너 전용 API | 배포가 `nl-lib-nuxt` 하나로 끝난다 (Q5) |

### 1-3. 주소가 오가는 길

```text
보고서 /research/<job>
  인용칩 data-anchor="c-<절>-<E#>[-n]" ─[논문 상세]─▶ useDetailLeave.leave(url, spot)
      ① router.replace(이 화면 주소 + at·y)   ② navigateTo(상세 주소)
        ▼
상세 /papers/<cnts>?from=research&job=<job>&e=<E#>&at=c-…&y=<px>
  배너·AI 요약 기준 = 그 보고서(GET /api/research/<job>) · 사이드바 = 딥리서치 탭·그 보고서
  연관 논문 ─▶ /papers/<other>?from=research&job=<job>&at=c-…&y=<px>      (e 만 뗀다)
  [딥리서치 보고서로] ─ shouldGoBack(history.state.back, /research/<job>?at=&y=)
      ├ 직전 기록이 그 보고서 → router.back()   (그 기록의 주소에 ①의 at·y 가 있다)
      └ 아니면(새 탭·연관 논문을 거침) → router.push(/research/<job>?at=&y=)
        ▼
보고서 /research/<job>?at=c-…&y=<px>   (scrollToTop: false — Nuxt 는 맞추지 않는다)
  useRestorePosition: 맨 위에서 기다림 → ready(최종본·초안이 그려짐) → nextTick → rAF
    → 보이는 그 칩을 높이 y 에 즉시 맞춤 → 칩에 초점(팝오버가 다시 열림)
    → router.replace(at·y 를 뗀 주소, state.skxSpot = 자리) → 사용자가 움직일 때까지 붙잡기(≤15초)

검색 결과 /papers?h=&q=   카드 data-anchor="p-<cnts>" ─ 같은 길, from=search&h=&q=(&score=)
  돌아오면 기록(h)으로 재검색 없이 복원 → 그 카드가 든 쪽을 열고(pageOfItem) → 같은 높이
제외 논문 링크 data-anchor="x-<cnts>" ─ 새 창. 누르는 순간 href 에 y 를 싣는다(stampExcludedLink)
```

### 1-4. 상세 주소의 쿼리 (spec §3)

| 키 | 출처 | 뜻 |
|---|---|---|
| `from` | 공통 | `search` \| `research`. 없으면 출처 없음 — 다만 `h`·`q` 가 있으면 검색 출처로 읽는다(옛 상세 주소 `?q=&h=`) |
| `h`, `q` | search | 기록 id, **결과의** 검색어(입력창 글자가 아니다). round04b 규칙 그대로 |
| `job` | research | 딥리서치 잡 id |
| `e` | research | 인용 근거 번호(E#) — 배너용. 연관 논문으로 넘어가면 뗀다 |
| `at`, `y` | 공통 | 돌아가서 맞출 요소의 앵커와 떠날 때 그 요소의 화면 높이(px, 0 이상 정수). 출처 주소로 그대로 넘긴다 |
| `score` | search | 관련도(기존). 연관 논문으로 넘어가면 뗀다 |
| `chat` | 공통 | `1` 이면 DeepRead 열기(기존) |

- `4e8ea36` 위치 복원 — ① 한 번 돌아와 맞춘 뒤 상세로 **앞으로** 갔다 다시 [돌아가기]·뒤로 가기를 하면 맨 위에 섰다(주소에서 자리를 지웠으니) → 자리를 그 기록의 `history.state` 에 남긴다. ② 요약이 끝나기 전에 떠난 검색 기록은 돌아오면 AI 요약을 다시 받아 카드가 밀렸다 → 맞춘 뒤 붙잡기. ③ 모양이 틀린 `at`(손으로 고친 주소 등)이면 Nuxt 의 맨 위 이동만 꺼진 채 직전 화면의 스크롤 높이에서 시작했고 주소에도 남았다 → 맨 위에서 시작하고 자리를 뗀다. ④ 트랙패드 가로 스와이프(뒤로 가기)의 관성 휠이 맞추기를 취소했다. ⑤ 오른쪽 클릭 메뉴의 "새 탭에서 열기"에 자리가 실리지 않았다. ⑥ 화면을 떠난 뒤 늦게 도는 프레임이 새 화면 주소를 건드릴 수 있었다(02 챕터 §2.10 "리뷰에서 바뀐 점").

### 3-4. 화면 확인 (2026-10-02, worktree 의 dev 서버를 운영 API 에 붙여)

미리보기 도구는 저장소 루트의 `.claude/launch.json` 으로 루트의 `frontend/` 를 띄운다. 그래서 라운드 worktree 의 `frontend/` 에서 `NUXT_DEV_API_TARGET=<운영 API 주소> npx nuxi dev --port 3005` 를 따로 띄우고 그 주소에 붙였다.

- **확인한 것** — 검색 결과 둘째 쪽 카드 → 상세 → [검색 결과로] 왕복이 재검색 없이 그 카드 자리로 오는 것, 앞으로 갔다 다시 돌아와도 같은 자리, 원문 뷰어(쪽 표시·Esc·초점 되돌리기·배경 `inert`·보안 설정), `?draft` 초안 채우기.
- **보지 못한 것** — 보고서 인용칩 왕복(spec §7 ①~④·⑪). 미리보기 브라우저에 딥리서치 기록이 없었다. **배포 뒤 운영 화면에서 확인한다.**

### 3-5. 배포

spec §9 — `nl-lib-nuxt` 이미지 빌드·푸시 → 서버 pull → Recreate(Portainer re-pull 끔) → `docker exec nl-lib-gateway nginx -s reload`(함정 20번 — Recreate 로 바뀐 컨테이너 IP 를 게이트웨이가 다시 풀게). 백엔드·워커는 이 라운드 몫이 없다. 공유 운영 서버라 배포는 사용자가 직접 한다.

**주의 — `frontend/public/pdfjs` 는 `.gitignore` 대상이다.** pdf.js 고정본(4.0.379)은 저장소에 없고 작업 폴더에만 있다. 새로 만든 worktree 에는 없으므로, 원문 뷰어가 든 이미지를 만들려면 이 폴더가 있는 작업 트리에서 빌드해야 한다 — 없는 폴더에서 빌드하면 운영 원문 뷰어가 깨진다. spec §10 의 "같은 저장소의 고정 버전(`public/pdfjs`)"은 git 에 든 것이 아니라 작업 트리에 둔 고정본이다.

### 3-6. 남은 한계와 다음 과제

- **제외 논문 앵커 중복**(spec §10) — 같은 논문이 보고서의 제외 목록과 탐색 타임라인(뺀 회차마다)에 함께 있어 `x-<cnts>` 가 여럿이다. DOM 순서상 보고서 쪽 항목에 맞추고, 펼칠 때 그 논문이 든 회차를 모두 펼친다. 배치 A 의 타임라인은 자체 스크롤이라 창 스크롤로는 맞출 수 없다. 담는 곳별 앵커(`t-…`)는 다음 라운드.
- **pdf.js 업그레이드** — 보안 설정은 SKOVIX 가 끼운 뷰어에서만 걸린다. iframe 없이 `/pdfjs/web/viewer.html?file=` 을 주소로 바로 열면 `webviewerloaded` 를 들을 부모가 없다. 근본 해결은 `public/pdfjs` 를 4.2.67 이상으로 올리는 것이다.
- **보고서 인용칩 왕복의 운영 화면 확인 대기**(§3-4).
- **도서 상세 미적용**(spec §8) — 같은 문제가 03-1 도서 상세에 있다.
- **메인 화면 논문 탭에서 온 상세** — 출처는 `from=search&q=`(h 없음)라 [검색 결과로]가 논문 검색 화면에서 같은 검색어로 다시 찾고, 메인 화면은 `useRestorePosition` 을 쓰지 않아 카드 자리는 맞추지 않는다(§2.6). 브라우저 뒤로 가기는 메인 화면으로 돌아간다.

## 4. 면접식 Q&A (라운드 전체)

챕터별 질문은 각 챕터 끝에 있다. 여기는 라운드를 가로지르는 질문이다.

**Q1. 이 라운드는 무엇을 고쳤고, 문제를 어떻게 찾았나?**
A. 운영 API 에 붙인 로컬 화면으로 사용자가 겪는 흐름을 하나씩 밟아 증상과 원인 코드를 짝지었다(spec §1, §1-1 표). 보고서의 인용칩에서 연 상세가 주소에 출처를 싣지 않아 돌아가기 문구·사이드바·탭 제목이 모두 틀렸고, 연관 논문으로 넘어가면 출처가 지워졌으며, 새 탭으로 연 상세는 `$router.back()` 이라 갈 곳이 없었다. 돌아온 화면이 맨 위에서 시작하는 것은 보고서·기록을 비동기로 다시 그려 브라우저의 스크롤 복원이 내용보다 먼저 끝나서였다. 그래서 **주소 규칙**(01)·**위치 복원**(02)을 먼저 하고, 같은 라운드에서 03 화면 나머지와 원문 뷰어(03)를 했다(A안). 증상 표를 원인 코드에 맞춰 두면 고친 뒤 무엇을 다시 볼지(spec §7 화면 확인 ①~⑪)도 함께 정해진다. (§1-1)

**Q2. 왜 "어디서 왔나"를 주소에 싣나? 상태 저장소에 두면 더 간단하지 않나?**
A. 상태 저장소의 값은 그 탭의 그 세션에만 있다. 보고서의 "제외한 논문" 링크는 새 창으로 열고, 사용자는 상세를 새로고침하거나 링크를 복사해 보낸다. 그때도 돌아갈 곳·사이드바 강조·인용 배너·AI 요약 기준이 같아야 하는데, 이 넷이 모두 출처 하나에서 나온다. 주소에 실으면 `readDetailSource(route.query)` 한 번으로 정해지고, 순수 함수라 테스트도 쉽다. round04b 가 기록 복원에 세운 "주소가 정본" 원칙(`?h=&q=`)을 상세까지 넓힌 것이다. 대가는 주소가 길어지는 것인데, 출처 화면 쪽의 `at`·`y` 는 맞춘 뒤 지우고, 상세 주소의 출처 쿼리는 새 탭·새로고침에 필요해서 남긴다(spec §10). 주소는 사용자가 고칠 수 있는 입력이라 읽을 때 모양을 검사해 틀리면 버린다. (01 §2.1)

**Q3. 보던 위치를 왜 스크롤 픽셀이 아니라 요소로 복원하나?**
A. 돌아온 화면의 문서 높이가 떠날 때와 같다는 보장이 없다. 딥리서치 화면은 단계에 따라 배치가 A(2단)/B(문서형)로 바뀌고, 창 크기가 다를 수 있으며, 작성 중 초안이 최종본으로 바뀌면 서론·한계가 붙어 아래가 밀린다. 픽셀로 돌아가면 다른 문단에 선다. 그래서 떠날 때 **누른 요소의 앵커와 그 요소의 화면 높이**를 싣고, 돌아와서는 그 요소를 찾아 같은 화면 높이에 오도록 차이만큼 굴린다. 사용자 눈에는 "누른 칩이 눌렀던 그 높이에 있다"가 되고, 인용칩이면 초점까지 돌려 팝오버가 다시 열린다. 요소가 없으면(보고서를 다시 만들었거나 결과가 바뀜) 오류 없이 맨 위에 둔다. (02 §2.9·§2.10)

**Q4. 컴포넌트 테스트 없이 어떻게 검증했나? 왜 순수 함수로 뺐나?**
A. 이 프로젝트의 Vitest 는 `environment: "node"` 이고 컴포넌트 마운트 도구가 없으며, plan 은 의존성 추가를 막았다. 그래서 판단을 모두 DOM 없는 함수로 뺐다 — 주소 읽기·쓰기, 뒤로 갈지, 앵커 문법, 굴릴 양·목표 높이·복원 단계, 사용자 움직임 판정, `history.state` 조각, 캐시에 담을지, 인용 대목 순서, Esc 를 누구에게 맡길지, 초점 되돌릴 곳, 확인 요청의 제한 시간. 테스트는 이 함수들의 경계값을 본다(예: `c-01-E3` 거부, `y=12.5` 거부, 관성 휠 `deltaX -60, deltaY 4` 는 움직임 아님, 연 버튼이 사라졌으면 칩으로). DOM 이 필요한 것은 최소한으로 흉내 냈다(`pdfViewer.test` 의 `isConnected`·`matches`·`querySelector` 만 가진 가짜 노드). 컴포넌트·페이지는 그 함수를 부르기만 하고 `nuxi typecheck`·`npm run build` 로 본다. 그래도 남는 것 — 실제 브라우저의 스크롤·초점·iframe — 은 화면 확인(§3-4)이 방어선이다. (§1-2, §3-1)

**Q5. 백엔드를 바꾸지 않은 결정의 득실은?**
A. 득은 배포·위험이다. 배포가 `nl-lib-nuxt` 하나로 끝나고, 공유 운영 서버에서 워커·API·DB 를 건드리지 않는다. 필요한 데이터는 이미 있었다 — 배너는 `GET /api/research/{id}` 의 `report.evidence[e]`(대목·쪽·서지), 원문 확인은 `GET /api/books/{id}/pdf` 의 상태 코드. 문제는 화면이 그 응답을 쓰는 방식이었다. 대가도 있다. 배너 하나를 위해 보고서 전체를 받는다(큰 보고서면 느려 최종 검토에서 "불러오는 중"을 더했다). 열기 전 확인은 PDF 를 받기 시작한 뒤 끊는 방식이다(본문을 받지 않게 `abort`). 서버 쪽 경량 API 는 데이터가 쌓여 느려지면 다음에 검토할 일이다. (03 §2.20·§2.22)

**Q6. 단위 테스트가 모두 통과했는데 최종 검토에서 무엇이 나왔나? 거기서 배운 것은?**
A. 흐름에서만 보이는 결함들이었다. 한 번 돌아와 맞춘 뒤 상세로 **앞으로** 갔다 다시 돌아오면 맨 위에 섰다 — 주소에서 자리를 지웠는데 상세 기록의 `history.state.back` 은 처음 주소를 들고 있어 `router.back()` 이 자리 없는 기록으로 왔다. 요약이 끝나기 전에 떠난 검색 기록은 돌아오면 요약을 다시 받아 맞춘 카드가 밀렸다. 출처를 싣기 전의 옛 주소는 돌아가기와 사이드바가 어긋났다. 고정본 pdf.js 는 알려진 취약점 범위였다. 각각 함수 단위로는 맞았지만 **앞으로/뒤로·비동기 스트림·옛 데이터·외부 의존성**이라는 경계를 밟지 않았다. 고칠 때는 다시 함수로 내려 테스트를 더했다(`spotFromState`·`holdDelta`·`isUserMove`·옛 주소·`hardenPdfViewerOptions`, +14건). 교훈은 "테스트가 통과한다"와 "사용자 흐름이 맞다"가 다른 질문이라는 것, 그리고 흐름 검토에서 찾은 결함도 판단을 함수로 빼면 회귀 테스트로 묶을 수 있다는 것이다. (§3-3)

**Q7. 이 라운드에서 남긴 것은?**
A. (1) **확인** — 보고서 인용칩 왕복(①~④·⑪)의 운영 화면 확인. (2) **알려진 한계** — 제외 논문 앵커 중복(담는 곳별 앵커는 다음), 배치 A 타임라인의 자체 스크롤, 메인 화면 논문 탭에서 온 상세의 자리 미복원. (3) **보안** — pdf.js 4.2.67 이상 업그레이드(지금 설정은 끼운 뷰어에서만 걸린다). (4) **범위 밖** — 도서 상세의 같은 문제, 대목 위치 강조·pdf.js 도구 줄 정리. 백엔드·DB 는 바꾸지 않았다. (§3-6)
