# 소장자료 검색 — 재작성이 제목을 지워 그 책을 놓치던 것 (2026-10-23)

사용자 보고: 소장자료에서 '구운몽'을 검색하면 운영에 적재된 `WS_014 구운몽`(literature, is_embedded)이 목록에 없고, 1위가
『The Queen's Necklace』와 유토피아 설명이었다.

## 원인

소장자료 검색(`POST /api/books/search`, 화면은 top_k 10·재작성 켬)은 질의를 gemma 로 재작성한 문장 **하나로만** 후보를
찾는다(`services/search/pipeline.py` — `search_query = rewritten`). 재작성 프롬프트(`query_rewrite.yaml`)는 "특정 도서를 직접
찾는 경우에만 제목·저자를 포함"하라고 하지만, 제목만 넣은 질의를 gemma 3 은 주제어로 바꾼다(temperature 0 이라 늘 같다).

| 질의 | 재작성 |
|---|---|
| 구운몽 | 요몽, 이상향, 유토피아, 꿈, 방랑, 선비, 현실 비판, 풍류, 자유 |
| 태평천하 | 번영하는 시대, 평화로운 사회, 이상적인 국가, 유토피아 … (원작은 풍자소설) |
| 동백꽃 | 봄, 생명, 아름다움, 덧없음, 자연, 한국, 시, 서정성 … |

제목 일치 점수(`title_scorer.apply_title_scores`)는 찾은 후보의 순서만 바꾸므로 후보에 못 든 책은 살리지 못한다. top_k 를
15 이상으로 넓히면(후보 45권) 구운몽이 겨우 후보에 들어 제목 점수로 1위가 된다 — 처음 API 로 확인했을 때 1위로 보인 까닭.

같이 찾은 것: 제목 정규화가 한글·영숫자만 남겨 한자가 많은 제목이 `'1930年代 世態小說 硏究' → '1930'`, `'韓國 四時歌의 硏究'
→ '의'` 로 줄었다. '1930' 이 든 질의(재작성 포함)마다 '질의 안에 제목 전체 포함'으로 제목 일치 1.0 이 됐다.

## 견준 방식 (운영 API 응답으로 그대로 다시 만듦 — `simulate.py`)

질의마다 운영 API 를 화면과 같은 인자로 재작성 켬·끔 두 번 불렀다(`fetch.py`, 104질의 — search_history 에 화면에 안 보이는
고정 세션 id 로 208줄을 남겼다). 응답의 content_score(제목 보정 전 내용 점수)로 방식을 다시 만든다.

- **CUR** 지금 — 재작성 질의로만 찾는다.
- **A** 원래 질의로도 같은 조건(도서 필터·후보 수)으로 찾아 합친다. 갈래마다 자기 질의로 재정렬하고, 같은 책이면 내용 점수가
  높은 쪽. 제목 일치는 [원래, 재작성] 으로 지금처럼.
- **C** CUR 에 원래 질의 갈래의 책 중 제목 일치(원래 질의 기준) 0.5 이상만 더한다.
- **AH0** A + 제목 정규화가 한자를 남긴다(첫 커밋 60b81d2b — 판정 묶음은 CUR·A·AH0 의 상위 10권).
- **AH** A + 지금 구현의 제목 일치 — 한자를 남기고 NFKC(호환 한자 → 통합 한자)를 걸고, 한자를 뺀 꼴이 제목 길이의 절반 이상
  남으면 그 꼴로도 견준다. 코드 리뷰가 AH0 이 "'월인천강지곡(月印千江之曲)' 연구"처럼 한글 제목에 한자를 덧붙인 꼴의 한글 질의
  완전 일치를 깎는 것(1.0 → 0.6)을 찾아 고쳤다.

CUR·A·C·AH0 의 제목 일치는 고치기 전 사본(`title_scorer_before.py`)으로 계산한다 — 다시 돌려도 표가 같게.

끔 응답이 도서 필터 0건이라 API 가 전체(논문)로 다시 찾은 경우가 있어(올리버 트위스트) 원래 질의 갈래의 논문은 뺐다 — 구현의
원래 질의 갈래는 도서 필터 안에서 찾는다. 두 갈래가 모두 0건이면 API 가 필터 없이 다시 찾는데(이때는 두 갈래 모두 논문까지),
'올리버 트위스트'는 켬 응답도 전부 KCI 논문이었다 — 이 폴백은 '구버전 인덱스 대비'가 아니라 운영에서 실제로 도는 경로다(따로 볼 것).

### 제목·저자 질의 (자동 — 그 책이 1위인가)

| 질의 묶음 | CUR | A | C | AH0 | AH |
|---|---|---|---|---|---|
| 한국 문학 제목 41 (WS_·GM_ 전부) | 10/41 (목록에 있음 10) | **41/41** | 41/41 | 41/41 | **41/41** |
| 영어 원서의 한국어 제목 20 | 8/20 (목록 15) | **16/20** | 8/20 | 16/20 | **16/20** |
| 영어 제목 10 | 9/10 | 10/10 | 10/10 | 10/10 | 10/10 |
| 제목이 든 문장 8 ('구운몽 줄거리가 궁금해' 등) | 3/8 | 7/8 | 5/8 | 8/8 | **8/8** |
| 저자 5 ('김유정 소설' — 그 저자 책이 1위) | 1/5 | 4/5 | 1/5 | 4/5 | 4/5 |

평균 후보 수는 약 30 → 40~52권. AH(·AH0)가 A 보다 나은 1건은 '김유정의 동백꽃' — 정규화 버그로 '1930年代 世態小說 硏究'·
'1930年代 韓國 心理小說 硏究' 가 제목 1.0 을 받아 동백꽃을 3위로 밀었다. 남은 실패: 레 미제라블·위대한 유산·올리버 트위스트
(영어 원서에 한국어 제목이 어디에도 없다 — 카탈로그 title_remainder·keyword 에 한국어 제목을 넣으면 풀릴 것), 앨리스 3위.

### 주제·유사 질의 (판정 — 상위 10권의 관련도)

질의 20개(랜딩 도서 예시 3 · 주제 13 · 'X 같은 책' 4)의 CUR·A·AH0 상위 10권을 합쳐 섞은 묶음(`judge/`, 159권)을 판정자 셋
(사서·이용자·시연 심사 관점, 방식을 모름)이 0·1·2 로 매겼다(`judge_result.json`, 집계 `tally.py` → `judge_tally.json`).
AH 의 상위 10권도 200칸 모두 판정된 책이었다.

| 질의당 평균 | CUR | A | AH0 | AH |
|---|---|---|---|---|
| 상위 10 관련도 합 (0~20) | 7.28 | **7.80** | 7.75 | **7.80** |
| 상위 3 합 | 2.52 | **3.18** | **3.18** | **3.18** |
| 1위 (0~2, 화면의 'SKOVIX 추천 1권') | 0.98 | **1.28** | **1.28** | **1.28** |
| nDCG@10 | 0.621 | **0.721** | 0.719 | **0.721** |
| 상위 10 중 무관 | 4.60 | 4.40 | 4.45 | 4.40 |

평균으로는 주제 질의도 나아졌다(소녀의 성장 이야기 2.3 → 8.0, 판소리계 소설 1.0 → 4.0, 동백꽃 같은 소설 1.0 → 2.7). 크게
떨어진 질의는 '가난한 시대를 그린 한국 소설' 8.3 → 4.3 — 짧은 원래 질의로 재정렬한 점수가 재작성 질의로 재정렬한 점수보다
대체로 높아(0.70 대 0.55) 원래 질의에 글자로만 맞는 국문학 학위논문('韓國 女性文學 硏究' 등)이 위로 올라왔다.

그래서 더 본 것(판정 범위 안 — 200/200 칸이 판정된 책):
- 원래 질의 갈래 점수에 0.9·0.85·0.8·0.7 을 곱해 합치기 — 주제 질의 상위 10 합은 7.9~8.0 으로 조금 오르지만 1위·상위 3·nDCG
  는 그대로이거나 떨어지고, 0.85 부터 저자 질의가 4/5 → 1/5, 0.7 이면 한국어 제목 16 → 11. 곱하지 않는다.
- 두 갈래에 모두 나온 책은 재작성 갈래 점수만 쓰기(재정렬을 한 번 줄임) — 한국어 제목 16 → 9, 주제 nDCG 0.625. 갈래마다 끝까지
  재정렬한다.

## 결론과 구현

**AH 로 고친다** — `include_original`(소장자료 검색 API 만 켬, 상황별 추천 등 다른 도서 검색은 그대로), 제목 일치에 한자·NFKC·
한자를 뺀 꼴. `app/tests/test_book_search_original_query.py`(병합 양방향·재작성 갈래 0건·날짜 정렬의 pub_date·서지 한 번 읽기 —
잘못 짠 구현 넷을 각각 잡는지 확인했다). 비용은 임베딩 한 번(두 질의를 한 배치로)·Milvus 검색 한 번·재정렬 약 30권이 더 든다
— 이 실험의 서버 응답 시간 중앙값은 켬 1.49초·끔 1.32초였다. 서지는 책마다 읽던 것을 한 번(IN)으로 바꿨다. 배포 뒤 응답 시간을
다시 잰다.

알고 둘 것:
- 제목 일치가 바뀌는 곳은 소장자료 검색만이 아니다 — 논문 검색(`api/paper.py`)·관련 자료(`api/book.py` related)도 같은 함수다.
  관련 자료는 '…에 나타난 …' 학위논문들이 서로 '에나타난' 으로 줄어 제목 1.0 을 받던 것이 사라진다(좋아짐). 한자가 대부분인
  제목을 한글 독음으로 친 질의('한국 전후소설의 휴머니즘 연구' → '韓國 戰後小說의 휴머니즘 硏究')는 남은 한글 조각이 우연히
  들어맞아 1.0 이던 것이 0.33 이 된다 — 같은 조각이 다른 질의에도 1.0 을 주던 규칙이라 되살리지 않는다(독음 변환이 필요).
- 'X 같은 책' 질의에서 X 자신이 1위('SKOVIX 추천 1권')가 될 수 있다 — '동백꽃 같은 소설'의 AH 1위가 동백꽃(제목 0.5). 판정자는
  관련으로 매겼지만 사용자가 원하는 것은 다른 책일 수 있다 — 제품 판단.
- 날짜 정렬 질의('최근 …')는 후보가 top_k×4×2 로 늘어 pub_date 만으로 top_k 를 고른다 — 이 실험은 날짜 질의를 보지 않았다.
- 화면 주석(`frontend/pages/index.vue` — 'top_k 10 이어도 16~30권')은 이제 40~50권이다(프론트 세션).
