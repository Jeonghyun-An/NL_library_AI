> **한 줄 결론** — 지금 프롬프트(A·B·C 어느 것)로는 도서 카드에 넣지 않는다. 넣으려면 **B 를 바탕으로** ①시스템·사용자 프롬프트 전체에서 '논문'·'초록' 낱말을 걷어내고 ②한쪽에만 있는 내용을 '두 자료 모두'로 씌우지 못하게 고친 뒤, ③**국문학 학위논문(literature) 짝에만** 보이고 **재정 보고서(policy) 짝과 본문이 빈 자료는 사유를 숨겨(지금의 'AI 요약' 유지)** 다시 시험해 정한다.

**한눈에** (엄 = 엄격 판정자 / 독 = 독자 판정자, 같으면 한 값)

| | A | A′ | B | C |
|---|---|---|---|---|
| 그대로 낼 만함 (12쌍) | 3 | 4 / 5 | 4 / 6 | 1 |
| 화면에 뜨는 9쌍 중 | 2 | 2 / 3 | 1 / 3 | 0 |
| 근거 맞음 (12쌍) | 5 / 6 | 6 / 9 | 5 / 8 | 3 / 5 |
| 형식 맞음 (12쌍) | 8 | 8 | 8 | 6 |
| 재정 보고서 4쌍 형식 | 0 | 0 | 0 | 0 |
| 밋밋함 평균 (0~2) | 0.83 | 0.92 / 0.75 | 0.67 | 0.50 / 0.58 |

- **밋밋함은 걱정보다 덜하다** — 대부분 주제 수준(1점)이고 빈말(2점)은 쌍 4 의 A·A′ 두 건뿐.
- **문제는 지어냄인데, 빈 본문 탓이 아니다** — 15권 모두 본문(summary)이 있었다. 틀린 문장 대부분은 한쪽에만 있는 내용을 '두 논문 모두'로 씌운 **교차 귀속**이다.
- **C(구체 항목 강제)가 가장 위험** — 덜 밋밋하지만 한쪽의 작품·인물 이름을 공통점으로 끌어오고 시기까지 바꿨다.
- **A 와 B 는 내용 품질이 사실상 같다** — 근거 맞음 차이(엄 5→5, 독 6→8)가 같은 프롬프트를 다시 돌린 A→A′ 차이(엄 5→6, 독 6→9) 안쪽이다. B 를 바탕으로 삼는 이유는 호칭('해당 자료는')뿐이고, 프롬프트 나머지의 '논문'을 그대로 둬서 그마저 반쪽이다.
- B·C 도 실제로 돌렸다(운영과 같은 vLLM 에 직접). 네 변형 48문장 모두 정상 종료 — 서버에서 따로 돌릴 명령은 없다.

판정 칸은 **밋밋·근거·형식** 순. 두 판정자가 다르면 `엄 …/독 …` 로 둘 다 적었다.

- 밋밋 0 = 공통 항목을 이름으로 짚음(틀려도 0) · 1 = 주제 수준 · 2 = 아무 짝에나 붙는 빈말
- 근거 X = 한쪽에만 있는 내용을 두 자료 공통으로 씌우거나 발췌와 어긋남
- 형식 X = 평문 카드에 그대로 못 냄: 정책 보고서를 '논문'이라 부름, '원본/연관 논문' 노출, `**` 마크다운, 비문, 요약 틀말('규율 대상' 등)
- 국문학 짝은 실제 학위논문이라 '논문' 호칭만으로는 X 로 치지 않았다(두 판정자 같음). 일반도서였다면 A 는 틀린 호칭
- **그대로 낼 만함** = 근거 O · 형식 O · 밋밋 ≤ 1
- 엄격 판정자는 발췌와 낱말 단위로 대조, 독자 판정자는 심사위원·이용자 눈높이로 따로 매겼다

## 본문이 빈 자료

| 필드 | 채워진 자료 (15권 중) | 비고 |
|---|---|---|
| abstract | 0 | 모두 비어 있음 |
| summary | 15 | 544~1175자, 적재 때 LLM 이 만든 요약. 서버가 15권 모두 이것을 골라 400자에서 문장 중간에 자름 |
| introduction | 15 | 사서 소개글('안녕하세요, 도서관을 찾아주신…' 말투) |
| 셋 다 빈 자료 | 0 | → '초록 없음'으로 나간 문장 0건 |

- **본문이 빈 자료에서 지어내는지는 이번 표본으로 시험되지 않았다**(C 의 '초록 없음이면 제목만' 분기도 미시험).
- 대신 본문이 있어도 지어냈다. 근거 X 문장 수(엄 / 독): A 7 / 6, A′(재생성) 6 / 3, B 7 / 4, C 9 / 7. 거의 전부가 한쪽에만 있는 내용을 '두 논문 모두'로 씌운 교차 귀속이다.
  - C 쌍 3: 우화소설 쪽에만 있는 '\<노섬상좌기\>' 등 작품명을 두 논문 모두 언급한다고 씀
  - C 쌍 10·11: 원본에만 있는 梁柱東·김억·박영희, 연관에만 있는 萬海를 공통 분석으로 씀
  - C 쌍 12: 본문의 '개화기' 신소설을 '1920년대 신소설'로 바꿈
  - A 쌍 3 · C 쌍 1: 원본에만 있는 '예술계의 변화'를 두 논문 공통으로 씀
- 본문 자체가 AI 요약의 앞 400자라, 사유는 원문이 아니라 'AI 요약끼리의 비교'다. summary 가 비면 서버는 사서 소개글(introduction)로 넘어가는데 그 경우도 시험되지 않았다.
- 다음 시험용으로 본문 빈 소장자료 수를 세는 읽기 쿼리(이번엔 실행 안 함):

```sql
SELECT doc_type,
       count(*) FILTER (WHERE coalesce(btrim(abstract),'')='' AND coalesce(btrim(summary),'')='') AS no_abs_no_summary,
       count(*) FILTER (WHERE coalesce(btrim(abstract),'')='' AND coalesce(btrim(summary),'')=''
                          AND coalesce(btrim(introduction),'')='') AS body_empty,
       count(*) AS total
FROM library_catalog WHERE is_embedded AND doc_type <> 'paper' GROUP BY doc_type;
```

## 구현한다면 필요한 것

**서버**

- 엔드포인트는 이미 도서 ID 로도 돈다(A 가 그 경로로 12/12 성공 — `BookRepository.get_by_cnts_id` 공용). 도서용 프롬프트 분기만 더하면 된다.
- 도서용 프롬프트: 시스템·사용자 메시지 **양쪽 모두**에서 '논문'·'초록'·'원본/연관'을 빼고('자료 1/자료 2', '내용 요약') '해당 자료는 ~ 한 내용이 유사합니다.' 한 문장으로.
- 교차 귀속 막기: 자료별로 따로 말하게 하거나(B 쌍 4 처럼 '세태소설의 경우 …, 초기 소설의 경우 …'), 생성 뒤 공통이라 쓴 고유명사가 두 발췌에 모두 있는지 검사해 실패하면 숨긴다.
- 본문 없음: abstract·summary 가 둘 다 비면 LLM 을 부르지 않고 빈 응답 → 카드는 지금의 AI 요약/'요약 정보가 없습니다.' 유지.
- doc_type=policy 짝은 사유를 내지 않는다(두 판정자 모두 형식 0/4).
- `_clean_excerpt` 가 `## …` 머리와 `**` 를 지우게(경제백서 1999 요약에 남아 있음), 출력에서도 `**` 제거.
- 비용: 논문 상세는 로드 때 관련 4건을 한꺼번에 스트리밍한다. 도서도 같으면 상세 1회에 LLM 4호출이 적재·검색과 같은 GPU 에 더해진다.

**프론트** (`frontend/pages/books/[cnts_id].vue`)

- 관련 카드 상자는 지금 'AI 요약' 하나다. 사유를 넣으면 요약과 사유 중 무엇을 상자에 둘지 기획 결정이 필요하다(논문 화면은 'AI 추천 사유' + 팝업 'AI 추천 사유 & 유사점 분석').
- 논문 화면의 `streamRelatedReason`(sessionStorage 캐시·로딩 표시)을 그대로 옮기고, 사유가 비면 AI 요약으로 대신한다.
- 별건: 질의 1 처럼 관련 자료 검색(1위 제목으로 검색)이 1권만 주는 경우가 있다 — 비교 사유보다 먼저 손볼 일.

## 시험 방식

- **코드 머지·저장소 수정 없음.** 저장소(.worktrees/fix-live)는 읽기만 했고, 변형 프롬프트는 시험 스크립트 안에서만 만들었다.
- **운영 서버(:92)에는 읽기성 호출만**: 상세 `GET /api/books/{id}` 15권, `POST /api/books/search` 7회, `POST /api/papers/related-reason/stream` 12회(A). 단, 검색 API 는 서버가 호출마다 search_history 에 한 줄씩 남긴다(7줄, x-session-id=trial-book-related-20261013) — 피할 수 없는 기록이다.
- A′·B·C 36문장은 운영 fastapi 가 쓰는 같은 vLLM(gemma-3-12b, :18080)에 직접 보냈다. 모두 정상 종료(200토큰에 안 잘림), 호출당 0.7~1.8초.
- 호출은 순차로, 사이마다 1초 쉬었다. 연구 생성·승인·삭제·DB 쓰기·컨테이너 조작은 하지 않았다.
- 표본 한계: 짝 12개(국문학 8 · 재정 4), 쌍마다 1회 생성. 질의 1 의 쌍 2~4 는 화면에 안 나오는 보충 짝.
