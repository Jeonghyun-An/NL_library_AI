# 연구 공백(gap) 절 프롬프트 A/B (2026-10-15)

이어가기 보고서의 연구 공백 절 프롬프트 `app/domains/nl_library/prompts/research_section_gap.yaml` 을 운영 연구 9건의 같은 절
입력으로 다시 써서 견준 1회성 실험이다. 운영 DB 에는 쓰지 않았고 운영 API 에는 GET 만 보냈다. 다시 쓰기는 운영과 같은
vLLM(gemma-3-12b, temperature 0.3)에 직접 보냈다.

**결론 — 프롬프트를 바꾸지 않는다(현재본 유지).** 해석 문장에도 [E#] 를 붙이게 한 A(cite)는 문장 단위 충실도가 두 회차 모두
나았지만, 2차에서 남의 논문 내용을 다른 논문 번호로 단 문장(W)이 3 → 12 로 늘었고 순위 판정은 현재본을 골랐다(1위 16 대 3).
판정자들은 현재본이 연결 해석을 인용 없이 두는 것('정직한 다리')을, 그 해석을 남의 논문 탓으로 돌리는 것보다 낫다고 봤다.
화면은 근거 표시 없는 문장에 점선 밑줄을 긋고 머리 줄·Word 부록에 수를 공개하므로, 현재본의 근거 없는 연결 문장은 숨은
오류가 아니다. 문단 짜임까지 시킨 B(frame)는 1차에서 크게 졌고(꼴찌 23/27), 제목 풀이를 막은 A2(cite2)는 A 보다 나빴다.

## 왜

공공도서관 이어가기 E2E(911d9583, 2026-10-15)의 공백 절이 두 번 생성해 두 번 다 '…에 관한 연구 [E1]에 따르면' + 근거 표시
없는 '이는 …시사한다' 문장 6~7개였다(기존 예시 c816c7b2 는 1개). 카드 주제(복합문화공간)와 공백 근거 논문(평가체계·성과평가·
독서유효성)이 어긋나 모델이 연결 문장으로 잇는 것으로 보였다. 프롬프트로 연결 문장에도 근거를 달게 할지 겨뤘다.

## 방법

- `fetch_inputs.py` — 운영 GET(연구·계획서·주제·담기 목록·절 근거)으로 절 입력을 다시 맞추고 저장소의 `gap_seeds`·`gap_input`
  을 그대로 부른다. 9건 모두 다시 만든 논문 번호(E#)가 저장된 공백 절의 evidence 지도와 같았다(`inputs/*.json` 의 `same_papers`).
- `run_ab.py` — 절 생성 코드(`section._build`·`_parse`·`_bind`·`_check`)를 그대로 쓰고 프롬프트만 바꾼다. 생성기처럼 형식·인용이
  맞지 않으면 세 번까지 다시 부른다(이번엔 다시 부른 일이 없다). 연구 9건 × 변형 3 × 3회 = 81호출, 두 회차.
- `make_judge.py` — 연구마다 출력 9개에 가린 라벨(L1~L9)과 문장 번호를 붙인다. 열쇠(`judge_key.json`·`judge_r2_key.json`)는
  판정자에게 주지 않았다.
- 판정(LLM 에이전트, 워크플로) — 연구마다 ① 감사: 모든 문장을 S(근거와 맞음)·W(다른 논문 내용)·M(인용한 논문이 말하지 않은
  내용 — 덧붙인 결과·대상·해석·제언)·U_ok(연구 질문·씨앗 되받기)·U_claim(인용 없는 주장)·F(어디에도 없는 사실)로 ② 검증:
  걸린 문장을 다른 에이전트가 반박 쪽에서 다시 봄(뒤집힌 것은 그 판정을 쓴다) ③ 순위: 같은 회차 세 출력을 공백 절로서
  줄 세움(충실도 > 공백 진술 > 규칙 > 군말). 결과 `judge_r1_result.json`·`judge_r2_result.json`.

| 변형 | 파일 | 바꾼 것 |
|---|---|---|
| base | `base.yaml` | 지금 저장소 프롬프트(바이트 단위로 같다) |
| cite (A) | `variant_cite.yaml` | 연결 해석·제언 문장도 기대는 근거의 [E#] 를 붙이고 받칠 수 없는 해석은 쓰지 않기, 제목 대신 '선행연구는 … [E1]', [E#] 는 마침표 앞 |
| frame (B) | `variant_frame.yaml` | A + 문단 짜임 '근거가 다룬 것 → 남긴 한계·공백 후보 → 연구 질문과 닿는 곳'(모두 [E#]) |
| cite2 (A2) | `variant_cite2.yaml` | A 에서 제목 문구만 — '…에 관한 연구는' 같은 제목 풀이 대신 '선행연구는'·'한 선행연구는' |

- cite 의 이득은 연구마다 고르지 않다 — 20ddd3b9·c816c7b2·911d9583 에서는 크게 낫고, 06123d9d·660ff17e·630e0d65 에서는 인용
  없는 연결 문장을 '인용한 논문이 말하지 않은 해석'(M)으로 바꿔 놓았다(`tally_perjob.py` 가 결과 JSON 의 perJob 으로 연구별로 센다).
- 넘친 숫자는 대부분 근거에 있는 연대('1990년대 후반'·'2010년 이후')·나이('5세경')다.
- 어느 변형이든 문장의 약 3분의 1이 인용한 논문보다 나아간다(M). 공백 절은 근거를 연구 질문에 잇는 자리라 모델이 해석을 덧붙인다
  — 프롬프트 한 줄로 줄지 않았다. 화면이 근거 대목을 함께 보이는 것(인용칩 팝오버)이 지금의 방어선이다.

## 한계

- 판정자는 사람이 아닌 LLM 에이전트다(감사 1 + 검증 1 + 순위 1, 연구마다). 같은 출력을 두 번 판정하지 않았다 — 회차마다 새 출력이다.
- 연구 9건 중 다수가 노인 우울·다문화 아동·공공도서관 세 주제에 몰려 있다.
- 입력은 운영 GET 으로 다시 맞춘 것이다(논문 번호·대목·초록은 저장된 절과 같음을 확인, 제목·연도는 담기 목록의 서지).
