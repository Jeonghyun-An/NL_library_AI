## 이 챕터의 자리

spec §14 다. §1~13 을 운영에 올린 뒤(2026-09-28) 사용자가 요청했다 — 보고서를 쓰는 동안(화면에 "보고서 작성 중 2/5" 만 뜨는 구간) 보여 주는 게 부족해 기다리기 지루하다. 종합은 절 하나에 LLM 호출 1회(round04a 실측: GPU 가 한가할 때 절당 약 6초)지만 운영에서는 vLLM 을 적재 요약과 나눠 써 절마다 수십 초씩 늘어난다(spec §14-0 배경).

**결정(E1·E2) — 다 쓴 절부터 보고서 자리에 바로 보여 주고, 그 절은 최종본과 같은 코드로 다듬은 절이다.** 진행 표시만 늘리는 안은 끝까지 읽을 것이 없고, 토큰 스트리밍은 모델이 JSON 으로 답해 중간 글을 풀기 어렵고 인용 검증 전 글이 보였다 바뀐다.

같은 시기 기획자 시연 피드백(spec §7-4) — 배치 A(우측 패널에 과정)는 "덜 인터랙티브해 보인다" — 에서 사용자는 **인터랙티브함이 매우 중요하다**는 방침을 세웠다. 그래서 이 챕터의 화면은 진행이 눈에 보이는 움직임(이어 늘어나는 막대·1초마다 가는 경과·튀어 오르는 체크), 눌러서 옮겨 가는 요소(현황 카드 → 초안의 절), 실시간 갱신을 먼저 두되, `prefers-reduced-motion` 을 존중하고 자동 스크롤로 읽는 사람을 끌고 가지 않는다.

## 2. 구현 (클론코딩)

### 2.35 `services/research/synthesizer.py` — 절 단위 처리 분리와 진행 콜백

**책임.** 세 가지를 더했다. ① `assemble_report` 의 절 루프 본문을 `finalize_section(state, sec) → (절, SectionTally)` 로 떼었다. ② 그 절이 인용한 근거만 `report.evidence` 와 같은 모양으로 만드는 `section_evidence`. ③ `synthesize` 의 `on_section(idx, total, status, info)` 콜백. 그리고 [03](03-딥리서치-이벤트.md) 의 보고서 `stats`(`research_stats`).

**왜 이렇게 짰나.**

- **출력은 한 글자도 바뀌지 않는다.** `assemble_report` 는 절마다 `finalize_section` 을 부르고 집계를 더할 뿐이다. 기존 보고서 테스트가 그대로 통과해야 했고, 새 테스트(`test_section_equals_the_assembled_report_section`)가 같은 입력에서 `finalize_section` 의 절과 `assemble_report` 의 절이 같음을 묶는다 — 초안에서 읽은 글과 완성본의 글이 갈리지 않는다(spec §14-9 의 첫 위험).
- **집계는 dataclass 하나(`SectionTally`).** 무표기·삭제·미파싱·요약 누락·도입 없음·실패 절 수. `add` 는 칸을 손으로 나열하지 않고 `fields()` 로 돈다 — 칸을 더하고 여기서 빠뜨리면 한계 문장이 조용히 준다.
- **근거 모양은 한 함수가 만든다(`_evidence_entry`)**(`680c728`, §14 다듬기). 완성본 근거(`_serialize_evidence`)와 절 미리보기 근거(`section_evidence`)가 같은 dict 모양(`{cnts_id, meta, 점수순 chunks}`)을 각자 만들면 한쪽만 바뀌어 초안·완성본의 인용칩 팝오버가 조용히 갈린다.
- **`section_evidence` 는 그 절이 인용한 근거·대목만.** 근거 전체를 절마다 실으면 절이 쌓일수록 같은 대목을 거듭 나른다. 도입의 마커는 `bind_markers` 의 `used` 로 읽는다 — 정규식을 여기서 다시 쓰면 마커 문법이 두 곳으로 갈라진다.
- **`idx` 는 절 순번이지 하위질문 번호가 아니다.** 근거 없는 하위질문은 절이 되지 않아 둘이 어긋나고, 화면의 "2/3" 은 절 순번으로 센다. `info` 에 `subq_idx` 를 따로 싣는다.
- **첫 절을 쓰는 동안에도 남은 절 이름을 안다(`headings`).** 쓸 절 전부의 소제목을 절 순서로 싣는다 — 화면이 남은 절을 "작성 대기"로 미리 그린다.
- **서술을 받지 못한 절(`failed`)도 싣는다.** 최종본처럼 논문 목록만 있는 절이다.
- **콜백은 인자 수를 타입에 못박지 않는다(`SectionFn = Callable[..., Awaitable[None]]`).** 워커의 콜백은 `info` 를 선택 인자로 받는다 — `info` 없는 옛 호출과 호환.

### 2.36 워커 `_SynthProgress` — 절 미리보기를 나르고 쌓고 닫기

**책임.** `synthesize` 의 `on_section` 콜백 객체. 절 진행을 `synth` 이벤트로 흘리면서 종합 단계 `result` 에 남길 값을 모은다 — 실패·취소로 끝나도 거기까지의 진행이 남는다. 코드는 [03](03-딥리서치-이벤트.md) §2.26 의 워커 diff 에 들어 있고, 아래는 그 부분과 종합 블록만 다시 발췌했다.

**왜 이렇게 짰나.**

- **절 내용은 `synth` 이벤트가 절마다 한 번만 나른다.** 진행 저장(`_save_progress`)은 저장 뒤 단계 result 를 `step` 이벤트로 알리는데, 종합 단계에서는 절이 쌓일수록 매번 전부를 다시 보내게 된다. 그래서 저장에는 미리보기를 싣고(새로고침·재접속한 화면이 단계 result 에서 이미 쓴 절을 되살린다), **알리는 `step` 에서는 뺀다**(`event_result=self.result(previews=False)`). 화면은 가벼운 `step` 이 이미 받은 절 내용을 지우지 않게 합친다(§2.37).
- **소요 시간은 워커가 단조 시계로 잰다.** 벽시계는 시각 보정으로 뒤로 갈 수 있다. 화면 시계와 무관한 값이라 남은 시간 추정(§2.38)의 평균이 브라우저 시계 차이에 흔들리지 않는다. 시작 시각(`started_at`)은 ISO(UTC) 로 따로 싣는다 — 쓰는 중인 절의 경과는 화면이 이것과 자기 시계를 견준다.
- **근거 합집합은 대목을 `chunk_id` 로 합친다(`_merge_evidence`).** 한 논문이 두 절에 실리면 절마다 제 대목만 가져온다. 덮어쓰면 앞 절 인용칩의 대목이 사라진다. 들고 있던 값을 고치지 않고 새 dict 로 바꿔 넣는다 — 앞서 넘긴 result 가 뒤따라 바뀌지 않게.
- **닫는 규칙.**
  - **완료로 닫으면 미리보기를 지운다** — 최종 보고서(`research_jobs.report`)와 같은 내용이다. 완료 뒤 새로 연 화면은 보고서를 바로 받으므로 초안이 필요 없다.
  - **실패·취소로 닫으면 남긴다** — 멈춘 초안을 보여 주고 내려받는 원천이다.
  - **완료 경로는 보고서를 먼저 저장(완료 전이)하고 단계를 닫는다**(`7a27287`, §14 다듬기). 처음엔 단계를 먼저 `done`(미리보기 없음)으로 닫고 전이를 했다. 그러면 전이가 취소에 질 때 초안을 되살리려 한 번 더 닫아야 하고(`done` 이 한 번 스친 뒤 `failed`), 그 사이 데드라인에 걸리면 보고서도 초안도 없이 남는다. 지금 순서에서는 전이와 닫기 사이에 끊겨도 보고서는 저장됐고 `_close_orphan_steps` 가 단계를 닫는다.
  - **전이가 지면 단계를 `failed`(초안 유지)로 한 번만 닫는다**(`05f23bf`, §14 Task 3 품질 검토). 대개 마지막 절을 쓰는 도중에 들어온 취소다 — `synthesize` 는 LLM 을 부르기 직전에만 멈춤을 본다.
  - **재시도가 완료되면 이전 시도의 멈춘 초안을 걷는다**(`6a6968d`, §14 다듬기). 화면은 최신 시도의 단계만 읽는데, 남겨 두면 완성된 보고서를 열 때마다 GET·스냅샷이 아무도 읽지 않는 수백 KB 를 더 나른다. 절 목록·시각·오류는 남기고, 실패해도 완료는 되돌리지 않고 경고만 남긴다. 무엇이 미리보기인지는 `_without_previews` 한 곳이 정한다(지금 시도의 가벼운 값도 같이 쓴다).
- **크기.** 절 하나에 수 KB~수십 KB(대목 원문이 대부분)다. 테스트 `test_six_sections_of_thirty_papers_stay_at_report_scale` 이 절 6개·논문 30편에서 최종 보고서의 `evidence` 와 같은 규모임을 본다.

```python
@dataclass
class _SynthProgress:
    """synthesize 의 on_section 콜백. 절 진행을 synth 이벤트로 흘리면서 종합 단계
    result 에 남길 값도 모은다 — 실패·취소로 끝나도 거기까지의 진행이 남는다.
    step 이 있으면 절이 바뀔 때마다 도는 중인 단계 result 에도 남긴다.

    보여 주고, 새로고침·재접속한 화면은 단계 result 에서 이미 쓴 절을 되살린다."""

    def _record(self, idx: int, status: str, info: dict) -> dict:

        self.headings = list(info.get("headings") or self.headings)

                 "headings": self.headings}

            return extra

        """끝난 절들의 근거를 합친다. 한 논문이 두 절에 실리면 절마다 제 대목만 가져오므로

def _without_previews(result: dict) -> dict:
    """종합 단계 result 에서 절 미리보기(sections[].section)와 근거(evidence)를 뺀 값.

    지금 시도의 가벼운 값(_SynthProgress.result)과 이전 시도의 정리(_drop_stale_previews)가 같이
    쓴다. 보강 전 잡의 sections 는 정수라(models/research.py) 목록일 때만 절마다 걷는다.
    """
    light = {k: v for k, v in result.items() if k != "evidence"}
    if isinstance(result.get("sections"), list):
        light["sections"] = [{k: v for k, v in s.items() if k != "section"}
                             for s in result["sections"]]
    return light


async def _drop_stale_previews(db: AsyncSession, step: _StepRef) -> None:
    """재시도가 완료되면 같은 잡의 이전 시도 종합 단계에 남은 멈춘 초안을 걷는다.

    실패·취소로 닫은 종합 단계는 멈춘 초안을 남긴다. 재시도가 완료하면 화면은 최신 시도의
    단계만 읽는데, 남겨 두면 완성된 보고서를 열 때마다 GET·스냅샷이 아무도 읽지 않는 수백 KB 를
    더 나른다. 실패는 경고만 남긴다 — 잡은 이미 완료로 끝났고 이것은 크기 정리다(시간 상한
    신호도 삼킨다 — 남은 일이 없다).
    """
    try:
        rows = (await db.execute(
            select(ResearchStep.id, ResearchStep.result).where(
                ResearchStep.job_id == step.job_id, ResearchStep.kind == "synthesize",
                ResearchStep.seq < step.seq,
            )
        )).all()
        for step_id, result in rows:
            light = _without_previews(result)
            if light != result:
                await db.execute(
                    update(ResearchStep).where(ResearchStep.id == step_id).values(result=light))
        await db.commit()
    except Exception:
        log.warning("[research] 이전 시도의 초안 정리 실패 job=%s", step.job_id, exc_info=True)
```

```python
            if not await _transition(db, jid, expect=("running",), status="completed",
                                     report=report, stage=_stage("synthesized"),

                # 대개 마지막 절을 쓰는 도중에 들어온 취소다(synthesize 는 LLM 을 부르기 직전에만
                # 멈춤을 본다). 보고서가 버려지므로 미리보기를 남겨 멈춘 초안으로 닫는다.
                await _finish(db, step, "failed", progress.result(error="취소됨"),

            await publish_terminal(jid, "completed")
            await _drop_stale_previews(db, step)
```

### 2.37 화면의 종합 합치기 — `researchEvents.ts` 의 종합 부분

**책임.** `synth` 이벤트와 종합 단계 result(스냅샷·GET·`step` 이벤트) 어느 쪽으로 와도 같은 `SynthView` 로 합친다. 전체 파일은 [03](03-딥리서치-이벤트.md) §2.29 에 있고, 아래는 종합 부분만 다시 발췌했다.

**왜 이렇게 짰나.**

- **없는 칸이 받은 칸을 지우지 않는다(`mergeSection`).** 상태는 더 나아간 쪽(`running` < `done`·`failed`), 나머지 칸은 들어온 값이 있을 때만 바꾼다 — 가벼운 `step` 이벤트·뒤처진 스냅샷이 이미 받은 절 내용·걸린 시간을 지우지 않게. 근거가 없는 값(가벼운 `step`)이면 받은 근거 객체를 그대로 둔다(`0aca68d`).
- **새 시도면 비운다(`sameAttempt`).** 재시도(`POST /retry`, `stage=explored`)는 새 종합 단계(새 `seq`)를 만든다 → 초안은 처음 절부터 다시 쌓인다.
- **재시도로 물러난 시도는 새 종합 단계가 열릴 때까지 읽지 않는다(`retiredSeq`)**(`ca764b0`, §14 다듬기). 워커는 `running` 을 알리고 스냅샷을 되살린 뒤에야 새 종합 단계를 연다. 그 사이 이전 시도의 닫힌 단계를 읽으면 멈춘 초안·진행률·남은 시간이 '작성 중'으로 잠깐 되살아난다. 재시도(끝난 잡이 다시 진행으로 바뀜)를 알아보면 종합 화면을 비우고 그 시도의 마지막 종합 단계 seq 를 기억한다. "실패한 종합 단계면 숨긴다"로 가르면 실패로 닫히는 길(단계 `failed` → 잡 `failed`)의 멈춘 초안까지 깜빡여 쓰지 않았다.
- **스냅샷과 구독 사이에 놓친 절 내용은 GET 으로 한 번 맞춘다(`sectionGapToRecover`)**(`4a3cb65`, §14 다듬기). 스트림은 스냅샷을 읽은 뒤에야 구독을 붙인다. 그 틈에 나간 `synth(done)` 의 절 내용은 그 세션에서 다시 받을 길이 없다 — 뒤따르는 `step` 은 절 내용을 싣지 않고, 하트비트는 상태·단계만 견준다. 그러면 현황 카드는 완료인데 초안·[초안 저장]에서 그 절이 빠진다. API 를 고치지 않고 화면에서 고쳤다 — 끝났다고 알려진 절에 내용이 없으면 저장본을 한 번 다시 읽는다. 열쇠(종합 단계 seq·절 번호)가 같으면 되풀이하지 않는다. 절 내용을 싣는 워커(절 제목 목록을 보낸다)가 종합 단계를 쓰는 동안만 본다 — 옛 워커의 절은 원래 내용이 없다.
- **취소 뒤 단계가 닫히기를 기다린다(`synthClosePending`)**(`cdf7b25`, §14 다듬기). 종합 중에 취소하면 API 는 곧바로 잡을 끝내지만 워커는 쓰던 절을 마저 쓰고서야 종합 단계를 닫는다. 그 절이 멈춘 초안과 [초안 저장] 파일에는 없고 다시 열어야 나타났다. 이 상태면 `useResearch` 가 단계가 닫힐 때까지 최대 6번 다시 읽는다([03](03-딥리서치-이벤트.md) §2.31). 실패는 워커가 단계를 먼저 닫고 잡을 끝내므로 해당하지 않는다.
- **옛 워커·옛 서버는 옛 동작으로 되돌아간다.** 새 칸이 없으면 `null` 로 남고 화면은 "보고서 작성 중 2/5" 로 그린다.

```ts
function mergeSections(base: SynthSectionView[], extra: SynthSectionView[]): SynthSectionView[] {
  const out = new Map(base.map((s) => [s.idx, s]));
  for (const s of extra) {
    const cur = out.get(s.idx);
    out.set(s.idx, cur ? mergeSection(cur, s) : s);
  }
  return [...out.values()].sort((a, b) => a.idx - b.idx);
}

    heading: s.heading ?? cur.heading,

    durationMs: s.durationMs ?? cur.durationMs,

// chunk_id 로 합집합하고, 보고서의 evidence(_serialize_evidence)처럼 점수순으로 둔다
export function mergeEvidence(
  a: Record<string, ReportEvidence>,
  b: Record<string, ReportEvidence>,
): Record<string, ReportEvidence> {
  const out: Record<string, ReportEvidence> = { ...a };
  for (const [eid, ev] of Object.entries(b)) {
    const cur = out[eid];
    if (!cur) {
      out[eid] = ev;
      continue;
    }
    const known = new Set(cur.chunks.map((c) => c.chunk_id));
    const chunks = [...cur.chunks, ...ev.chunks.filter((c) => !known.has(c.chunk_id))]
      .sort((x, y) => y.score - x.score);
    out[eid] = { ...cur, chunks };
  }
  return out;
}
```

### 2.38 `utils/researchDraft.ts` — 절 자리·초안·남은 시간

**책임.** 순수 함수 셋. `draftSlots(view)` — 현황 카드의 한 줄이자 초안의 절 자리. `draftReport(view)` — 끝난 절들을 절 순서대로 모아 `ResearchReport` 모양으로(절이 하나도 없으면 `null`). `synthEta(view, now)` — 끝난 수·전체·쓰는 중인 절의 경과·남은 시간.

**왜 이렇게 짰나.**

- **초안은 최종 보고서와 같은 모양이다.** `ReportView`·내보내기가 최종본과 같은 코드로 그린다. 한계는 보고서가 완성된 뒤에만 있으므로 비우고, `stats` 는 라이브 카운터다(셋 중 하나라도 비면 싣지 않는다 — 서론이 옛 문장으로 물러선다).
- **절 수는 워커가 알린 `total` 이 정본이다.** 모르면(옛 결과·첫 이벤트 전) 제목 목록·받은 절 번호로 센다. 제목은 절 제목 목록 → 이벤트의 제목 → 다듬은 절의 제목 → "절 N" 순으로 고른다.
- **멈춘 뒤의 "작성 중"은 대기로 본다.** 실패·취소로 멈춘 뒤에는 더 쓰이지 않는다 — 움직이는 줄·경과 시계를 띄우지 않게.
- **남은 시간 = 끝난 절들의 걸린 시간 평균 × 대기 절 수 + 쓰는 중인 절의 (평균 − 경과, 0 미만이면 0).** 걸린 시간은 워커가 잰 값이라 화면 시계와 무관하다. 경과만 화면 시계와 서버의 `started_at` 을 견주므로, 두 시계가 어긋나 `started_at` 이 미래로 보여도 음수가 되지 않게 자른다. 끝난 절이 없으면 `null` — "첫 절을 쓰는 중".
- **끝난 절은 있는데 남은 시간을 모르면 칸을 비운다**(`8b8a257`, §14 다듬기). 절마다 걸린 시간을 주지 않는 옛 워커다. 처음엔 "남은 시간 계산 중"이라 적었는데, 옛 워커는 절이 더 끝나도 남은 시간이 끝내 나오지 않아 끝까지 틀린 말이 된다.
- **1분이 넘는 추정은 10초 단위로 반올림한다.** 긴 추정을 초 단위로 적으면 매초 흔들려 읽기 어렵다.

```ts
// 작성 현황 카드의 한 줄이자 초안의 절 자리 하나. idx 는 워커의 section_idx(절 순번)와 같다

  idx: number;
  heading: string;
  status: DraftSlotStatus;
  durationMs: number | null;
  startedAt: string | null;
  // DraftReport.report.sections 안의 위치 — 내용을 받은 끝난 절에만 있다
  sectionIndex: number | null;
}

export interface DraftReport {
  report: ResearchReport;
  slots: DraftSlot[];
  done: number;
  total: number;
}

export interface SynthEta {
  done: number;
  total: number;
  runningIdx: number | null;
  runningElapsedMs: number | null;
  remainingMs: number | null;
}

export function draftSlots(view: ResearchView): DraftSlot[] {
  const byIdx = new Map(view.synth.sections.map((s) => [s.idx, s]));
  const stopped = isStopped(view);
  const count = slotCount(view);
  const slots: DraftSlot[] = [];
  let placed = 0;
  for (let idx = 0; idx < count; idx++) {
    const s = byIdx.get(idx);
    const finished = s?.status === "done" || s?.status === "failed";
    slots.push({
      idx,
      heading: slotHeading(view, idx, s),
      status: slotStatus(s, stopped),
      durationMs: s?.durationMs ?? null,
      startedAt: s?.startedAt ?? null,
      sectionIndex: finished && s?.section ? placed++ : null,
    });
  }
  return slots;
}

// 끝난 절을 절 순서대로 모아 최종 보고서와 같은 모양으로 만든다 — ReportView·내보내기가 최종본과
// 같은 코드로 그리게. 한계는 보고서가 완성된 뒤에만 있으므로 비워 둔다.
export function draftReport(view: ResearchView): DraftReport | null {
  const slots = draftSlots(view);
  const byIdx = new Map(view.synth.sections.map((s) => [s.idx, s.section]));
  const sections = slots
    .filter((slot) => slot.sectionIndex !== null)
    .map((slot) => byIdx.get(slot.idx))
    .filter((sec): sec is ReportSection => !!sec);
  if (!sections.length) return null;
  const stats = liveStats(view.counters);
  return {
    report: {
      question: view.question,
      range: null,
      sections,
      evidence: view.synth.evidence,
      trail: [],
      limitations: [],
      ...(stats ? { stats } : {}),
    },
    slots,
    done: sections.length,
    total: slots.length,
  };
}

// 남은 시간 = 끝난 절들의 걸린 시간 평균 × 대기 절 수 + 쓰는 중인 절의 (평균 − 경과, 0 미만이면 0).
// 걸린 시간은 워커가 잰 값이라 화면 시계와 무관하다. 경과만 화면 시계(nowMs)와 서버의 started_at 을
// 견주므로, 두 시계가 어긋나 started_at 이 미래로 보여도 음수가 되지 않게 자른다.
export function synthEta(view: ResearchView, nowMs: number): SynthEta {
  const slots = draftSlots(view);
  const finished = slots.filter((s) => s.status === "done" || s.status === "failed");
  const running = slots.find((s) => s.status === "running");
  const runningElapsedMs = running ? elapsedSince(running.startedAt, nowMs) : null;
  const durations = finished.map((s) => s.durationMs).filter((d): d is number => d !== null && d >= 0);
  let remainingMs: number | null = null;
  if (durations.length) {
    const avg = durations.reduce((sum, d) => sum + d, 0) / durations.length;
    const waiting = slots.filter((s) => s.status === "waiting").length;
    const current = running ? Math.max(0, avg - (runningElapsedMs ?? 0)) : 0;
    remainingMs = Math.round(avg * waiting + current);
  }
  return {
    done: finished.length,
    total: slots.length,
    runningIdx: running?.idx ?? null,
    runningElapsedMs,
    remainingMs,
  };
}

export function formatClock(ms: number): string {
  const total = Number.isFinite(ms) ? Math.max(0, Math.floor(ms / 1000)) : 0;
  return `${Math.floor(total / 60)}:${String(total % 60).padStart(2, "0")}`;
}

// 요약 줄의 남은 시간 칸. null 이면 칸을 비운다
export function formatRemaining(ms: number | null, done: number): string | null {
  if (done <= 0) return "첫 절을 쓰는 중";
  // 끝난 절은 있는데 남은 시간이 없다 = 절마다 걸린 시간을 주지 않는 옛 워커다. 절이 더 끝나도 끝내
  // 나오지 않으므로 "계산 중"이라 적으면 끝까지 틀린 말이 된다
  if (ms === null) return null;
  const sec = Math.round(Math.max(0, ms) / 1000);
  if (sec < 10) return "곧 끝납니다";
  if (sec < 60) return `약 ${sec}초 남음`;
  // 1분을 넘으면 초 자리를 10초 단위로 반올림한다 — 긴 추정을 초 단위로 적으면 매초 흔들려 읽기 어렵다
  const rounded = Math.round(sec / 10) * 10;
  const m = Math.floor(rounded / 60);
  const s = rounded % 60;
  return s ? `약 ${m}분 ${s}초 남음` : `약 ${m}분 남음`;
}

// 절 수는 워커가 알린 total 이 정본이다. 모르면(옛 결과·첫 이벤트 전) 제목 목록·받은 절 번호로 센다
function slotCount(view: ResearchView): number {
  const { total, headings, sections } = view.synth;
  const known = sections.reduce((n, s) => Math.max(n, s.idx + 1), 0);
  return Math.max(total, headings.length, known);
}

function slotHeading(view: ResearchView, idx: number, s: SynthSectionView | undefined): string {
  const named = [view.synth.headings[idx], s?.heading, s?.section?.heading].find((h) => h?.trim());
  return named?.trim() || `절 ${idx + 1}`;
}

function slotStatus(s: SynthSectionView | undefined, stopped: boolean): DraftSlotStatus {
  if (!s) return "waiting";
  // 실패·취소로 멈춘 뒤의 "작성 중"은 더 쓰이지 않는다 — 움직이는 줄·경과 시계를 띄우지 않게 대기로 본다
  if (s.status === "running" && stopped) return "waiting";
  return s.status;
}

function isStopped(view: ResearchView): boolean {
  return view.synth.status === "done" || view.synth.status === "failed" || isTerminalStatus(view.status);
}

// 보고서 서론 한 줄(reportIntro)이 읽는 stats — 라이브 카운터가 셋 다 있을 때만 싣는다.
// 하나라도 비면(옛 잡) 서론은 근거 수만 쓰는 옛 문장으로 되돌아간다
function liveStats(c: CountersView): CountersPayload | null {
  if (c.papersReviewed === null || c.evidenceAdopted === null || c.rechecks === null) return null;
  return { papers_reviewed: c.papersReviewed, evidence_adopted: c.evidenceAdopted, rechecks: c.rechecks };
}

function elapsedSince(startedAt: string | null, nowMs: number): number | null {
  if (!startedAt) return null;
  const t = Date.parse(startedAt);
  return Number.isNaN(t) ? null : Math.max(0, nowMs - t);
}
```

### 2.39 `utils/researchReport.ts` — 서론·초안의 때·빈자리 문구

**책임.** 보고서 화면과 내려받은 문서가 함께 쓰는 문장·판정. 수록 범위 라벨, 서론 한 줄, 빈자리 문구(`INTROLESS`·`NO_SUMMARY`·`NO_LIMITS`), 초안이 놓인 때(`draftStateFor` → `writing`·`finishing`·`interrupted`)와 그 배지·서론, 보고서 칸의 상태(`reportSlot`), 인용칩 팝오버의 대목 넘기기·닫기 판정.

**왜 이렇게 짰나.**

- **서론 문장은 모델이 아니라 화면이 만든다.** 수치를 모델에게 쓰게 하면 틀린 숫자가 실린다. 하위질문 수는 탐색 경로(`trail`)로 세는데, `trail` 은 종합이 끝나야 생기므로 초안은 탐색한 하위질문 수를 인자로 넘긴다(`9f9af0f`, §14 다듬기 — 처음엔 화면의 하위질문마다 `TrailItem` 을 지어내 넘겼다).
- **빈자리 문구는 상수 하나(`aef4049`, §14 다듬기).** 화면(절 본문·보고서)과 내려받은 문서가 같이 쓴다 — 한쪽만 고치면 문서가 화면과 다른 말을 한다.
- **완료 뒤에도 최종본을 받기 전에는 읽던 초안을 치우지 않는다(`finishing`)**(`89289b1`, §14 다듬기). 완료 이벤트에는 보고서가 없어 GET 으로 다시 받는다. 그 사이 초안 머리에 깜빡이는 '작성 중' 배지가 붙고 서론이 '다 쓴 절부터 먼저 보여 드립니다'로 남아, 머리는 완료인데 초안은 아직 쓰는 중이라고 말했다. 그래서 때를 셋으로 나눴다 — `finishing` 이면 점 없는 '작성을 마친 초안' 배지와 "모두 쓴 초안입니다" 서론(카운터는 최종 집계라 '지금까지'를 뗀다).
- **보고서 칸을 비우지 않는다(`reportSlot`)**(`f15f0ab`, 최종 리뷰 minor). 완료 뒤 보고서를 받는 동안은 불러오는 중, 실패해 다시 시도하는 중이면 [다시 불러오기]를 그린다. 본문 칼럼을 비우면 연구가 사라진 것처럼 보인다.
- **팝오버 대목 넘기기는 끝에서 제자리에 선다(`stepChunk`).** 버튼을 `disabled` 로 막으면 초점을 쥔 버튼이 비활성이 되는 순간 초점이 body 로 떨어져 팝오버가 닫힌다 — 화면은 `aria-disabled` 로 알리기만 하고 범위는 여기서 지킨다.

### 2.40 `utils/synthCard.ts` · `composables/useNow.ts` — 카드 문구·막대·강조와 화면 시계

**책임.** `synthCard.ts` 는 현황 카드의 요약 줄·항목 상태·막대 비율·포인터와 초점 강조·이번에 끝난 절·알림 문장을 순수 함수로. `useNow` 는 보고서를 쓰는 동안만 1초마다 도는 화면 시계.

**왜 이렇게 짰나.**

- **막대는 끊기지 않게 늘어난다(`barFraction`).** 절 하나가 수십 초라 끝날 때만 늘면 막대가 서 있는 것처럼 보인다. 쓰는 중인 절의 몫 = 경과 ÷ 예상 소요(예상 소요 = (남은 시간 + 경과) ÷ 남은 절 수 — 경과가 평균보다 짧으면 정확히 평균이 된다). 그 절이 끝나기 전에 막대가 다 차 보이면 멈춘 것처럼 읽혀 90% 아래에 둔다. 첫 절은 평균이 없어 30초마다 남은 거리의 절반씩 다가간다.
- **포인터와 초점을 따로 든다(`nextSlotHover`)**(`a12f788`, §14 다듬기). 한 칸을 같이 쓰면 마우스가 떠날 때 키보드 초점의 강조까지 풀리고, 누른 뒤 초점이 초안으로 옮겨 가며 난 blur 가 포인터가 아직 올라가 있는 항목의 강조를 지운다. 터치는 강조하지 않는다 — iOS·iPadOS Safari 는 탭한 항목에 떠날 신호를 다음 탭까지 보내지 않아 강조가 남는다. 강조할 절은 눌러 옮긴 절(잠깐) → 포인터 → 초점 순이다(`linkedSlot`) — 옮기며 화면이 움직여 포인터 밑에 우연히 온 다른 항목이 옮겨 간 자리를 가리지 않게.
- **처음 그릴 때는 "이번에 끝난 절"이 없다(`newlyFinished`).** 새로고침한 화면에서 이미 끝난 절이 한꺼번에 튀어 오르거나 스크린리더가 몰아 읽지 않게. 직전 목록에 없던 절이 끝난 채로 오면(재접속 스냅샷) 끝난 것으로 본다.
- **시계는 쓰는 동안만 돈다.** 늘 돌리면 시계를 읽는 화면 전체가 1초마다 다시 그려진다. 서버 렌더에서는 타이머를 걸지 않는다 — 요청이 끝나도 풀리지 않는다.

```ts
import type { DraftSlot, DraftSlotStatus, SynthEta } from "./researchDraft";
import { formatClock, formatRemaining } from "./researchDraft";

// 쓰는 중인 절이 끝나기 전에 막대가 다 차 보이면 멈춘 것처럼 읽힌다 — 끝날 때까지 이 비율 아래에 둔다
const RUNNING_CAP = 0.9;
// 첫 절은 평균이 없어 예상 소요를 모른다 — 30초마다 남은 거리의 절반씩 다가간다
const FIRST_HALF_LIFE_MS = 30_000;

const FINISHED: readonly DraftSlotStatus[] = ["done", "failed"];

export function synthSummary(eta: SynthEta): string {
  if (eta.total <= 0) return "보고서 작성을 준비하는 중";
  const head = `${Math.min(eta.done, eta.total)}/${eta.total} 절 완료`;
  if (eta.done >= eta.total) return `${head} · 보고서를 마무리하는 중`;
  const remaining = formatRemaining(eta.remainingMs, eta.done);
  return remaining ? `${head} · ${remaining}` : head;
}

export function slotStateLabel(slot: DraftSlot, eta: SynthEta): string {
  switch (slot.status) {
    case "done":
      return slot.durationMs !== null ? `완료 ${formatClock(slot.durationMs)}` : "완료";
    case "running":
      return slot.idx === eta.runningIdx && eta.runningElapsedMs !== null
        ? `작성 중 ${formatClock(eta.runningElapsedMs)}`
        : "작성 중";
    case "failed":
      return "서술 받지 못함";
    case "waiting":
      return "대기";
  }
}

// 막대는 끝난 절 + 쓰는 중인 절의 몫이다. 절 하나가 수십 초라 끝날 때만 늘면 막대가 서 있는 것처럼 보인다.
// 몫 = 경과 ÷ 예상 소요, 예상 소요 = (남은 시간 + 경과) ÷ 남은 절 수. synthEta 의 남은 시간은
// 평균 × 대기 절 + max(0, 평균 − 경과) 라, 경과가 평균보다 짧으면 예상 소요가 정확히 평균이 된다.
export function barFraction(eta: SynthEta): number {
  if (eta.total <= 0) return 0;
  const done = Math.min(Math.max(eta.done, 0), eta.total);
  const left = eta.total - done;
  let part = 0;
  if (left > 0 && eta.runningIdx !== null && eta.runningElapsedMs !== null) {
    const elapsed = Math.max(0, eta.runningElapsedMs);
    if (eta.remainingMs !== null) {
      const expected = (eta.remainingMs + elapsed) / left;
      part = expected > 0 ? Math.min(RUNNING_CAP, elapsed / expected) : RUNNING_CAP;
    } else {
      part = RUNNING_CAP * (1 - 0.5 ** (elapsed / FIRST_HALF_LIFE_MS));
    }
  }
  return Math.min(1, (done + part) / eta.total);
}

// 현황 카드 항목에 올라가 있는 포인터·초점. 한 칸을 같이 쓰면 마우스가 떠날 때 키보드 초점의 강조까지 풀리고,
// 누른 뒤 초점이 초안으로 옮겨 가며 난 blur 가 포인터가 아직 올라가 있는 항목의 강조를 지운다
export interface SlotHover {
  pointer: number | null;
  focus: number | null;
}

export type SlotHoverEvent =
  | { kind: "pointerenter"; idx: number; pointerType: string }
  | { kind: "pointerleave"; idx: number }
  | { kind: "focus"; idx: number }
  | { kind: "blur"; idx: number };

export const NO_SLOT_HOVER: SlotHover = { pointer: null, focus: null };

export function nextSlotHover(s: SlotHover, e: SlotHoverEvent): SlotHover {
  switch (e.kind) {
    case "pointerenter":
      // 터치는 올려 둔 상태가 없다 — iOS Safari 는 탭한 항목에 떠날 신호를 다른 항목을 탭할 때까지 보내지 않아
      // 강조가 남는다. 탭은 곧바로 초안으로 옮겨 가 그 절을 잠깐 강조하므로 따로 강조할 까닭도 없다
      return e.pointerType === "touch" ? s : { ...s, pointer: e.idx };
    case "pointerleave":
      return s.pointer === e.idx ? { ...s, pointer: null } : s;
    case "focus":
      return { ...s, focus: e.idx };
    case "blur":
      return s.focus === e.idx ? { ...s, focus: null } : s;
  }
}

// 초안에서 함께 강조할 절. 눌러 옮긴 절(flash)이 잠깐 가장 앞선다 — 옮기며 화면이 움직여 포인터 밑에
// 우연히 온 다른 항목이 옮겨 간 자리를 가리지 않게. 그다음은 포인터, 초점 순이다
export function linkedSlot(flash: number | null, hover: SlotHover): number | null {
  return flash ?? hover.pointer ?? hover.focus;
}

// 직전 목록과 비교해 이번에 끝난 절. 처음 그릴 때(prev 가 null)는 없다 — 새로고침한 화면에서
// 이미 끝난 절이 한꺼번에 튀어 오르거나 스크린리더가 몰아 읽지 않게
export function newlyFinished(prev: ReadonlyMap<number, DraftSlotStatus> | null, slots: readonly DraftSlot[]): number[] {
  if (!prev) return [];
  return slots
    .filter((s) => FINISHED.includes(s.status) && !FINISHED.includes(prev.get(s.idx) ?? "waiting"))
    .map((s) => s.idx);
}

export function finishedAnnouncement(slots: readonly DraftSlot[], idxs: readonly number[]): string {
  return idxs
    .map((idx) => slots.find((s) => s.idx === idx))
    .filter((s): s is DraftSlot => s !== undefined)
    .map((s) =>
      s.status === "failed"
        ? `절 ${s.idx + 1} 서술 받지 못함, 논문 목록만 싣습니다: ${s.heading}`
        : `절 ${s.idx + 1} 작성 완료: ${s.heading}`,
    )
    .join(". ");
}
```

```ts
}
```

### 2.42 `utils/citations.ts` — 마커 분해·칩 라벨·쪽 표기

**책임.** 모델이 쓴 글을 글 조각과 인용 칩 배열로 나눈다(`splitCitations`). 칩 라벨(`김 2019`), 팝오버의 서지 한 줄, 그 절의 대목 고르기(`citeChunks`), 쪽 표기(`pageLabel`·`pdfPage`).

**왜 이렇게 짰나.**

- **모델이 쓴 글은 `v-html` 로 넣지 않는다(D9).** 기존 화면은 `marked` + `v-html` 에 sanitize 가 없다. 보고서는 `[E3]` 마커로 쪼개 글은 텍스트 노드로, 마커는 칩 컴포넌트로 그린다. 서버(`bind_markers`)가 인식한 표기를 전부 `[E3]` 한 모양으로 다시 써서 보내므로 화면은 표준형만 칩으로 바꾸고 나머지는 글자 그대로 둔다.
- **칩은 자기 절에서 매칭된 대목만 보인다.** 한 논문이 여러 절에 실리면 `evidence.chunks` 는 그 합집합이다. 순서는 절 매핑(`evidence_chunks`)의 순서를 그대로 쓴다(`e9cefe7`, 최종 리뷰 minor) — 서버가 그 하위질문의 점수 순으로 준다. `evidence.chunks` 는 전역 최고점 순이라 그 순서로 고르면 이 절의 검색어로는 덜 맞은 대목이 먼저 나온다.
- **대목 목록은 id 로 견준다(`chunkListKey`)**(`c558b81`, §14 다듬기). 초안에 절이 더해지거나 초안이 최종본으로 바뀌어 다시 그리면 `citeChunks` 가 같은 대목의 새 배열을 돌려준다. 배열 동일성으로 지켜보면 열어 둔 팝오버가 보던 대목에서 첫 대목으로 돌아간다.
- **쪽 0 은 "쪽 정보 없음".** 저장된 쪽수는 0부터 센다(PyMuPDF). 0 은 "첫 쪽"과 "쪽 정보 없음"(인덱서의 `or 0`)이 겹쳐 구분할 수 없다 — "p.0" 을 보이지 않는다(spec §6-3). 표기와 PDF 쪽은 저장값 + 1.

```ts
// frontend/utils/citations.ts
import type { EvidenceMeta, ReportChunk, ReportEvidence, ReportSection } from "../types/research";

export type CitationPart = { type: "text"; text: string } | { type: "cite"; eid: string };

// 서버(services/research/citations.bind_markers)가 인식한 표기를 전부 [E3] 한 모양으로
// 다시 써서 보낸다 — 화면은 이 표준형만 칩으로 바꾸고 나머지는 글자 그대로 둔다.
const MARKER = /\[(E\d+)\]/g;
const YEAR = /(19|20)\d{2}/;
const HANGUL_NAME = /^[가-힣\s]+$/;

export function splitCitations(text: string): CitationPart[] {
  const parts: CitationPart[] = [];
  let last = 0;
  for (const m of text.matchAll(MARKER)) {
    const at = m.index ?? 0;
    if (at > last) parts.push({ type: "text", text: text.slice(last, at) });
    parts.push({ type: "cite", eid: m[1] ?? "" });
    last = at + m[0].length;
  }
  if (last < text.length) parts.push({ type: "text", text: text.slice(last) });
  return parts;
}

export function pubYear(pubDate: string | null | undefined): string | null {
  const m = YEAR.exec(pubDate ?? "");
  return m ? m[0] : null;
}

export function splitAuthors(personal: string | null | undefined): string[] {
  const raw = (personal ?? "").trim();
  if (!raw) return [];
  const bySemicolon = raw.split(/[;|·]/).map((s) => s.trim()).filter(Boolean);
  if (bySemicolon.length > 1) return bySemicolon;
  const byComma = raw.split(",").map((s) => s.trim()).filter(Boolean);
  // "Smith, John" 처럼 성과 이름을 쉼표로 가른 한 사람은 쪼개지 않는다 — 조각마다
  // 한글이 있거나 띄어 쓴 이름일 때만 여러 저자로 본다
  const allNames = byComma.every((s) => /[가-힣]/.test(s) || /\s/.test(s));
  return byComma.length > 1 && allNames ? byComma : [raw];
}

export function firstAuthorSurname(personal: string | null | undefined): string | null {
  const first = splitAuthors(personal)[0]?.replace(/\s*외\s*\d*\s*인?\s*$/, "").trim();
  if (!first) return null;
  if (HANGUL_NAME.test(first)) return first.replace(/\s/g, "").slice(0, 1);
  if (first.includes(",")) return first.split(",")[0]?.trim() || first;
  const tokens = first.split(/\s+/);
  return tokens[tokens.length - 1] ?? first;
}

export function citeLabel(meta: EvidenceMeta | undefined, eid: string): string {
  const who = firstAuthorSurname(meta?.personal_author);
  const year = pubYear(meta?.pub_date);
  if (who && year) return `${who} ${year}`;
  return who ?? eid;
}

export function metaLine(meta: EvidenceMeta | undefined): string {
  if (!meta) return "";
  const journal = [meta.series_title, meta.vol_issue].filter((s) => s && s.trim()).join(" ");
  const citations = meta.kci_citations != null ? `피인용 ${meta.kci_citations}` : "";
  return [meta.personal_author ?? "", journal, pubYear(meta.pub_date) ?? "", citations, meta.grade ?? ""]
    .map((s) => s.trim())
    .filter(Boolean)
    .join(" · ");
}

// 한 논문이 여러 절에 실리면 evidence.chunks 는 그 합집합이다 — 칩은 자기 절에서
// 매칭된 대목만 보여 줘야 절 내용과 맞는다. 매핑이 없으면(옛 보고서) 전부 보여 준다.
// 순서는 절 매핑(evidence_chunks)의 순서를 그대로 쓴다 — 서버가 그 하위질문의 점수 순으로
// 준다(citations.link_chunks). evidence.chunks 는 전역 최고점 순이라 그 순서로 고르면 이 절의
// 검색어로는 덜 맞은 대목이 먼저 나온다.
export function citeChunks(
  section: ReportSection | undefined,
  evidence: ReportEvidence | undefined,
  eid: string,
): ReportChunk[] {
  if (!evidence) return [];
  const ids = section?.evidence_chunks?.[eid];
  if (!ids || !ids.length) return evidence.chunks;
  const byId = new Map(evidence.chunks.map((c) => [c.chunk_id, c]));
  const picked = ids.map((id) => byId.get(id)).filter((c): c is ReportChunk => c !== undefined);
  return picked.length ? picked : evidence.chunks;
}

// 인용칩이 보던 대목을 첫 대목으로 돌릴지 견주는 열쇠. 초안에 절이 더해지거나 초안이 최종본으로 바뀌어 다시
// 그리면 citeChunks 가 같은 대목의 새 배열을 돌려주므로, 배열이 아니라 대목 id 로 견준다
export function chunkListKey(chunks: readonly ReportChunk[]): string {
  return chunks.map((c) => c.chunk_id).join("|");
}

// 저장된 쪽수는 0부터 센다(ingestion/extractor). 0 은 "첫 쪽"과 "쪽 정보 없음"
// (indexer 의 `or 0`)이 겹쳐 구분할 수 없으므로 쪽을 표시하지 않는다.
export function pageLabel(chunk: Pick<ReportChunk, "page_start" | "page_end">): string {
  if (!chunk.page_start || chunk.page_start <= 0) return "쪽 정보 없음";
  const start = chunk.page_start + 1;
  const end = chunk.page_end + 1;
  return end > start ? `p.${start}–${end}` : `p.${start}`;
}

export function pdfPage(chunk: Pick<ReportChunk, "page_start">): number | undefined {
  return chunk.page_start > 0 ? chunk.page_start + 1 : undefined;
}
```

### 2.43 `components/research/CitationChip.vue` — 인용칩 팝오버

**책임.** 칩(`김 2019`)을 올리거나 누르거나 키보드로 초점을 옮기면 팝오버 — 제목, 저자·학술지·권호·연도·피인용·등재구분, 그 절의 원문 대목(여러 개면 1/2 넘기기, 쪽수), [원문 보기](`PdfViewer` 를 해당 쪽으로), [논문 상세].

**왜 이렇게 짰나 — 초점 처리.** 이 컴포넌트는 품질 검토·최종 리뷰에서 초점 결함이 네 번 나왔다(`38ca2ea`·`0b81675`·`e6d3214`·`c558b81`).

- **Esc 한 번에 닫히게 초점을 먼저 칩으로 옮기고 닫는다.** `focus()` 가 동기로 쏘는 `focusin` 이 감싼 요소의 `show` 로 올라가 닫힘을 되돌리지 않게.
- **대목 넘기기 끝·팝오버 안쪽 글 클릭·창 전환에 닫히지 않는다.** 초점이 다른 요소로 옮겨 가지 않고 그냥 빠진 것(`relatedTarget` 없음 — 창 전환, 초점을 받지 않는 곳 클릭)은 떠난 게 아니다.
- **포인터로 연 팝오버 안에 초점이 있으면 포인터가 벗어나도 닫지 않는다**(`hideOnPointerLeave`). 초점을 쥔 팝오버를 닫으면 초점이 body 로 떨어진다. 닫기는 `focusout` 에 맡긴다.
- **대목을 끌어 선택하다 팝오버 밖에서 놓아도 닫지 않는다.** click 이 바깥 공통 조상에 떨어진다 — 복사하려던 선택을 지킨다.
- **화면 오른쪽 끝의 칩은 넘친 만큼 팝오버를 왼쪽으로 민다** — 잘리고 가로 스크롤이 생기지 않게.
- **원문 쪽.** [원문 보기]는 지금 보는 대목의 쪽(`pdfPage`)을 실어 페이지에 올린다. 페이지가 먼저 PDF 존재를 확인하고(404 면 "원문 파일이 없습니다", [03](03-딥리서치-이벤트.md) §2.30) 뷰어를 연다.

### 2.45 `components/research/ReportView.vue` — 보고서와 초안 모드

**책임.** 보고서 머리(질문·수록 범위·생성 시각·[링크 복사]·`actions` 슬롯) · 서론 한 줄 · 절들 · 한계 섹션. `draft` prop 이 있으면 초안 모드 — 머리에 배지, 끝난 절은 최종본과 똑같이(인용칩·원문 보기 동작), 쓰는 중인 절은 제목 + 은은하게 움직이는 회색 줄, 대기 절은 제목 + "작성 대기". 한계 섹션은 없다.

**왜 이렇게 짰나.**

- **초안은 아직 쓰지 않은 절까지 자리를 잡아 둔다.** 절이 끝나도 뒤 절이 밀리지 않는다 — 읽던 자리가 흔들리지 않는다.
- **절 id(`rs-sec-<idx>`)는 현황 카드가 눌러 옮겨 오는 자리다.** 초점도 받아(`tabindex="-1"`) 키보드로 옮긴 사람이 이어 읽는다. 초안이 같은 자리에서 최종본으로 바뀔 때 `tabindex` 가 빠지면 그 절에 있던 초점이 body 로 떨어지므로(Chrome 152 로 확인, `535ea4f`) 최종본에도 둔다.
- **한계 섹션은 눈에 띄게, 가공 없이**(spec §6-3, round04a Q19 — 한계를 드러내는 것이 차별점이다). 없으면 `NO_LIMITS`.
- **절이 완성되면 제자리에 부드럽게 나타난다(CSS `rs-reveal`).** 자동 스크롤은 하지 않는다. 애니메이션의 `fill` 은 `backwards` 만이다(`a819a46`, §14 Task 7 품질 검토) — `both`·`forwards` 면 끝난 뒤에도 효과가 남아 본문마다 쌓임 맥락이 생기고, 인용칩 팝오버가 다음 절 본문 아래로 깔려 클릭을 빼앗긴다.

### 2.46 `pages/research/[id].vue` — 상태 기계와 배치

**책임.** 블록 넷(머리·계획 카드·진행 패널·보고서)을 단계에 따라 배치 A(2단)·B(쌓이는 문서)로 그린다. 종합 단계에서는 현황 카드와 초안, 완료 뒤에는 보고서와 [다운로드], 멈추면 실패·취소 카드와 멈춘 초안·[초안 저장].

| 단계(`researchPhase`) | 본문 | 진행 패널 |
|---|---|---|
| `planning` | "연구 계획을 세우는 중입니다" | 안내 |
| `awaiting` | 계획 카드(고치기·승인·취소) | 안내 |
| `queued` | "앞선 연구가 끝나면 시작합니다" | 안내 |
| `exploring` | 계획 카드(하위질문별 진행) | 카운터·강조 카드·회차 타임라인 |
| `synthesizing` | **현황 카드 + 초안** | 탐색 완료 요약 |
| `completed` | 보고서([다운로드]) | 탐색 경로 |
| `failed` | 오류 + [재시도](탐색이 끝났으면 "보고서 작성부터 다시 시도") + 멈춘 초안 | 멈춘 지점 |
| `canceled` | "취소된 연구입니다" + [같은 질문으로 다시 시작] + 멈춘 초안 | 멈춘 지점 |

**왜 이렇게 짰나.**

- **초안과 최종본은 같은 `ReportView` 한 갈래로 그린다(`shownReport`)**(`535ea4f`, §14 다듬기). 처음엔 `v-if` 두 갈래(초안 `ReportView` / 최종본 `ReportView`)라, 최종본이 도착하면 vnode 종류·key 가 달라 초안 쪽을 언마운트하고 새로 마운트했다 — 초안 안의 초점이 body 로 떨어지고, 고정해 둔 인용 팝오버가 닫히며, 스크롤 기준 노드가 사라져 읽던 자리가 튀었다. 지금은 최종본이 오면 같은 인스턴스에 넘기고, [다운로드]·[초안 저장]은 `actions` 슬롯 안에서 가른다. 절 idx 로 묶인 절·인용칩 인스턴스가 그대로 이어진다(DOM 없는 렌더러로 작성 중 → 완료 → 최종본 도착 동안 `ReportView` 가 한 번만 마운트됨을 확인했다 — 커밋 메시지).
- **`draftMode` 를 computed 로 만든다.** 템플릿에서 객체를 만들면 1초마다 도는 시계 때문에 초안 전체가 매초 다시 그려진다.
- **현황 카드 → 초안 이동(`jumpToSection`).** `prefers-reduced-motion` 이면 부드러운 스크롤 대신 바로 옮기고, 초점도 그 절로 옮긴다(스크롤은 이미 했으니 `preventScroll`). 1.6초 강조. 종합이 끝나 카드가 사라지면 `pointerleave`·`blur` 가 오지 않으므로 올려 둔 강조를 푼다.
- **원문 보기 전 존재 확인.** `fetch` 로 상태만 보고 본문은 바로 끊는다 — 안 끊으면 PDF 전체를 두 번 내려받는다.
- **링크 복사.** 운영 게이트웨이가 http 라 clipboard API 가 없을 수 있다(보안 컨텍스트 전용) — `prompt` 로 물러선다.
- **배치.** 넓은 화면(1200px 이상)의 기본은 A, 좁은 화면은 늘 B 다. 고른 보기는 localStorage(`skx_research_layout`)에 기억했다. **round04c 에서 바뀌었다** — 2026-09-30 사용자 결정으로 "보고서가 나오기 전 B, 나오면 A" 로 단계에 따라 바뀌고 localStorage 기억은 없앴다(`2e3d87a`, spec §7-5). 아래 코드와 §2.47 은 round04b 시점이다.
- **내려받기**는 [05](05-문서모델-Word-인쇄.md) 에서 읽는다 — 페이지는 `docInputFromReport`·`docInputFromDraft` 로 문서 모델 입력을 만들어 `buildReportDocument` 에 넘긴다. 배포 뒤 옛 화면에서 누르면 `docx` 조각 파일이 사라져 동적 import 가 실패한다 — "새로고침한 뒤 다시 시도" 안내.

```ts
// frontend/utils/researchLayout.ts
export type ResearchLayout = "A" | "B";

// 아래 셋은 화면 기획자가 정할 값이다. 정해지면 값만 바꾼다.
export const DEFAULT_LAYOUT: ResearchLayout = "A";
export const WIDE_MIN_PX = 1200;
export const SHOW_LAYOUT_TOGGLE = true;

export const LAYOUT_KEY = "skx_research_layout";

export function readLayoutPref(storage: Storage | null): ResearchLayout | null {
  try {
    const v = storage?.getItem(LAYOUT_KEY);
    return v === "A" || v === "B" ? v : null;
  } catch {
    return null;
  }
}

export function writeLayoutPref(storage: Storage | null, layout: ResearchLayout): void {
  try {
    storage?.setItem(LAYOUT_KEY, layout);
  } catch {
    // 막힌 저장소(사생활 보호 모드 등)면 이번 방문 동안만 기억한다
  }
}

// 2단은 폭이 모자라면 본문이 좁아져 읽을 수 없다 — 좁은 화면은 선택과 무관하게 B 다
export function effectiveLayout(pref: ResearchLayout | null, wide: boolean): ResearchLayout {
  if (!wide) return "B";
  return (SHOW_LAYOUT_TOGGLE ? pref : null) ?? DEFAULT_LAYOUT;
}
```
