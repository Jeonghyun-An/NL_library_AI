### 2.6 Postgres 정기 백업

**파일**: `infra/backup/pg_backup.sh`

백업을 compose 서비스가 아니라 호스트 cron 으로 붙였다. compose 에 넣으면 스택 재배포가 필요해 사고 직후에 급히 달기 어렵고, 백업은 앱 배포 주기와 분리돼 있는 편이 낫다. 실측 DB 4.8GB 중 `book_sections` 가 4.1GB, `library_catalog` 은 381MB 이므로 두 단계로 나눈다 — 매일 5GB 를 덤프하는 건 낭비이고, 실제로 날아간 건 카탈로그다. 덤프는 임시 파일(`.part`)에 받고 성공했을 때만 제자리로 옮긴다: 중단된 덤프가 백업인 척하는 것이 백업이 없는 것보다 나쁘다. 공유 서버라 weekly 전체 덤프에 `search_history.query`(사용자 검색어 원문)가 들어가므로 `umask 077` 로 소유자만 읽게 했다. 복원 연습까지 마쳤다 — 임시 DB 에 `pg_restore` 해 241,243행 / abstract 42,957 / summary 945 를 확인했다.

```sh
#!/bin/sh
# pg_backup.sh — nl_lib Postgres 정기 백업 (호스트 cron 에서 실행)
#
# 2026-09-14 library_catalog 이 통째로 비워져 고아 문서 72,601 건이 발생했다.
# 복구가 가능했던 건 원본 카탈로그 파일이 uploads/ 에 남아있고 초록이 Milvus 청크에
# 남아있었기 때문이지 설계된 안전장치 덕이 아니었다. 그래서 백업을 붙인다.
#
# 두 단계로 나눈다 (실측: DB 4.8GB, library_catalog 381MB, book_sections 4.1GB):
#   daily  — library_catalog 만. 작아서 매일 돌려도 부담이 없고, 실제로 날아간 것이 이 테이블이다.
#   weekly — 전체 DB. book_sections(원문 100만행 이상)까지 포함해 무겁지만,
#            원문은 재추출에 OCR 비용이 들어 반드시 지켜야 한다.
#
# 인증: postgres 컨테이너가 로컬 소켓 접속을 신뢰하므로 비밀번호가 필요 없다.
# 백업 위치는 Postgres 볼륨 바깥이어야 한다 — 볼륨이 날아갈 때 같이 죽으면 의미가 없다.
#
# 설치:
#   sudo install -m 755 pg_backup.sh /usr/local/bin/nl-lib-pg-backup
#   sudo crontab -e
#     30 4 * * * /usr/local/bin/nl-lib-pg-backup >> /var/log/nl-lib-backup.log 2>&1
#
# 복원 (반드시 한 번은 연습할 것 — 복원해 본 적 없는 백업은 백업이 아니다):
#   docker exec -i nl-lib-postgres pg_restore -U admin -d nl_lib --clean --if-exists \
#     -t library_catalog < /data/nl-lib/backup/daily/library_catalog_<타임스탬프>.dump
set -eu

# 공유 서버라 로컬 계정 누구나 접근 가능 — weekly 전체 덤프에는
# search_history.query(사용자 검색어 원문)가 그대로 들어있어 소유자만 읽게 한다.
umask 077

BACKUP_DIR="${NL_LIB_BACKUP_DIR:-/data/nl-lib/backup}"
CONTAINER="${NL_LIB_PG_CONTAINER:-nl-lib-postgres}"
DB="${NL_LIB_PG_DB:-nl_lib}"
DB_USER="${NL_LIB_PG_USER:-admin}"
KEEP_DAILY="${NL_LIB_KEEP_DAILY:-14}"
KEEP_WEEKLY="${NL_LIB_KEEP_WEEKLY:-4}"

ts="$(date +%Y%m%dT%H%M%S)"
mkdir -p "$BACKUP_DIR/daily" "$BACKUP_DIR/weekly"

# 임시 파일에 받고 성공했을 때만 제자리로 옮긴다 — 중단된 덤프가 백업인 척하면 안 된다.
dump() {
  target="$2"
  tmp="$target.part"
  if docker exec "$CONTAINER" pg_dump -U "$DB_USER" -d "$DB" --format=custom $1 > "$tmp"; then
    mv "$tmp" "$target"
    echo "$(date -Is) OK   $target ($(du -h "$target" | cut -f1))"
  else
    rm -f "$tmp"
    echo "$(date -Is) FAIL $target"
    return 1
  fi
}

dump "-t library_catalog" "$BACKUP_DIR/daily/library_catalog_$ts.dump"

# 일요일에만 전체 덤프
if [ "$(date +%u)" = "7" ]; then
  dump "" "$BACKUP_DIR/weekly/nl_lib_full_$ts.dump"
fi

# 최신 N 개만 남긴다. 패턴을 따옴표 없이 둬야 셸이 glob 을 확장한다
# (ls "pattern*" 는 ls 가 글로빙을 하지 않아 동작하지 않는다).
prune() {
  dir="$1"
  pat="$2"
  keep="$3"
  cd "$dir" || return 0
  ls -1t $pat 2>/dev/null | tail -n "+$((keep + 1))" | while read -r f; do
    rm -f "$dir/$f"
    echo "$(date -Is) prune $f"
  done
}

prune "$BACKUP_DIR/daily" "library_catalog_*.dump" "$KEEP_DAILY"
prune "$BACKUP_DIR/weekly" "nl_lib_full_*.dump" "$KEEP_WEEKLY"
```

### 2.7 게이트웨이에서 관리자 API·문서 차단

**파일**: `infra/conf.d/default.conf`, `infra/conf.d.dev/default.conf`

`/api/admin` 에는 `library_catalog` 을 통째로 지우는 `DELETE` 가 있는데 인증이 없다. 사고의 원인이 API 경유는 아니라고 배제됐지만(§00-개요 참조), 인증 없는 전체 삭제 엔드포인트가 외부에 열려 있는 상태 자체를 그대로 둘 수는 없었다. `/docs`·`/openapi.json` 도 함께 막는다 — Swagger UI 가 열려 있으면 그 `DELETE` 를 버튼 한 번으로 부를 수 있다.

핵심은 **nginx 의 접두 location 은 최장 일치가 이긴다**는 점이다. `location ^~ /api/admin` 과 `location /api/` 가 함께 있을 때 `/api/admin/books` 요청은 더 긴 접두인 `/api/admin` 블록에 잡히므로, 뒤에 오는 `/api/` 프록시 블록으로 새지 않는다. 작성 순서는 무관하다(정규식 location 과 달리 접두 location 은 순서가 아니라 길이로 정해진다). `^~` 수식자는 여기서 필수는 아니지만, 나중에 누군가 정규식 location 을 추가해도 그것이 이 차단을 이기지 못하게 못박는 용도다. 두 파일 모두 서버 블록 안, `location /api/` **앞**에 두어 의도가 눈에 보이게 했다(동작은 위치와 무관하다). `/docs`·`/openapi.json` 은 정확히 그 경로만 막으면 되므로 `location =` 정확 일치를 쓴다.

운영(`infra/conf.d/default.conf`) — 서버 블록 시작부터 차단 블록까지:

```nginx
server {
    listen 80;
    server_name _;

    # ── 관리자 API 외부 차단 ───────────────────────────────
    # /api/admin 은 library_catalog 를 통째로 지우는 DELETE 를 포함하는데
    # 인증이 없다. 2026-09-14 카탈로그 전체 유실 이후 외부 노출을 차단한다.
    # 관리 작업은 서버 내부에서 컨테이너로 직접 호출할 것:
    #   docker exec nl-lib-fastapi curl -s localhost:8000/api/admin/status
    # 접두 매칭은 최장 일치가 이기므로 이 블록이 location /api/ 보다 우선한다.
    # (^~ 는 정규식 location 이 나중에 추가돼도 뒤집히지 않게 못박는 용도)
    location ^~ /api/admin {
        deny all;
    }

    # FastAPI (REST API)
    location /api/ {
        proxy_pass         http://fastapi/api/;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }

    # Swagger UI / OpenAPI 스키마 — 외부 차단
    # 공개 시 /api/admin 의 DELETE 를 버튼 한 번으로 호출할 수 있다.
    location = /docs {
        deny all;
    }

    location = /openapi.json {
        deny all;
    }
```

운영 파일에서는 `/docs`·`/openapi.json` 이 원래 FastAPI 로 프록시되는 블록이었고(`proxy_pass http://fastapi/docs;`), 그 두 블록을 `deny all;` 로 치환했다.

개발(`infra/conf.d.dev/default.conf`) — 같은 블록을 동일하게 넣는다. dev 게이트웨이도 같은 네트워크에 노출되므로 운영만 막으면 우회로가 남는다. 이 파일에서는 `/health` 가 서버 블록 맨 앞에 있어 차단 블록이 그 뒤에 온다:

이 차단 때문에 관리 API 호출 방법이 바뀌었다. 기존 런북의 `curl http://<호스트>/api/admin/...` 안내는 이제 403 이 되므로, 컨테이너 경유 호출(`docker exec nl-lib-fastapi curl -s localhost:8000/api/admin/...`)로 정정했다.

한 가지 밝혀둘 것 — `app/api/admin.py` 의 Milvus expression injection(사용자 입력 `cnts_id` 가 검증 없이 f-string 으로 필터 표현식에 들어간다)은 round01 부터 알려진 항목이고, 도서관 대회 이후 별도 라운드로 **의도적으로 이월된 상태**다. 이 게이트웨이 차단은 그 이월과는 별개로 외부 노출 자체를 줄이는 조치다.

### 2.8 빈 본문 인덱싱 가드

**파일**: `app/services/ingestion/stages.py` (`run_embed_index`)

`index_chunks` 는 `book_id` 기준 delete 후 insert 다. 그래서 빈 본문으로 임베딩 단계를 돌리면 새로 넣을 청크가 0개인 채로 기존 청크를 전부 지운다. 그런데 `run_finalize` 는 성공한 문서의 추출 아티팩트를 정리하므로, 이미 적재가 끝난 문서에서 임베딩 단계만 다시 돌리면 아티팩트가 없는 상태가 정상적으로 만들어진다 — 즉 이 경로는 실수로 밟기 쉽다. 인덱스를 건드리기 전에 멈춘다.

판정은 truthiness 가 아니라 `strip()` 기준이다. OCR 저품질 페이지는 공백만 담긴 채 로드되는데 그건 truthy 라 통과해버리고, chunker 는 최종적으로 strip 해 문장 0개를 내놓기 때문이다. 같은 이유로 바로 위의 논문 abstract 폴백 조건도 `if not full_text:` 에서 `if not full_text.strip():` 으로 함께 고쳤다 — 그러지 않으면 공백뿐인 본문이 폴백을 건너뛰고 곧바로 가드에 걸려 죽는다.

`error_group` 은 `artifact_missing` 을 재사용하지 않고 `empty_body` 로 분리했다. strip 기준이라 **아티팩트가 정상 로드된 문서도 걸리기 때문**이다. `artifact_missing` 으로 집계하면 실패 대시보드가 거짓을 말하고, 그 그룹의 표준 복구 절차("extract 부터 재실행")도 이 경우엔 맞지 않는다.

아래는 가드가 들어간 `run_embed_index` 전체다.

```python
def run_embed_index(ctx: StageContext) -> dict:
    """아티팩트 + 섹션 요약 로드 → 시맨틱 청킹 → contextual 임베딩 → Milvus delete+insert."""
    from domains import get_active_profile
    from domains.base import build_scalar_meta
    from services.ingestion.chunker import semantic_chunk, Chunk as ChunkType
    from services.ingestion.embedder import embed_texts
    from services.ingestion.indexer import index_chunks

    book_id = ctx.book_id
    client = minio_client()

    try:
        full_text, page_map = load_extraction_artifact(book_id, client)
    except StageError as _se:
        if _se.error_group != "artifact_missing":
            raise
        # PDF 없는 메타데이터 전용 논문 — abstract를 임베딩 텍스트로 사용
        full_text = ""
        page_map = {}

    db = SyncSessionLocal()
    try:
        book = db.query(Book).filter_by(cnts_id=book_id).first()
        if not book:
            raise StageError("not_found", "카탈로그 row 없음")

        # KCI 메타데이터 전용 논문 — abstract → title+journal 순으로 fallback
        if not full_text.strip() and (book.doc_type or "") == "paper":
            if book.abstract:
                full_text = book.abstract
                log.info(f"[{book_id}] PDF 없음 — abstract를 임베딩 텍스트로 사용 ({len(full_text)}자)")
            else:
                # abstract도 없으면 제목+저자+학술지로 최소 텍스트 구성
                fallback_parts = [p for p in [
                    book.title,
                    book.personal_author or book.corporate_author,
                    book.series_title,
                    book.subject,
                    book.keyword,
                ] if p]
                if fallback_parts:
                    full_text = " ".join(fallback_parts)
                    log.info(f"[{book_id}] PDF·abstract 없음 — 메타 필드로 최소 임베딩 ({len(full_text)}자)")

        # index_chunks 는 book_id 기준 delete 후 insert 라, 빈 본문으로 진행하면
        # 기존 청크가 전부 사라진다. 인덱스를 건드리기 전에 멈춘다.
        # 공백만 있는 페이지(OCR 저품질)는 truthy라 full_text 가 비어있지 않을 수
        # 있으므로 strip 기준으로 판단 — chunker 도 최종적으로 strip 해 문장 0개가 된다.
        if not full_text.strip():
            raise StageError(
                "empty_body",
                "추출 본문이 비어있다(아티팩트 없음 또는 공백뿐) — 빈 본문 인덱싱은 기존 청크를 전부 삭제한다",
            )

        sections_rows = (
            db.query(BookSection)
            .filter_by(book_id=book_id)
            .order_by(BookSection.section_idx)
            .all()
        )
        sections = [{"section_idx": s.section_idx, "text": s.full_text} for s in sections_rows]
        section_summary_map = {s.section_idx: s.summary for s in sections_rows if s.summary}
        section_themes_map = {
            s.section_idx: [t.strip() for t in s.themes.split(",") if t.strip()]
            for s in sections_rows if s.themes
        }
        doc_type = book.doc_type or "book"
        title = book.title or book_id
        meta_parts = [
            f"제목: {title}",
            f"기관: {book.corporate_author}" if book.corporate_author else None,
            f"저자: {book.personal_author}" if book.personal_author else None,
            f"출판사: {book.publisher}" if book.publisher else None,
            f"발행년도: {book.pub_date}" if book.pub_date else None,
            f"KDC분류: {book.kdc}" if book.kdc else None,
            f"주제: {book.subject}" if book.subject else None,
            f"키워드: {book.keyword}" if book.keyword else None,
            f"초록: {book.abstract}" if book.abstract else None,
        ]
        scalar_meta = build_scalar_meta(book, get_active_profile().milvus_scalar_fields)
    finally:
        db.close()

    def _embed_fn(texts: list[str]) -> list[list[float]]:
        dense, _ = embed_texts(texts)
        return dense

    chunks = semantic_chunk(full_text, _embed_fn, page_map=page_map)
    log.info(f"[{book_id}] 청킹 완료: {len(chunks)}개")

    assign_section_idx(chunks, sections)

    # 본문 청크: [핵심 테마] + [섹션 요약] + [본문] — 테마가 벡터 방향을 결정
    contextual_texts = []
    for c in chunks:
        parts = []
        if c.section_idx in section_themes_map:
            parts.append(f"[핵심 테마] {', '.join(section_themes_map[c.section_idx])}")
        if c.section_idx in section_summary_map:
            parts.append(f"[섹션 요약] {section_summary_map[c.section_idx]}")
        parts.append(f"[본문] {c.text}")
        contextual_texts.append("\n".join(parts))

    # ── [paper] 보강 청크 ────────────────────────────────────
    enriched_chunks: list[ChunkType] = []
    enrich_meta: dict = {}   # enrichment 커버리지 — 검증/모니터링용 (item.meta 로 노출)
    if doc_type == "paper" and cfg.PAPER_ENRICH_ENABLED:
        try:
            from services.ingestion.paper_enricher import enrich_paper, save_enrichment_artifact
            from sqlalchemy.orm.attributes import flag_modified as _flag_modified

            enrichment = run_async(enrich_paper(book_id, title, full_text, client))
            save_enrichment_artifact(book_id, enrichment, client)

            # 추출이 조용히 실패해도 보이도록 커버리지 기록 (전부 0이면 PDF 추출 품질 의심)
            enrich_meta = {
                "enriched": True,
                "has_abstract": bool(enrichment.abstract),
                "n_keywords": len(enrichment.keywords),
                "n_references": len(enrichment.references),
                "n_tables": len(enrichment.table_chunks),
                "n_figures": len(enrichment.figure_chunks),
                "n_toc": len(enrichment.toc),
            }

            if enrichment.abstract or enrichment.references or enrichment.keywords or enrichment.toc:
                db2 = SyncSessionLocal()
                try:
                    book_row = db2.query(Book).filter_by(cnts_id=book_id).first()
                    if book_row:
                        if enrichment.abstract and not book_row.abstract:
                            book_row.abstract = enrichment.abstract
                        if enrichment.keywords and not book_row.keyword:
                            book_row.keyword = ", ".join(enrichment.keywords)
                        extra = dict(book_row.extra or {})
                        extra["references"] = enrichment.references
                        if enrichment.toc:
                            extra["toc"] = enrichment.toc
                        if enrichment.keywords:
                            extra["keywords"] = enrichment.keywords
                        book_row.extra = extra
                        _flag_modified(book_row, "extra")
                        db2.commit()
                except Exception as _e:
                    log.warning(f"[{book_id}] enrichment DB 저장 실패: {_e}")
                    db2.rollback()
                finally:
                    db2.close()

            base_idx = len(chunks)
            if enrichment.abstract:
                enriched_chunks.append(ChunkType(
                    chunk_idx=base_idx, text=f"[초록] {enrichment.abstract}", section_idx=None,
                ))
                base_idx += 1
            if enrichment.keywords:
                kw_text = f"[키워드] {', '.join(enrichment.keywords)}"
                enriched_chunks.append(ChunkType(chunk_idx=base_idx, text=kw_text, section_idx=None))
                base_idx += 1
            for tc in enrichment.table_chunks:
                # ① 원본 마크다운 청크 — 수치 질문용
                table_text = f"[표]\n{tc.context}\n\n{tc.table_md}" if tc.context else f"[표]\n{tc.table_md}"
                table_text = table_text.encode("utf-8")[: cfg.MAX_CHUNK_BYTES].decode("utf-8", errors="ignore")
                enriched_chunks.append(ChunkType(chunk_idx=base_idx, text=table_text, section_idx=None))
                base_idx += 1
                # ② LLM 서술 청크 — 해석·의미 검색용 (실패 시 생략)
                if tc.description:
                    enriched_chunks.append(ChunkType(
                        chunk_idx=base_idx, text=f"[표 설명] {tc.description}", section_idx=None,
                    ))
                    base_idx += 1
            for i, fc in enumerate(enrichment.figure_chunks):
                enriched_chunks.append(ChunkType(
                    chunk_idx=base_idx + i, text=f"[그림 설명] {fc.description}", section_idx=None,
                ))
        except Exception as _e:
            import traceback
            log.warning(f"[{book_id}] paper enrichment 실패, 계속 진행: {_e}\n{traceback.format_exc()}")
            enrich_meta = {"enriched": False, "enrich_error": str(_e)[:500]}

    # 메타데이터 전용 청크 (chunk_idx=-1)
    meta_text = " | ".join(p for p in meta_parts if p)
    enriched_texts = [c.text for c in enriched_chunks]
    all_texts = contextual_texts + enriched_texts + [meta_text]

    dense_embeddings, sparse_embeddings = embed_texts(all_texts)
    log.info(
        f"[{book_id}] contextual 임베딩 완료: {len(chunks)}개 본문"
        f" + {len(enriched_chunks)}개 보강 + 1개 메타"
    )

    meta_chunk = ChunkType(chunk_idx=-1, text=meta_text, section_idx=None)
    all_chunks = chunks + enriched_chunks + [meta_chunk]

    idx_result = index_chunks(
        book_id, all_chunks, dense_embeddings, sparse_embeddings, scalar_meta=scalar_meta,
    )
    if idx_result.errors:
        raise StageError("milvus_error", f"Milvus 인덱싱 실패: {idx_result.errors}")
    log.info(f"[{book_id}] 인덱싱 완료: {idx_result.chunks_indexed}개")

    return {"chunks": len(chunks), "indexed": idx_result.chunks_indexed, **enrich_meta}
```

### 2.9 `doc_type` 오판정 수정

**파일**: `app/domains/nl_library/doc_types.py`

한국 근대문학 작품이 `paper` 로 판정돼 도서 검색에서 통째로 사라진 것이 이 라운드 본 스코프의 발단이다. 원인은 카탈로그 없이 적재된 문서(`source_format="PDF"`)의 `genre` 를 그대로 믿은 것이다 — 그 `genre` 는 카탈로그 값이 아니라 PDF 에서 LLM 이 자동추출한 추측이다.

바꾼 것은 한 줄이다: `genre` 가 학술 유형이어도 `source_format="PDF"` 면 `paper` 로 판정하지 않는다. 비대칭이 근거다 — **`paper` 오판정이 `book` 오판정보다 치명적이다.** 논문 필터에는 `book_id like "KCI_FI%"` 라는 ID 폴백이 있어 오판정돼도 회복되지만, 도서 필터는 `doc_type != "paper"` 라 폴백이 없다. 즉 잘못 `paper` 가 된 도서는 검색에서 영구히 사라지고 후처리로도 되살릴 수 없다. 대신 학위논문 PDF 가 `book` 으로 잡히는 대가는 계속 진다. 이건 안전망이고, 원천 대책은 크롤링 적재 잡에 `params.doc_type` 을 명시하는 것이다(메커니즘은 원래 있었고 쓰지 않았을 뿐이다).

`genre` 를 무시해도 KDC 가 있으면 그건 신뢰한다 — 아래 `if kdc:` 분기는 그대로다.

```python
def detect_doc_type(meta: dict[str, Any]) -> str:
    """
    문서 유형 판별.

    meta 키: kdc, title, source_format, genre (모두 선택)

    Returns:
        "paper"      : 학술논문·학위논문·보고서 (카탈로그 출신 genre 기반 — PDF 자동추출 genre 는 제외)
        "literature" : 문학 작품 (KDC 800~899)
        "policy"     : 법령·행정·조달 문서 (KDC 320~359 또는 제목 키워드)
        "book"       : 그 외 모든 도서 (기본값)
    """
    kdc = meta.get("kdc")
    title = meta.get("title")
    genre = meta.get("genre")
    source_format = meta.get("source_format")

    # source_format="PDF"(카탈로그 없이 적재)의 genre 는 PDF 자동추출 LLM 추측이라 근거로 쓰지 않는다.
    # 논문 필터는 ID 폴백(book_id like "KCI_FI%")이 있어 오판정이 복구되지만, 도서 필터에는 폴백이 없다.
    if genre in ("paper", "thesis", "report") and source_format != "PDF":
        return "paper"

    if kdc:
        digits = re.sub(r"[^0-9]", "", kdc)[:3]
        if digits:
            n = int(digits)
            if 800 <= n <= 899:
                return "literature"
            if n in _POLICY_KDC_RANGE:
                return "policy"

    if title and any(k in title for k in _POLICY_TITLE_KEYWORDS):
        return "policy"

    return "book"
```

### 2.10 참고문헌 파서 보강

**파일**: `app/services/ingestion/paper_enricher.py`

논문 `extra.references` 는 사고로 날아갔다가 `book_sections` 원문을 재구성해 `extract_references()` 로 다시 뽑는 방식으로 복구했다. 1차에서 30,532건을 얻고 41,399건이 미검출로 남았는데, 그 미검출분을 표본으로 들여다보니 실패가 두 가지 패턴에 몰려 있었다. 둘 다 구 라우팅 정책(모든 KCI 페이지를 VLM 으로 처리)이 만든 레거시 텍스트의 특성이다.

첫째, 헤더가 앞선 본문과 한 줄에 붙어 나온다 — `… 할 수 있다. ## 참 고 문 헌` 처럼. 기존 `_REF_HEADER` 는 `^\s*` 로 시작하는 단독 줄만 인정했다. 그래서 `^.*#{1,6}\s*키워드…$` 분기를 추가하되 **`#` 마크다운 헤더 마커가 실제로 있고 키워드가 줄 끝에 오는 경우만** 허용했다. 아무 줄에서나 "참고문헌"이라는 단어를 헤더로 오인하면 본문 한복판이 참고문헌 섹션 시작으로 잡히기 때문이다(회귀 테스트 `test_header_keyword_in_prose_not_matched` 가 이걸 지킨다).

둘째, 항목이 `박성수(1997).` 처럼 구분자 없이 이름에 연도가 바로 붙는다. 기존 `_REF_ENTRY` 패턴은 전부 쉼표나 마침표 같은 구분자를 요구해서 이런 줄을 항목 시작으로 보지 못하고 직전 항목의 연속으로 병합해버렸다. 한국어/영문 각각 한 분기씩 추가했다.

2차 복구 실적은 6,931건(누적 37,463건)이다. 500건 dry-run 에서 25.4% 가 나와 1만 건 안팎을 기대했으나 실제는 16.7% 였다 — dry-run 표본이 `ORDER BY cnts_id LIMIT 500` 이라 무작위가 아니었다. 정렬이 걸린 `LIMIT` 은 표본이 아니다.

`extract_references()` 함수 본체는 이번에 바뀌지 않았다. 아래에 전체를 싣는 것은 위 두 정규식이 이 함수의 어느 지점에서 쓰이는지 — 헤더 `finditer` 의 마지막 매칭과 줄 단위 항목 시작 판정 — 를 보이기 위해서다.

먼저 정규식 정의부(`_REF_HEADER_KEYWORD`·`_REF_HEADER` 신설/수정, `_REF_STOP` 은 불변, `_REF_ENTRY` 에 두 분기 추가):

```python
# ── 참고문헌 헤더 ─────────────────────────────────────────────
# 뒤에 붙는 마크다운(**참고문헌**)도 허용
_REF_HEADER_KEYWORD = r'참\s*고\s*문\s*헌|References?|REFERENCES?|Bibliography|참\s*고\s*자\s*료'
_REF_HEADER = re.compile(
    r'(?m)(?:'
    # 단독 줄 헤더 — 줄 시작에 (선택) 마크다운 장식 뒤 키워드만
    r'^\s*(?:[#*\-]+\s*)?(?:' + _REF_HEADER_KEYWORD + r')\s*[*_#]*\s*$'
    # 레거시 VLM 텍스트 — OCR 줄바꿈 오류로 '## 참고문헌'이 앞선 본문과
    # 한 줄에 붙어 나오는 경우. '#' 앞에 공백을 요구해야 URL 프래그먼트
    # (…/doc#references)가 헤더로 잡히지 않는다 — 마지막 매칭을 기준으로
    # 자르므로 가짜 헤더 하나가 참고문헌 전체를 날린다.
    r'|^.*(?:^|\s)#{1,6}\s*(?:' + _REF_HEADER_KEYWORD + r')\s*[*_#]*\s*$'
    r')',
    re.IGNORECASE,
)

# 참고문헌 이후 종료 패턴 (저자정보·부록·감사·연락처·초록)
_REF_STOP = re.compile(
    r'(?m)^\s*(?:[#*\-]+\s*)?(?:'
    r'저\s*자\s*(?:정보|소개)?|Author\s*(?:Information|s)?|AUTHOR'
    r'|부\s*록|Appendix|APPENDIX'
    r'|감\s*사|Acknowledgment'
    r'|연\s*락\s*처|Contact'
    r'|Abstract|ABSTRACT|국\s*문\s*(?:초록|요약|abstract)|영\s*문\s*(?:초록|요약)'
    r'|초\s*록|요\s*약'
    r')',
    re.IGNORECASE,
)

# 참고문헌 항목 시작 패턴
_REF_ENTRY = re.compile(
    r'^(?:'
    r'\[\d+\]'                         # [1]
    r'|\d{1,3}\.'                       # 1.
    r'|[가-힣A-Z][가-힣A-Za-z\s,\-]{2,}\.\s+\(?(?:19|20)\d{2}\)?'  # 저자(연도)
    r'|[가-힣A-Z][가-힣A-Za-z\s,\-]{2,},\s+(?:19|20)\d{2}[,.]'     # 저자, 연도.
    r'|[가-힣]{2,}(?:,\s*[가-힣]{2,})*(?:\s*외|\s*등)?\s*[,.]'      # 한국어 저자명. (KCI: 공은배 외., 백성준, 박인심.)
    r'|[A-Z][a-zA-Z\-]+,\s+[A-Z]'                                    # English Last, First (Bogue, E.)
    # 단독 저자명(연도) — 구분자 없음. 연도 뒤 '.'·','를 요구해야 본문 인용
    # ('박성수(1997)는 …')이 항목 시작으로 잡히지 않는다.
    r'|[가-힣]{2,4}\((?:19|20)\d{2}[a-z]?\)\s*[.,]'        # 박성수(1997).
    r'|[A-Z][a-zA-Z\-]{2,}\((?:19|20)\d{2}[a-z]?\)\s*[.,]'  # Csikszentmihalyi(1965).
    r')'
)
```

그리고 이 패턴들을 쓰는 `extract_references()`:

```python
def extract_references(full_text: str) -> list[str]:
    """참고문헌 섹션을 헤더로 찾은 뒤 항목 시작 패턴(_REF_ENTRY) 기준으로 분리.

    PDF 추출 텍스트는 항목 사이 빈 줄이 없는 경우가 많아, 빈 줄 분리만으로는
    전체가 1개 덩어리로 뭉친다. 줄 단위로 항목 시작을 감지하고 이어지는 줄은
    직전 항목의 연속으로 병합한다. 참고문헌은 항상 문서 끝에 위치하므로
    헤더는 마지막 매칭을 사용한다.
    """
    matches = list(_REF_HEADER.finditer(full_text))
    if not matches:
        return []
    m = matches[-1]  # 마지막 occurrence — 본문 내 오매칭 방지

    rest = full_text[m.end():]
    stop_m = _REF_STOP.search(rest)
    if stop_m:
        rest = rest[:stop_m.start()]

    # 1차: 항목 시작 패턴 기반 줄 단위 파싱
    refs: list[str] = []
    current: list[str] = []
    current_len = 0
    nonmatch_streak = 0
    for line in rest.splitlines():
        stripped = line.strip()
        if not stripped:
            continue
        if _PAGE_MARKER.search(stripped):
            continue  # 페이지 헤더/푸터 줄 제거
        if _REF_ENTRY.match(stripped):
            if current:
                refs.append(" ".join(current))
            current = [stripped]
            current_len = len(stripped)
            nonmatch_streak = 0
        elif current:
            # 직전 항목의 줄바꿈 연속 — 단, 비정상적으로 길어지면 본문 침범으로 판단
            current_len += len(stripped)
            if current_len > _REF_MAX_ENTRY_CHARS:
                refs.append(" ".join(current))
                current = []
                break
            current.append(stripped)
        else:
            nonmatch_streak += 1
            if nonmatch_streak >= _REF_MAX_CONSECUTIVE_NONMATCH:
                break
    if current:
        refs.append(" ".join(current))

    # 2차 폴백: 항목 패턴이 거의 안 잡히는 서식이면 기존 빈 줄 분리 방식
    if len(refs) < 3:
        blank_refs: list[str] = []
        for para in re.split(r'\n\s*\n', rest.strip()):
            lines = [
                ln.strip() for ln in para.splitlines()
                if ln.strip() and not _PAGE_MARKER.search(ln.strip())
            ]
            if lines:
                blank_refs.append(" ".join(lines))
        if len(blank_refs) > len(refs):
            refs = blank_refs

    return refs[:200]


# ── 3. 마크다운 표 추출 (원본 그대로) ────────────────────────
```

### 2.11 요약·테마·소개글 백필 태스크

**파일**: `app/workers/tasks.py` (`backfill_summary` — 신규 추가)

복구 9단계 중 마지막이 `summary`·`themes`·`introduction` 이다. `book_sections` 는 무사했고 섹션 요약도 112만 건이 살아있었으므로, 문서 단위 요약은 **섹션 요약을 재사용해 재추출 없이** 다시 만들 수 있다. 기존 `backfill_plot`·`backfill_read_effect` 와 같은 골격이지만 세 가지가 다르다.

첫째, `doc_type` 을 고정으로 가리지 않는다 — 줄거리·독후 효과와 달리 요약과 소개글은 논문도 쓴다. 대신 대상이 수만 건이 되므로 `doc_types` 인자로 좁혀 나눠 돌린다. 둘째, 후보 조건이 `summary`·`themes`·`introduction` 중 **하나라도** 비어있으면(`or_`) 대상이다. 처음엔 `summary`·`introduction` 만 봤는데, 리뷰에서 `themes` 단독 결손인 문서를 선택도 생성도 못 한다는 것이 드러나 `or_` 조건과 아래 `if force or not book.summary or not book.themes:` 를 함께 고쳤다. 셋째, 이미 채워진 필드는 `force` 가 아니면 덮지 않는다 — 각 대입이 `(force or not book.<필드>)` 를 다시 확인한다.

요약 LLM 과 소개글 LLM 은 각각 `try` 로 감싸 한쪽이 실패해도 다른 쪽은 쓴다. 둘 다 아무것도 못 썼으면(`wrote` 가 False) 세션을 롤백하고 `failed` 로 센다 — 커밋할 게 없는 것과 실패를 구분하지 않고 `done` 으로 세면 실적이 거짓이 된다.

```python
# ── 4-d. 요약·테마·소개글 백필 ───────────────────────────
@celery_app.task(name="tasks.backfill_summary", queue="ingestion")
def backfill_summary(limit: int = 500, force: bool = False, doc_types: list[str] | None = None):
    """summary·themes·introduction 백필 (섹션 요약 재사용, 재추출 없음).

    plot/read_effect 와 달리 doc_type 을 가리지 않는다 — 요약과 소개글은 논문도 쓴다.
    대상이 논문까지 포함되면 수만 건이 되므로 doc_types 로 좁혀 나눠 돌린다.

    force=False(기본): summary 나 introduction 중 하나라도 비어있는 임베딩 완료 문서
    force=True       : 대상 전체 재생성
    이미 채워진 필드는 force 가 아니면 덮지 않는다. 섹션 요약 없는 문서는 스킵.
    """
    from sqlalchemy import or_
    from models.section import BookSection
    from services.ingestion.stages import run_async
    from services.ingestion.summarizer import (
        generate_book_introduction,
        summarize_book_from_sections,
    )

    db = SyncSessionLocal()
    done = skipped = failed = 0
    try:
        q = db.query(Book).filter(Book.is_embedded == True)  # noqa: E712
        if doc_types:
            q = q.filter(Book.doc_type.in_(list(doc_types)))
        if not force:
            q = q.filter(or_(
                Book.summary.is_(None), Book.themes.is_(None), Book.introduction.is_(None),
            ))
        books = q.limit(limit).all()
        log.info(f"backfill_summary 시작: 대상 {len(books)}건 (force={force}, doc_types={doc_types})")

        for book in books:
            rows = (
                db.query(BookSection.summary)
                .filter_by(book_id=book.cnts_id)
                .order_by(BookSection.section_idx)
                .all()
            )
            valid = [r[0] for r in rows if r[0]]
            if not valid:
                skipped += 1
                continue

            title = book.title or book.cnts_id
            author = book.personal_author or book.corporate_author or ""
            doc_type = book.doc_type or "book"
            wrote = False

            if force or not book.summary or not book.themes:
                try:
                    summary, themes_list = run_async(summarize_book_from_sections(
                        title=title, author=author,
                        section_summaries=valid, doc_type=doc_type,
                    ))
                    if summary and (force or not book.summary):
                        book.summary = summary
                        wrote = True
                    if themes_list and (force or not book.themes):
                        book.themes = ", ".join(themes_list)
                        wrote = True
                except Exception as e:
                    log.warning(f"[{book.cnts_id}] 요약 백필 실패: {e}")

            if force or not book.introduction:
                try:
                    intro = run_async(generate_book_introduction(
                        title=title, author=author,
                        publisher=book.publisher or "", pub_date=book.pub_date or "",
                        section_summaries=valid, doc_type=doc_type,
                    ))
                    if intro:
                        book.introduction = intro
                        wrote = True
                except Exception as e:
                    log.warning(f"[{book.cnts_id}] 소개글 백필 실패: {e}")

            if not wrote:
                db.rollback()
                failed += 1
                continue
            try:
                db.commit()
                done += 1
            except Exception as e:
                db.rollback()
                log.warning(f"[{book.cnts_id}] 백필 커밋 실패: {e}")
                failed += 1
    finally:
        db.close()

    log.info(f"backfill_summary 완료: done={done}, skipped={skipped}, failed={failed}")
    return {"done": done, "skipped": skipped, "failed": failed}
```

#### `app/tests/test_embed_index_guard.py` (신규)

§2.8 가드 테스트다. 이 파일의 어려움은 테스트 대상이 아니라 **환경**에 있다 — `run_embed_index` 는 `pymilvus`(indexer)·`FlagEmbedding`(embedder)를 함수 최상단에서 무조건 로컬 import 하는데 개발 PC 엔 둘 다 없어서, 가드에 닿기도 전에 `ModuleNotFoundError` 로 죽는다. 그래서 **미설치인 경우에만** 더미를 꽂는다(설치된 환경은 건드리지 않는다). 그리고 더미를 꽂은 경우엔 `services.ingestion.indexer`·`embedder` 모듈 캐시도 함께 비운다 — `monkeypatch` 는 `sys.modules` 의 해당 항목만 원복하지, 이미 캐시된 모듈이 import 시점에 잡아간 전역 바인딩(`pymilvus.Collection` 등)은 되돌리지 않아서 뒤에 도는 테스트가 오염된 Mock 을 물려받는다.

검증의 핵심은 `called == []` 다 — 예외가 났다는 것만으로는 부족하고, **`index_chunks` 가 호출되기 전에** 멈췄어야 한다. 마지막 테스트는 반대 방향으로, abstract 폴백이 있으면 공백뿐인 본문에서도 인덱싱까지 진행하는지 본다.

index_chunks 가 book_id 기준 delete 후 insert 를 돌려 기존 청크가 전멸한다.
"""
import importlib
import sys
from unittest.mock import MagicMock

import pytest

from services.ingestion import stages

def _stub_missing_module(monkeypatch, name: str, cache_clear: tuple[str, ...] = ()) -> None:
    """설치 안 된 모듈만 더미로 꽂는다 — 실제 설치된 환경에서는 건드리지 않는다.

    더미를 꽂은 경우에만 cache_clear 로 지정한 우리 쪽 모듈도 sys.modules 에서
    비운다 — monkeypatch 는 이 모듈 항목 자체만 원복하고, 이미 캐시된
    indexer/embedder 의 전역 바인딩(예: pymilvus.Collection)은 원복하지
    않아 뒤에 도는 다른 테스트가 오염된 Mock 을 물려받을 수 있다.
    """
    try:
        importlib.import_module(name)
    except ModuleNotFoundError:
        monkeypatch.setitem(sys.modules, name, MagicMock())
        for mod in cache_clear:
            monkeypatch.delitem(sys.modules, mod, raising=False)

#### `app/tests/test_backfill_summary.py` (신규)

§2.11 태스크의 분기 로직 테스트다. LLM 생성기와 DB 세션을 목으로 대체한다. 두 가지가 까다롭다.

하나는 `@celery_app.task(...)` 데코레이터다. 가짜 celery 모듈의 `task()` 는 **원본 함수를 그대로 반환**해야 한다 — Task 객체로 감싸면 `backfill_summary(...)` 직접 호출로 실제 로직을 돌릴 수 없다. 다른 하나는 `run_async(coro)` 인데, 이건 진짜 이벤트 루프를 돌리므로 목이 아니라 **진짜 코루틴 함수**여야 한다. 그래서 `_async_mock` 은 `async def` 를 반환하고 호출 기록만 내부 `MagicMock` 에 남긴다.

세션 목(`_make_session`)은 `db.query(Book)` 과 `db.query(BookSection.summary)` 두 체인을 인자 종류로 분기한다. 후보 필터(`or_`) 자체의 SQL 은 실제 DB 없이 검증할 수 없으니 대상으로 삼지 않았다 — `books` 리스트를 그대로 돌려주고, 그 뒤의 파이썬 레벨 분기(요약·테마·소개글 조건)만 검증한다. 첫 테스트가 `themes` 단독 결손 케이스로, 리뷰에서 발견된 그 버그의 회귀 테스트다.
