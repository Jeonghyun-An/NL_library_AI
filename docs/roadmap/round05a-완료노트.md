## 1. 왜 했나

출발점은 UI 고도화 기능 명세서의 **03 논문 상세**와 **S6 끊기지 않는 근거 동선**이다. 딥리서치를 넣으면서 상세의 뒤로 가기와 주소가 꼬였다. 2026-10-01 운영 API 에 붙인 로컬 화면으로 재현한 문제는 일곱 가지다(spec §1).

1. 보고서 인용칩에서 연 상세는 주소가 `/papers/<id>` 뿐이었다. 그래서 돌아가기는 "검색 목록 돌아가기"로 나왔고, 사이드바는 논문 탭으로 바뀌었으며, 탭 제목은 "딥리서치"로 남았다.
2. 연관 논문으로 넘어가면 `q`·`h` 가 빠졌다. 돌아가기는 직전 논문으로 갔고, 검색어 기준 AI 요약이 나오지 않았다.
3. 새 탭으로 연 상세에서는 돌아가기(`$router.back()`)가 갈 곳이 없었다.
4. 메인 논문 탭의 상세 주소에는 `h` 가 없었다. `q` 도 결과 검색어가 아니라 입력창 글자였다.
5. 상세를 오갈 때마다 AI 요약 1개와 연관 이유 스트림 4개를 다시 만들었다.
6. 상세에는 탭 제목이 없었다.
7. 보고서·검색 결과로 돌아오면 맨 위부터 보였다. 내용을 비동기로 다시 그려서, 브라우저의 스크롤 복원이 내용보다 먼저 끝났다.

사용자는 "보던 곳의 위치로까지 그대로" 돌아가기로 정했고, **A안**을 골랐다. 돌아가기·주소·위치 복원을 먼저 하고, 같은 라운드에서 03 화면 나머지와 원문 뷰어까지 한다.

## 6. 결정

- **출처를 상세 주소에 싣는다(D1).** 주소만으로 돌아갈 곳·사이드바 강조·배너·AI 요약 기준이 정해진다. 새 탭·새로고침에도 같다.
- **연관 논문으로 넘어가도 처음 출처를 잇는다(D2).** 몇 편을 넘겨 봐도 [돌아가기]는 처음 화면으로 간다. 직전 논문은 브라우저 뒤로 가기로 간다.
- **돌아가기는 직전 기록이 출처면 `router.back()`, 아니면 push(D3).** 직전이 출처면 브라우저 상태를 그대로 쓴다. 새 탭·직접 진입에도 갈 곳이 있다.
- **위치는 픽셀이 아니라 요소 기준이다(D4).** 배치 A/B 나 창 크기가 바뀌어도 같은 자리다. 즉시 이동이라 "자동 스크롤로 읽는 사람을 끌고 가지 않는다"(round04b spec §7-4)와 부딪히지 않는다. 요소를 못 찾으면 아무것도 하지 않는다.
- **맞춘 뒤 붙잡고, 자리는 그 기록에 남긴다(최종 검토).** 붙잡기는 사용자가 움직이면 놓는다(최대 15초). 주소는 깨끗하게 두고 자리는 `history.state` 에 둔다. 사용자가 움직이면 그 자리도 지운다.
- **출처 없는 옛 주소(`?q=&h=`)는 검색 출처로 읽는다.** 열린 탭·방문 기록·북마크에 남아 있기 때문이다.
- **논문 검색 기록은 건수로 자르지 않는다.** 크기(180KB)로만 줄인다. round04b spec §4-5 에 논문 예외로 적었다.
- **AI 글 캐시는 sessionStorage, 끝까지 받은 글만 담는다(D6).** 만료·용량 관리는 하지 않는다. 탭을 닫으면 사라지고, 용량을 넘으면 캐시 없이 새로 만든다.
- **원문 보기는 늘 원문 뷰어다(S6-4).** 외부 KCI 페이지는 보조 링크로 뺐다.
- **이 논문으로 딥리서치는 자동으로 시작하지 않는다.** 초안을 고쳐 보내게 한다.
- **pdf.js 는 이번에 올리지 않고 설정으로 막았다.** 근본 해결(4.2.67 이상)은 다음으로 미뤘다(§9 ②).
- **백엔드 변경 없음(D9)** — 그래서 배포는 `nl-lib-nuxt` 하나다.

## 7. 작업 중 드러난 것 · 배운 점

1. **여러 세션이 같은 저장소를 쓰면 본 작업 폴더의 브랜치가 바뀐다.** 2026-10-02 11:28 에 누군가 본 작업 폴더에서 checkout 했다. 그 바람에 round05a 가 다른 브랜치에 커밋할 뻔했고, 작업을 `.worktrees/round05a` 로 옮겼다. 본 작업 폴더에서는 브랜치를 바꾸지 않는다.
2. **`frontend/public/pdfjs` 는 gitignore 라 새 worktree 에 없다.** 복사해 넣고 썼다. nuxt 이미지도 pdfjs 가 있는 폴더에서 빌드해야 한다. 없는 폴더에서 빌드하면 원문 뷰어 파일이 이미지에 들어가지 않는다.
3. **미리보기 도구는 저장소 루트의 `.claude/launch.json` 만 읽는다.** 그래서 루트의 frontend 를 띄운다. worktree 화면은 worktree 에서 `NUXT_DEV_API_TARGET=… npx nuxi dev --port 3005` 로 띄워 붙였다.
4. **새 worktree 에서 vitest 는 `.nuxt` 가 생기기 전에는 전부 실패한다.** tsconfig 를 찾지 못하기 때문이다. typecheck 나 build 를 한 번 돌린 뒤 다시 돌린다.
5. **비동기로 다시 그리는 화면은 한 번 맞춰서는 자리가 지켜지지 않는다.** 맞춘 뒤에도 내용이 늦게 움직였다. 검색 기록은 AI 요약을 다시 받아 펼치고 인용 논문을 맨 위로 올렸고, 작성 중 초안은 절이 올라오며 나타났다. 사용자가 움직이기 전까지 붙잡아야 했다.
6. **vue-router 의 `history.state.back` 은 처음 주소를 그대로 들고 있다.** 주소에서 지운 자리는 두 번째로 돌아올 때 없다. 자리를 주소에만 두면 한 번만 돌아온다.
7. **같은 출처로 끼운 뷰어의 취약점은 앱의 취약점이다.** pdf.js 뷰어가 SKOVIX 와 같은 출처라, PDF 가 스크립트를 돌리면 앱의 저장소·세션에 닿는다. 고정본을 들일 때는 버전의 알려진 취약점부터 본다.
8. **화면 확인은 검증 브라우저의 데이터에 달려 있다.** 기록 세션은 브라우저 ID 단위라, 검증 브라우저에 딥리서치 기록이 없으면 보고서 쪽 흐름을 열 수 없다. 이번에는 인용칩 왕복을 보지 못했다. 다음에는 확인 전에 그 브라우저에서 잡 하나를 만들어 둔다.

**새 함정 번호는 더하지 않았다.** 1·3·4 는 개발 환경 쪽이다. 2 는 배포에도 걸리므로, `docs/ops/recurring-gotchas.md` 에 올릴지는 §9 에 남긴다.
