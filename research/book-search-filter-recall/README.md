# 소장자료 검색이 논문을 보이거나 권수가 적은 원인 (2026-10-23)

## 물음

2026-10-23 운영에서 소장자료 검색(`POST /api/books/search`)이 `올리버 트위스트`에 논문(KCI_FI…)만 30편 보였고,
재작성을 끄면 `돈키호테` 1권, `셜록 홈즈 같은 추리소설` 6권만 보였다(research/book-search-title-recall 의 raw — 다른 세션,
`fix/book-search-title-recall` 브랜치). 세운 가설: IVF 인덱스의 필터 검색은 질의에 가까운 nprobe 개 클러스터 안에서만 도서
조건을 거르므로, 그 클러스터가 논문 청크뿐이면 도서가 적거나 0건이 된다. 가정하지 않고 운영 응답으로 확인했다.

## 결론

| 증상 | 원인 | 가설(IVF 필터)과의 관계 |
|---|---|---|
| 도서 대신 논문만 보임 | **LLM 날짜 필터 오작동 + 낡은 재시도.** 재작성을 꺼도 도는 날짜 필터(gemma, `extract_metadata_filter`)가 `올리버`·`올빼미`·`올림픽`의 '올'을 '올해'로 읽어 발행 연도 2026, `82년생 김지영`을 1982 로 걸었다 → 그해 도서가 없어 0권 → 라우트가 doc_scope 를 풀고(옛 인덱스 대비 재시도) **날짜 조건은 그대로** 다시 찾아 그해 논문을 보였다 | 아님 |
| 권수가 적음(1~9권) | **긴 책 한두 권이 후보 창(하이브리드 검색 300청크)을 차지.** 구텐베르크 장편은 청크가 수천 개라 제목 질의의 dense·sparse 상위가 그 책 청크로 찬다. 10건 모두 정답 책이 1위 | 아님 — 창은 꽉 찼다 |
| (가설) 필터 결과가 limit 미달 | 도서 조건만으로는 **관찰되지 않음**(84질의 중 0). 날짜까지 더해 조건이 아주 좁으면 **실제로 일어난다**: `1984`(도서+1984년)는 청크 1개 — 그 해 학위논문 한 편만도 청크가 205개 잡힌다 | 기제는 맞다, 지금 증상의 원인은 아니다 |

논문 검색(`POST /api/papers/search`, 대회 시연 흐름)도 같은 날짜 필터를 써서 `올리버 트위스트`·`올바른 양육 태도`·`올레길 관광`이
30편 모두 2026년 논문이었다. 시연 질의(`노인 사회적 지지와 우울`)와 정상 날짜 표현(`2020년 이후`·`최근 3년`·`작년`)은 맞게 동작했다.

## 측정

`measure.py` — 운영 API 를 화면과 같은 인자(mode book · top_k 10 · rerank 켬)에 재작성만 끄고 부른다. 질의는 앞 세션의
`queries.json`(제목·저자 84개: 한국 문학 41 · 영어 원서 한국어 제목 20 · 영어 제목 10 · 문장 속 제목 8 · 저자 5)에 날짜 필터를
건드릴 만한 질의 14개(probe), 논문 검색 10개(paper)를 더했다. 응답에서 보는 것:

- **논문 폴백**: 응답이 전부 논문 — 도서 0권이라 라우트가 범위를 푼 것.
- **후보 창이 찼나**: 도서 모드는 하이브리드 검색 청크 300개(top_k 10 × 3 × 10)를 책으로 묶고 30권에서 자른다. 30권 미만인데
  청크+메타 청크가 300 미만이면 Milvus 필터 검색이 limit 를 못 채운 것이다(IVF 가설이 직접 드러나는 모양).
- **RRF 순위 역산**: 청크 점수는 Σ 1/(60+rank) 라 한 목록에만 든 청크는 1/점수−60 이 정수다. 같은 정수 순위가 두 번 나오면
  dense·sparse 두 목록 모두 그 순위까지 결과가 있었다(`max_twice_rank` — 짧은 쪽 목록 길이의 하한).
- **연도 분포**: 응답 30권의 발행 연도가 한 해로 몰리면 날짜 필터가 걸린 것이다(LLM 출력은 응답에 없다).

| 논문 폴백 | 1 (`올리버 트위스트`, 30편 모두 2026.01~) |

| 정답 1위 | 한국 문학 41/41 · 영어 원서 한국어 제목 16/20(10위 안 17) · 영어 제목 10/10 · 문장 속 제목 7/8 · 저자 4/5 |

정답을 놓친 셋 중 `올리버 트위스트`는 날짜 필터, `레 미제라블`·`위대한 유산`은 30권 안에도 없다(가설로는 가를 수 없음 — 아래 '남은 것').

probe — 날짜 필터가 걸린 것으로 보이는 것:

| 질의 | 결과 | 걸린 연도(추정) |
|---|---|---|
| 올리버 · 올빼미 · 올림픽 · 올해의 소설 | 논문 폴백, 30편 모두 2026 | 2026 ('올'→'올해') |
| 82년생 김지영 | 논문 폴백, 30편 모두 1982 | 1982 |
| 1930년대 소설 | **빈 응답**(도서 0, 범위를 푼 재시도도 0) | 1930~1939 |
| 1984 | 도서 1권, **청크 1개** | 1984 — 그 책(CNTS-00052063987)은 제목 질의에서 청크 205개가 잡힌다 |
| 트위스트 | 정상, LIT-GUTENBERG-730(올리버 트위스트) 1위 | 없음 |

`1984` 는 IVF 필터 기제가 실제로 일어나는 증거다: 도서+1984년 조건에 맞는 청크가 그 논문 하나로만 205개 이상인데 dense·sparse
결과를 합쳐 청크 1개(+메타 청크)가 왔다. 전수 검색이면 300개를 채웠을 것이다.

## 수정 (`fix/book-search-filter-recall`, 운영 미반영)

저위험 두 가지 — 둘 다 결정적이고 단위 테스트로 묶었다.

1. **날짜 필터 근거 검사** (`app/services/search/metadata_filter.py`): LLM 이 낸 연도 가운데 질의 글자에 근거가 없는 것을 버린다.
   근거 = 4자리 연도 그대로(`2020년 이후`·`1984`), `YYYY년대`, `올해`, `작년`/`지난해`, `재작년`, `최근 N년`(프롬프트 규칙이 연도를
   만드는 표현). 정렬(`sort_by`)은 그대로 둔다. 조건을 빼기만 하고 켜지는 않는다. 소장자료·논문·상황별 추천 검색이 함께 쓴다.
2. **0권 재시도는 도서 안에서** (`app/api/book.py`, `app/api/scenario.py`): 도서 0권이면 `doc_scope` 를 풀지 않고 날짜 조건만 빼고
   (`use_metadata_filter=False`) 다시 찾는다. `doc_type` 은 컬렉션 필수 필드(`indexer._CORE_SCALAR`)이고 빈 값도 도서 조건을
   통과해, 옛 인덱스 대비 재시도는 할 일이 없었다.

## 수정 효과 — 배포 전에 말할 수 있는 것

운영 LLM·Milvus 에 고친 코드를 돌려 볼 수 없어(관리 API 차단, Milvus 포트 미노출, 운영 변경 금지) 결과 목록 자체의 전후 비교는
배포 뒤에 `measure.py` 를 다시 돌려야 한다. 배포 전에 확인한 것:

- 근거 검사는 결정적이다. 관찰한 오작동에 추정 연도를 넣어 돌리면 `올리버 트위스트`·`올리버`·`올빼미`·`올림픽`·`82년생 김지영`·
  `올바른 양육 태도`·`올레길 관광`의 연도는 버리고, `올해의 소설`·`1930년대 소설`·`1984`·`2020년 이후 …`·`작년 …` 은 남긴다.
- 그래서 배포 뒤 기대: 위 '올'·'82년생' 질의는 날짜 조건 없이 검색된다. 날짜 조건이 걸린 채 0권이 되는 질의(`1930년대 소설`,
  `올해의 소설`)는 도서 안에서 날짜 없이 다시 찾아 논문·빈 응답 대신 도서를 보인다. 어느 경우에도 소장자료 검색에 논문이 나오지 않는다.
  `트위스트` 가 날짜 조건 없이 올리버 트위스트를 1위로 찾으므로 `올리버 트위스트` 도 찾을 가능성이 높지만 배포 전에는 확인할 수 없다.
- 바뀌지 않는 것: `1984` 처럼 근거 있는 연도로 좁힌 검색의 IVF 부족(1권이라도 나오면 재시도하지 않는다), 긴 책의 창 포화.
- 비용: 재시도는 0권일 때만 돈다(예전과 같은 조건·같은 횟수).

## 남은 것 — 대회 뒤

- **IVF 필터 재현율 측정**: `nprobe_sweep.py` — FastAPI 컨테이너 안에서 운영 컬렉션을 **읽기만** 하며 dense 검색을 nprobe 100(지금)·
  256·1024 와 nlist(전수)로 돌려 겹침·결과 수·지연을 잰다. 도서 조건(제목 질의 21), 도서+연도(4), DeepRead 조건(`book_id == X`,
  limit 6·30) 세 가지와 컬렉션·도서 청크 수를 낸다. BGE-M3 는 CPU 로 올린다. 시연이 없는 시간에:

  ```
  docker cp nprobe_sweep.py nl-lib-fastapi:/tmp/nprobe_sweep.py
  docker exec -w /app nl-lib-fastapi python /tmp/nprobe_sweep.py > sweep.json
  ```

  재현율이 낮으면 후보: 필터가 있는 검색만 nprobe 를 키우기(요청별 param — 인덱스 그대로), 도서·논문 파티션 키로 컬렉션 나누기(재적재).
- **후보 창 포화**: 책마다 청크 수를 묶어 창을 나누거나(group by) 창을 키우기 — 순위·지연이 바뀌므로 평가 뒤에.
- `레 미제라블`·`위대한 유산`(한국어 제목 → 영어 원서) 놓침이 IVF 탓인지 임베딩 탓인지는 `nprobe_sweep.py` 의 전수 순위로 가린다.
- 날짜 프롬프트 자체(`metadata_filter.yaml`)는 고치지 않았다 — '초기 근대소설'의 '초기'를 오래된 순 정렬로 읽는 것처럼 규칙대로지만
  주제어를 정렬로 바꾸는 경우가 남는다.

## 파일

- `measure.py` — 운영 API 측정(`raw/<번호>.json`, `--tally` → `tally.json`)
- `queries.json` — 앞 세션(`research/book-search-title-recall`)의 제목·저자 질의 그대로
- `nprobe_sweep.py` — 서버 안에서 돌리는 읽기 전용 nprobe 측정(아직 돌리지 않음)
