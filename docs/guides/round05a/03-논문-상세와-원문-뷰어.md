### 2.17 `utils/paperDetail.ts` — 인용 맥락 배너·AI 요약 기준 질문·조사

**책임.** 보고서에서 온 상세의 배너 글(`citeContext`), AI 요약의 기준 질문(`summaryQuestion`), 배너의 "김 2019**로**"·"김 2020**으로**" 조사(`withRo`).

**왜 이렇게 짰나.**

- **배너는 근거 번호가 이 논문의 것일 때만 낸다.** `e` 는 주소의 값이다. `report.evidence[e].cnts_id` 가 지금 논문과 같은지 확인하지 않으면, 주소의 `e` 를 고쳐 쓰는 것만으로 다른 논문의 인용 대목을 이 논문 것처럼 보이게 된다. 보고서가 아직 없으면(작성 중) 배너도 없다.
- **질문은 `report.question || job.question`.** 보고서의 질문이 정본이고, 없으면 잡을 만들 때의 질문이다.
- **인용 대목은 쪽 순, 쪽 정보가 없는 대목은 빼지 않고 뒤에.** 첫 대목이 첫 인용 쪽이라 [인용 대목 보기]가 그 쪽에서 원문 뷰어를 연다. 쪽 정보가 없는 대목(`pdfPage` 가 `undefined` — `page_start` 가 0 이하)을 빼면 배너의 "인용 대목 N곳"과 뷰어의 "인용 대목 n/N"이 다른 수를 센다. 처음 계약의 `passages: { page }[]` 를 `chunks`(쪽 순 전체)로 바꾼 까닭이다(plan "처음 계약에서 바뀐 것"). 정렬은 복사본(`[...evidence.chunks]`)으로 한다 — API 응답 객체를 고치지 않는다.
- **AI 요약 기준 질문.** 검색에서 왔으면 결과의 검색어(`q`), 보고서에서 왔으면 보고서 질문(작성 중이면 잡 질문), 그 밖에는 빈 문자열이다. 빈 문자열이면 요약을 만들지 않고 소개글을 보인다 — 질문 없이 만든 "요약"은 이 논문이 왜 여기 있는지 말하지 못한다.
- **`withRo` — 받침으로 '로/으로'.** 끝 글자가 한글이면 `(코드 − 0xAC00) % 28` 로 종성을 보고, 받침이 없거나 ㄹ 이면 '로', 그 밖이면 '으로'다. 인용 표기는 "김 2019" 처럼 숫자로 끝나는 일이 많아 **숫자는 읽는 소리로** 가린다 — 끝자리 0(십·백·천)·3(삼)·6(육)만 ㄹ 이 아닌 받침이 있다(1 일·7 칠·8 팔은 ㄹ, 2·4·5·9 는 받침이 없다). 영문 성(`Smith`)은 받침을 알 수 없어 '로'로 둔다. 백엔드의 조사 고르기(round04c `hangul.py`)와 같은 생각이지만, 화면에서 이 한 조사만 쓰므로 작은 함수로 뒀다.

```ts
// frontend/utils/paperDetail.ts
import type { ReportChunk, ResearchJob } from "~/types/research";
import { citeLabel, pdfPage } from "./citations";
import type { DetailSource } from "./detailSource";

type JobText = Pick<ResearchJob, "question" | "report">;

export interface CiteContext {
  question: string;
  label: string;
  // 인용 대목 — 쪽 순이라 첫 대목이 첫 인용 쪽이다. 쪽 정보가 없는 대목도 빼지 않고 뒤에 둔다 —
  // 배너의 "인용 대목 N곳"과 원문 뷰어의 "n/N"이 같은 수를 센다
  chunks: ReportChunk[];
}

// 쪽 정보가 없는 대목(pdfPage 가 undefined)을 맨 뒤로 보내는 정렬 값
const NO_PAGE = Number.MAX_SAFE_INTEGER;

// 보고서에서 온 상세의 인용 맥락 배너. 보고서가 아직 없거나(작성 중) 근거 번호가 이 논문의 것이 아니면 내지 않는다 —
// 주소의 e 를 고쳐 쓰면 다른 논문의 대목을 이 논문 것처럼 보이게 된다
export function citeContext(job: JobText, eid: string | null, cntsId: string): CiteContext | null {
  if (!eid || !job.report) return null;
  const evidence = job.report.evidence[eid];
  if (!evidence || evidence.cnts_id !== cntsId) return null;
  return {
    question: job.report.question || job.question,
    label: citeLabel(evidence.meta, eid),
    chunks: [...evidence.chunks].sort((a, b) => (pdfPage(a) ?? NO_PAGE) - (pdfPage(b) ?? NO_PAGE)),
  };
}

// AI 요약의 기준 질문 — 검색에서 왔으면 결과의 검색어, 보고서에서 왔으면 보고서 질문(작성 중이면 잡 질문).
// 빈 문자열이면 요약을 만들지 않고 소개글을 보인다
export function summaryQuestion(source: DetailSource, job: JobText | null): string {
  if (source.kind === "search") return source.q;
  if (source.kind === "research" && job) return job.report?.question || job.question;
  return "";
}

// "김 2019로"·"김 2020으로" — 끝 글자에 받침이 있으면(ㄹ 제외) "으로". 숫자는 읽는 소리로 가린다(0 십·백·천, 3 삼, 6 육).
// 한글·숫자가 아니면(영문 성) 받침을 알 수 없어 "로"로 둔다
const DIGIT_BATCHIM = new Set(["0", "3", "6"]);
const HANGUL_FIRST = 0xac00;
const HANGUL_LAST = 0xd7a3;
const RIEUL = 8;

function needsEuro(ch: string): boolean {
  if (DIGIT_BATCHIM.has(ch)) return true;
  const code = ch.charCodeAt(0);
  if (code < HANGUL_FIRST || code > HANGUL_LAST) return false;
  const jong = (code - HANGUL_FIRST) % 28;
  return jong !== 0 && jong !== RIEUL;
}

export function withRo(word: string): string {
  return `${word}${needsEuro(word.slice(-1)) ? "으로" : "로"}`;
}
```

### 2.18 `utils/aiCache.ts` · `utils/browserId.ts` — AI 글 탭 캐시

**책임.** 상세의 AI 요약·연관 이유를 탭 안에서 다시 쓴다(D6). 상세 → 다른 화면 → 뒤로 올 때마다 AI 요약 1개와 연관 이유 4개를 GPU 로 다시 만들던 것(00 §1-1 의 5번)을 막는다.

**왜 이렇게 짰나.**

- **키.** AI 요약은 `skx:ai:summary:<논문>:<기준 질문>` — 같은 논문이라도 검색어·보고서 질문이 다르면 다른 요약이다. 연관 이유는 `skx:ai:related:<논문>:<연관 논문>` — 방향이 있다(A 에서 본 B 와의 유사점). 접두가 달라 요약과 연관 이유가 섞이지 않는다.
- **sessionStorage.** 문제는 "오갈 때 재생성"이라 탭 범위면 된다. 탭을 닫으면 사라져 모델·데이터가 바뀐 뒤에도 낡은 글이 오래 남지 않는다.
- **담지 않는 글이 둘이다.** (1) 빈 글. (2) **서버의 생성 실패 문구** — `services/search/paper_summary.py` 는 생성이 실패하면 "요약 생성 중 오류가 발생했습니다." 같은 글을 보통 글처럼 보내고 스트림을 정상으로 닫는다. 담아 두면 탭을 닫을 때까지 실패 문구만 다시 보인다(`FAILED_TAIL`). 그리고 상세는 **`[DONE]` 까지 받은 글만** 넘긴다 — `readSSE` 가 `[DONE]` 을 받았을 때만 `true` 를 돌려주고(§2.20), 페이지를 떠나 끊긴 스트림·네트워크로 끊긴 글은 반쪽이라 담지 않는다.
- **막힌 저장소·용량 초과는 조용히 넘긴다.** 캐시는 덤이다 — 없으면 새로 만들 뿐이다. 읽기도 `try` 로 감싼다(쿠키·사이트 데이터를 막은 브라우저에서는 저장소 접근이 `SecurityError` 를 던진다).
- **`safeSessionStorage()`** — 서버 렌더(`window` 없음)·막힌 저장소에서 `null`. 같은 파일의 `safeLocalStorage` 와 같은 모양이다.

// 논문 상세의 AI 요약·연관 이유를 탭 안에서 다시 쓴다 — 상세를 오갈 때마다 같은 글을 GPU 로 다시 만들지 않게.
// sessionStorage 라 탭을 닫으면 사라진다. 막힌 저장소·용량 초과는 캐시 없이 새로 만들 뿐이다
const PREFIX = "skx:ai:";
// 서버(services/search/paper_summary)는 생성 실패를 글로 보내고 스트림을 정상으로 닫는다 —
// 담아 두면 탭을 닫을 때까지 실패 문구만 다시 보인다
const FAILED_TAIL = /오류가 발생했습니다\.?\s*$/;

export function summaryCacheKey(paperId: string, question: string): string {
  return `${PREFIX}summary:${paperId}:${question}`;
}

export function relatedCacheKey(paperId: string, relatedId: string): string {
  return `${PREFIX}related:${paperId}:${relatedId}`;
}

export function readAiCache(storage: Storage | null, key: string): string | null {
  try {
    return storage?.getItem(key) || null;
  } catch {
    return null;
  }
}

export function writeAiCache(storage: Storage | null, key: string, text: string): void {
  if (!text.trim() || FAILED_TAIL.test(text)) return;
  try {
    storage?.setItem(key, text);
  } catch {
    // 용량 초과·막힌 저장소 — 다음에 다시 만든다
  }
}

### 2.19 `utils/paperResearch.ts` · `SearchPlusMenu.vue` — 이 논문으로 딥리서치(⑧)

**책임.** 상세의 [이 논문으로 딥리서치]가 제목·키워드로 질문 초안을 만들어 논문 검색 입력창으로 넘긴다. `/papers?draft=<초안>` 으로 가면 논문 검색이 **검색하지 않고** 랜딩 입력창에 딥리서치 칩을 켠 채 초안을 채운다.

**왜 이렇게 짰나.**

- **바로 시작하지 않는다.** 딥리서치 한 번은 분 단위의 시간과 GPU 를 쓰고, 기계가 만든 초안은 사용자의 관심과 다를 수 있다. 고쳐 쓰고 보내게 초점을 글 끝에 둔다. round04c 의 랜딩 예시 질의를 "입력창에만 채운다"로 바꾼 것(`2d8320d`)과 같은 원칙이다.
- **조사를 피한 틀.** "「제목」에서 출발해, 키워드1·키워드2·키워드3 관련 선행 연구는 어떻게 전개되어 왔고 주요 쟁점과 남은 과제는 무엇인가?" — 제목·키워드 바로 뒤에 받침에 따라 바뀌는 조사(을/를·와/과)를 붙이지 않는다. 키워드가 없으면 "이 주제의"다.
- **자르기.** 제목 120자·키워드 30자·키워드 3개. 부제까지 붙은 긴 제목이나 문장형 키워드가 질문을 다 차지하지 않게 하고 서버 질문 한도(500자) 안에 둔다(테스트가 `questionProblem` 으로 확인한다). **코드포인트로 센다** — UTF-16 단위로 자르면 이모지 같은 보충 문자가 반쪽으로 잘린다. 공백·줄바꿈은 제목·키워드 모두 한 칸으로 줄인다(`ec10ec7`).
- **`activateMode` 를 노출한다**(`SearchPlusMenu`). 페이지가 칩을 켠 채 입력창을 채울 길이 없었다. 켜고 초점을 글 끝에 둔다.
- **`/papers` 는 채운 뒤 주소에서 `draft` 만 뗀다**(§2.16 의 `fillResearchDraft`). 남겨 두면 새로고침·뒤로 가기로 올 때마다 고쳐 쓰던 글을 초안이 다시 덮는다. 다른 쿼리는 지우지 않는다(`ec10ec7` 에서 고친 것 — 처음은 쿼리를 통째로 비웠다). 입력창 값이 바뀐 뒤(`nextTick`) 칩을 켜야 초점이 글 끝에 간다.
- **초안 읽기는 `firstValue`**(01 §2.1) — 배열이면 첫 값, 빈 값이면 없음.

// frontend/utils/paperResearch.ts
// 논문 상세의 [이 논문으로 딥리서치] — 제목·키워드로 질문 초안을 만들어 논문 검색 입력창으로 넘긴다
import { firstValue } from "~/utils/detailSource";

// 부제까지 붙은 긴 제목이나 문장형 키워드가 질문을 다 차지하지 않게 자른다(서버 한도 QUESTION_MAX 500자 안쪽)
const TITLE_MAX = 120;
const KEYWORD_MAX = 30;
const KEYWORDS = 3;

// 코드포인트로 센다 — UTF-16 단위로 자르면 이모지 같은 보충 문자가 반쪽으로 잘린다
function clip(text: string, max: number): string {
  const chars = [...text];
  return chars.length > max ? `${chars.slice(0, max).join("")}…` : text;
}

// 조사(을/를·와/과)는 앞 글자의 받침에 따라 바뀐다 — 제목·키워드 바로 뒤에는 받침과 무관한 말만 붙인다
export function paperResearchQuestion(title: string, keywords: readonly string[]): string {
  const name = title.trim().replace(/\s+/g, " ");
  if (!name) return "";
  const picked = keywords
    .map((k) => k.trim().replace(/\s+/g, " "))
    .filter(Boolean)
    .slice(0, KEYWORDS)
    .map((k) => clip(k, KEYWORD_MAX));
  const topic = picked.length ? `${picked.join("·")} 관련` : "이 주제의";
  return `「${clip(name, TITLE_MAX)}」에서 출발해, ${topic} 선행 연구는 어떻게 전개되어 왔고 주요 쟁점과 남은 과제는 무엇인가?`;
}

export function paperResearchUrl(question: string): string {
  return `/papers?${new URLSearchParams({ draft: question })}`;
}

// /papers 가 받는 질문 초안(?draft=). 없거나 빈 값이면 null
export function readResearchDraft(query: Record<string, unknown>): string | null {
  return firstValue(query.draft) ?? null;
}

### 2.20 `pages/papers/[id].vue` — 논문 상세 화면

### 2.22 `utils/pdfViewer.ts` — 원문 뷰어의 판단을 DOM 없이

**책임.** 원문 뷰어(`PdfViewer.vue`)가 하는 판단 — pdf.js 앱·설정 읽기, 보안 설정, Esc 를 누가 처리할지, 인용 대목 목록, 닫을 때 초점을 돌려줄 곳, 열기 전 확인 요청 — 을 순수 함수로 모은다(plan Task 10).

**왜 이렇게 짰나.**

- **pdf.js 의 앱 객체는 쓰는 부분만 타입으로 적는다**(`PdfJsApp`). 뷰어는 `public/pdfjs`(4.0.379 고정본)의 `/pdfjs/web/viewer.html` 이라 앱과 같은 출처이고, iframe 창의 `PDFViewerApplication` 을 바로 읽는다. 내부 API 라 없거나 바뀌면 `null` 로 받고 화면은 쪽 표시만 숨긴다(spec §10).
- **보안 설정(`hardenPdfViewerOptions`, `8538441`).** 뷰어가 SKOVIX 와 같은 출처라, PDF 가 스크립트를 돌리면 앱의 저장소·세션에 닿는다. pdf.js 4.2.67 전에는 글꼴 글리프를 `eval` 로 컴파일해 조작한 글꼴이 임의 스크립트를 돌린다(CVE-2024-4367). 셋을 준다.
  - `isEvalSupported = false` — eval 을 끄면 같은 글리프를 해석해 그린다.
  - `externalLinkTarget = 2`(`LinkTarget.BLANK`) — 끼운 뷰어는 PDF 안의 외부 링크를 `_top` 으로 열어 SKOVIX 탭을 통째로 떠난다. 새 탭으로 연다(rel 은 pdf.js 기본 `noopener`).
  - `disablePreferences = true` — 링크 대상은 사용자 설정 항목이라 `run()` 이 저장된 설정의 값(기본 0 → 끼우면 `_top`)으로 덮어쓴다. 설정 읽기를 꺼야 위 값이 남는다. 이 판의 뷰어는 설정을 쓰지 않고 설정 기본값도 앱 기본값과 같아 다른 동작은 바뀌지 않는다.
- **Esc 를 pdf.js 에 맡길 때**(`viewerOwnsEscape`). 찾기 막대·보조 도구 줄·pdf.js 대화상자가 열려 있으면 pdf.js 의 Esc 는 그것부터 닫는다 — 이때 뷰어까지 닫으면 한 번 눌러 둘이 닫힌다. 주석 도구(글상자·펜 등)를 켠 동안(`annotationEditorMode > 0`)도 Esc 는 편집을 끝내는 키다(`f383bc5` — 편집 중에 뷰어가 닫혔다). 그때 뷰어를 닫으려면 ✕ 를 누르거나 도구를 끈다. 앱을 못 읽으면 뷰어가 닫는다.
- **인용 대목**(`citedPassages`·`citedPdfTarget`). 쪽 번호는 `utils/citations.ts` 의 `pdfPage` 한 규칙이다(spec §6). 첫 대목의 쪽에서 열고, 첫 대목에 쪽이 없으면 첫 쪽에서 연다.
- **초점 되돌릴 곳**(`focusReturnTarget`). 뷰어를 연 순간의 초점 요소부터 위로 올라간 조상들을 받는다. 연 버튼이 남아 있으면 그 버튼, 사라졌으면 **아직 문서에 남은 가장 가까운 조상 안의 첫 초점 요소**다. 딥리서치 인용 팝오버의 [원문 보기]가 그 경우다 — 초점이 뷰어로 옮겨 가면 팝오버가 닫히며 그 버튼도 빠진다. 그 조상(칩 묶음) 안의 첫 초점 요소가 그 인용칩이라, 닫으면 칩으로 돌아온다.
- **열기 전 확인 요청**(`pdfStatus`). 상태 코드만 필요하다. `finally` 에서 요청을 끊어 PDF 본문을 받지 않는다 — 뷰어가 다시 받으므로 끊지 않으면 두 번 내려받는다. **10초 제한**(`f383bc5`) — 확인 요청이 멈추면(백엔드가 객체 저장소를 기다리는 등) 확인 중에는 클릭을 무시하므로 원문 보기 버튼이 영영 먹지 않는다. 시간이 지나면 끊고 `null`(판단을 뷰어에 맡긴다). `fetchFn` 을 인자로 받아 테스트가 가짜 `fetch` 를 넣는다.

export async function pdfStatus(
  url: string,
  headers: Record<string, string>,

): Promise<number | null> {
  const ctrl = new AbortController();
  const timer = setTimeout(() => ctrl.abort(), PDF_CHECK_TIMEOUT_MS);

    ctrl.abort();
  }
}

**책임.** 원문을 열기 전에 파일이 있는지 묻고, 있으면 뷰어 상태(`pdf`)에 열 대상을 넣는다(S6-6). 딥리서치 화면과 논문 상세가 같이 쓴다.

import type { OpenPdfPayload } from "~/types/research";
import { pdfStatus } from "~/utils/pdfViewer";
import { pdfCheckProblem } from "~/utils/researchErrors";
import { apiHeaders, apiUrl } from "./useApi";

// 원문 뷰어를 열기 전에 파일이 있는지 먼저 묻는다 — 없는 원문을 그대로 열면 pdf.js 의 영문 오류 화면이 뜬다.
// 알릴 문구는 돌려주기만 하고 어디에 보일지는 화면이 정한다(딥리서치는 토스트, 논문 상세는 누른 버튼 옆)
export function usePdfOpener() {
  const pdf = ref<OpenPdfPayload | null>(null);
  const checking = ref(false);

  async function openPdf(target: OpenPdfPayload): Promise<string | null> {
    // 확인이 끝나기 전에 또 누르면 무시한다 — 뷰어가 두 번 열리거나 문구가 뒤섞이지 않게
    if (checking.value) return null;
    checking.value = true;
    try {
      const problem = pdfCheckProblem(await pdfStatus(apiUrl(`/books/${encodeURIComponent(target.cntsId)}/pdf`), apiHeaders()));
      if (!problem) pdf.value = target;
      return problem;
    } finally {
      checking.value = false;
    }
  }

    pdf.value = null;
  }

  return { pdf, checking, openPdf, closePdf };
}

### 2.24 `components/PdfViewer.vue` — 머리·Esc·초점·배경 고정·보안 설정

**책임.** 원문 뷰어 모달. `<Teleport to="body">` 로 그려 `#__nuxt` 밖에 있다. 이 라운드가 더한 것이다.

- **대화상자 의미** — `role="dialog"`·`aria-modal="true"`·`aria-label="원문 보기: <제목>"`, iframe 에 `title`. 열리면 닫기 버튼으로 초점을 옮긴다.
- **머리의 쪽 표시와 넘기기** — pdf.js 가 알려 주는 지금 쪽(`currentPage`)·전체 쪽(`total`). 전체가 0 이면(문서를 받기 전·내부 API 변경) 쪽 표시만 숨기고 뷰어는 그대로 쓴다. 넘기기는 round04b 의 `stepChunk`(0부터 세는 칸을 끝에서 멈추게 넘긴다)를 쪽에 맞춰 하나 빼고 넘긴다. 지금 쪽 상태는 처음 쪽 prop(`page`)과 헷갈리지 않게 `currentPage` 라 이름 붙였다(`9468756`).
- **인용 대목 넘기기** — `passages` 를 받았을 때만 "인용 대목 n/N · p.x" 와 ‹ › 를 보인다. 대목을 넘기면 그 쪽으로 간다. **끝에서 흐려진 버튼은 아무것도 하지 않는다**(`9468756`) — 다른 쪽을 보던 뷰어가 지금 대목의 쪽으로 되돌아가지 않게. 대목 표시는 `aria-live="polite"`.
- **넘기기 버튼은 `aria-disabled`** — `disabled` 면 마지막 쪽에서 › 를 누른 순간 그 버튼이 초점을 잃는다. `aria-disabled` 는 초점을 지키고 스크린리더에 "사용할 수 없음"을 알린다. 눌러도 `stepChunk` 가 끝에서 멈추므로 아무 일도 없다.
- **보안 설정** — pdf.js 는 `run()` 바로 앞에 부모 문서로 `webviewerloaded` 를 보낸다(`detail.source` = 뷰어 창). 이 듣기에서 바꾼 설정이 그 실행에 쓰이므로, 여기서 `hardenPdfViewerOptions` 를 부른다. **iframe 이 뷰어를 읽기 시작하기 전에** 들어야 해서 `onBeforeMount` 에서 붙인다(iframe 은 마운트에서 문서에 붙으며 로드를 시작한다). 이벤트는 뷰어 창에서 만든 것이라 `instanceof CustomEvent` 로 가리지 않고(창마다 생성자가 다르다) `detail.source` 가 **이 뷰어의 iframe 창**인지만 본다.
- **Esc** — 초점이 뷰어 안(iframe)에 있으면 키 입력이 부모 문서까지 오지 않는다. 그래서 iframe 창에도 `keydown` 을 **캡처로** 붙인다 — 캡처라야 pdf.js 가 Esc 로 찾기 막대를 닫기 **전에** 열려 있었는지 볼 수 있다(`viewerOwnsEscape`). 초점이 머리(부모 문서)에 있을 때는 문서의 `keydown` 이 닫는다. iframe 은 로드마다 새 창이라 듣기도 `@load` 마다 붙인다.
- **쪽 동기화** — `initializedPromise` 를 기다린 뒤 `eventBus` 의 `pagesinit`·`pagechanging` 을 듣는다. 듣기를 붙이기 전에 문서가 이미 열렸을 수 있어 `pagesCount > 0` 이면 바로 맞춘다.
- **배경 고정**(`lockPage`) — 열려 있는 동안 `#__nuxt` 에 `inert`(초점·클릭을 받지 않아 Tab 이 뷰어 밖으로 새지 않는다), 문서 `overflow: hidden`(겹친 화면을 굴려도 읽던 자리가 그대로). 스크롤바가 있던 화면은 `scrollbar-gutter: stable` 로 그 자리를 남겨 배경이 옆으로 밀리지 않게 한다 — 스크롤바 유무는 `overflow` 를 바꾸기 전에 잰다.
- **초점 되돌리기** — 마운트 때 연 순간의 초점 요소부터 조상들을 모으고(`returnPath`), 닫을 때 `focusReturnTarget(returnPath)?.focus({ preventScroll: true })`. 모으는 것은 `lockPage` 로 `inert` 를 걸기 **전**이다(inert 가 걸리면 그 안의 초점은 풀린다). `preventScroll` — 배경은 그대로 있으니 돌려준 초점 때문에 화면이 움직이지 않게.
- **스타일** — 흐린 버튼(`[aria-disabled="true"]`), `:focus-visible` 윤곽선, 640px 아래에서는 제목이 한 줄을 차지하고 넘기기·닫기가 다음 줄로, `prefers-reduced-motion` 이면 전환을 끈다.

**리뷰에서 바뀐 점.** 머리·Esc·초점·배경 고정은 `6272348`(Task 11), 끝에서 흐린 버튼·`currentPage` 는 `9468756`(Task 11 품질 검토), `webviewerloaded`·보안 설정은 `8538441`(최종 검토)이다. 이 컴포넌트의 판단(Esc·초점·대목·보안 설정)은 모두 §2.22 의 함수라 거기서 테스트된다. 화면 확인에서 쪽 표시·Esc·초점·`inert`·보안 설정을 봤다(00 §3-4).

## 면접 Q&A (03 — 논문 상세와 원문 뷰어)

**Q1. SSE 로 받은 AI 글을 캐시할 때 무엇을 담지 않나? 왜 sessionStorage 인가?**
A. 셋을 담지 않는다. (1) **끝까지 받지 못한 글** — `readSSE` 가 `[DONE]` 을 받았을 때만 `true` 를 돌려주고 그때만 쓴다. 페이지를 떠나 스트림을 끊었거나(`pageAbort`) 네트워크가 끊긴 글은 반쪽이라, 담으면 다음에 반쪽 요약을 완성본처럼 보인다. (2) **서버의 생성 실패 문구** — 서버는 생성이 실패해도 "…오류가 발생했습니다." 를 보통 글처럼 보내고 `[DONE]` 으로 정상 종료한다. 끝까지 받았다는 것만으로는 성공을 모르므로 끝 문구로 거른다. (3) **빈 글**. 키는 논문 + 기준 질문(요약), 두 논문(연관 이유 — 방향이 있다)이다. sessionStorage 인 것은 문제가 "상세를 오갈 때마다 재생성"이라 탭 범위면 충분하고, 탭을 닫으면 사라져 낡은 생성 글이 오래 남지 않기 때문이다. 막힌 저장소·용량 초과는 조용히 넘긴다 — 캐시는 덤이고, 없으면 새로 만들 뿐이다. (§2.18·§2.20)

**Q2. 인용 맥락 배너는 주소의 `e` 를 왜 그대로 믿지 않나? 인용 대목은 왜 그 순서인가?**
A. `e` 는 주소의 값이라 누구나 고칠 수 있다. 보고서의 `evidence[e]` 를 그대로 쓰면 `e` 만 바꿔 다른 논문의 인용 대목을 이 논문 것처럼 보이게 된다. 그래서 그 근거의 `cnts_id` 가 지금 논문과 같을 때만 배너를 낸다. 보고서가 아직 없거나 보고서를 못 읽어도 배너가 없고, 논문을 못 읽어도 그리지 않는다(빈 화면에 배너만 남았다). 대목은 쪽 순이라 첫 대목이 첫 인용 쪽이고, [인용 대목 보기]가 그 쪽에서 연다. 쪽 정보가 없는 대목은 빼지 않고 뒤에 둔다 — 빼면 배너의 "N곳"과 뷰어의 "n/N"이 다른 수를 센다. 처음 계약은 쪽 있는 대목만의 목록이었는데 조립 때 이 이유로 바꿨다. (§2.17)

**Q3. 원문 뷰어가 앱과 같은 출처의 iframe 이라는 것의 위험은 무엇이고, 어떻게 막았나? 남은 구멍은?**
A. 같은 출처면 iframe 안의 스크립트가 부모 창과 같은 저장소·쿠키·세션에 닿는다. 우리가 쪽 표시를 위해 iframe 의 `PDFViewerApplication` 을 직접 읽을 수 있는 것도 같은 출처라서다. 그런데 고정본 pdf.js 4.0.379 는 CVE-2024-4367 범위다 — 글꼴 글리프를 `eval` 로 컴파일해, 조작한 글꼴이 든 PDF 를 열면 임의 스크립트가 돈다(4.2.67 에서 수정). 그래서 뷰어가 `run()` 직전 부모 문서에 보내는 `webviewerloaded` 에서 `isEvalSupported=false` 로 끈다 — 글리프를 해석해 그리므로 화면은 같다. 같은 자리에서 PDF 안의 외부 링크를 새 탭으로 열게 하고(끼운 뷰어의 기본은 `_top` 이라 SKOVIX 탭이 넘어갔다), 저장된 설정이 그 값을 덮어쓰므로 설정 읽기도 끈다. 이벤트는 이 뷰어의 iframe 창이 보낸 것만 받는다. 남은 구멍은 **iframe 없이** `/pdfjs/web/viewer.html?file=…` 을 주소로 바로 여는 경우다 — 부모가 없어 이 설정이 걸리지 않는다. 근본 해결은 pdf.js 를 4.2.67 이상으로 올리는 것이고 다음 라운드로 넘겼다. (§2.22·§2.24, 00 §3-6)

**Q4. Esc 는 어떻게 다루나? iframe 안에 초점이 있을 때, pdf.js 의 찾기 막대·주석 도구가 열려 있을 때는?**
A. 초점이 iframe 안에 있으면 키 이벤트는 iframe 의 문서에서 끝나고 부모 문서로 오지 않는다. 그래서 부모 문서의 `keydown`(초점이 머리에 있을 때)과 **iframe 창의 `keydown`** 을 둘 다 듣는다. iframe 쪽은 로드마다 새 창이라 `@load` 마다 붙이고, **캡처 단계**로 듣는다 — pdf.js 의 Esc 처리는 찾기 막대를 닫는데, 버블 단계에서 들으면 이미 닫힌 뒤라 "열려 있었는지"를 알 수 없다. 찾기 막대·보조 도구 줄·pdf.js 대화상자가 열려 있으면 Esc 를 pdf.js 에 맡긴다 — 한 번 눌러 둘이 닫히지 않게. 주석 도구가 켜져 있을 때도 맡긴다. 편집을 끝내는 키라, 처음 구현은 글상자를 쓰다가 Esc 로 뷰어가 통째로 닫혔다(품질 검토 `f383bc5`). 판단은 `viewerOwnsEscape` 한 함수라 넷의 경우를 테스트로 고정했다. (§2.22·§2.24)

**Q5. 뷰어를 닫을 때 초점은 어디로 돌려주나? 연 버튼이 사라졌으면? 배경은 어떻게 묶나?**
A. 연 순간의 초점 요소부터 조상들을 모아 두고, 닫을 때 그중 아직 문서에 남은 가장 가까운 것을 찾는다. 그것이 초점을 받을 수 있으면(연 버튼) 그것, 아니면 그 안의 첫 초점 요소다. 딥리서치 인용 팝오버의 [원문 보기]는 초점이 뷰어로 옮겨 가는 순간 팝오버가 닫히며 사라지므로, 남은 조상(칩 묶음) 안의 첫 초점 요소인 그 인용칩으로 돌아온다 — 키보드 사용자는 제자리를 잃지 않는다. `preventScroll` 로 돌려줘 배경이 움직이지 않는다. 배경은 열려 있는 동안 `#__nuxt` 에 `inert` 를 걸어(뷰어는 `body` 로 텔레포트돼 밖에 있다) Tab 이 새지 않게 하고, 문서 `overflow: hidden` 으로 스크롤을 묶어 읽던 자리를 지킨다. 스크롤바가 있던 화면은 `scrollbar-gutter: stable` 로 그 자리를 남겨 배경이 옆으로 밀리지 않게 한다. 초점 경로는 `inert` 를 걸기 전에 모은다. (§2.22·§2.24)

**Q6. 원문을 열기 전에 왜 확인하나? 확인이 멈추면? 본문은 왜 끊나?**
A. 원문이 없는 논문을 그대로 열면 pdf.js 의 영문 오류 화면이 뜬다. 그래서 `GET /api/books/{id}/pdf` 를 먼저 보내 상태만 본다 — 404 면 "원문 파일이 없습니다", 그 밖의 오류면 "원문을 불러오지 못했습니다…" 를 누른 자리에 보이고(상세는 버튼 아래, 딥리서치는 토스트), 성공이면 연다. 요청 자체가 실패하면 문구 없이 연다 — 네트워크 탓일 수 있어 판단을 뷰어에 맡긴다. 상태만 필요하므로 `finally` 에서 요청을 끊는다 — 끊지 않으면 PDF 를 확인에서 한 번, 뷰어에서 또 한 번 받는다. 확인 중에는 다시 누르는 것을 무시하는데, 확인 요청이 멈추면 버튼이 영영 먹지 않는다. 그래서 10초가 지나면 끊고 뷰어에 맡긴다(품질 검토 `f383bc5`). 이 셋(상태·끊기·제한 시간)은 `pdfStatus`, 상태와 재클릭 무시는 `usePdfOpener` 가 맡아 딥리서치와 상세가 같은 규칙을 쓴다. (§2.22·§2.23)

**Q7. 왜 `disabled` 대신 `aria-disabled`·`aria-busy` 를 썼나?**
A. `disabled` 인 버튼은 초점을 받을 수 없어서, 초점을 쥔 채 `disabled` 가 되면 초점이 `body` 로 떨어진다. 원문 뷰어의 쪽 넘기기에서 마지막 쪽에 닿는 순간, 상세의 [원문 보기]에서 누르자마자 확인 중이 되는 순간이 그렇다. 키보드 사용자는 제자리를 잃고 다시 Tab 으로 찾아와야 한다. `aria-disabled="true"` 는 초점을 지키면서 스크린리더에 "사용할 수 없음"을 알리고, 모양은 CSS 속성 선택자로 흐리게 한다. 대신 눌렀을 때 아무 일도 없게 하는 것은 코드의 몫이다 — 넘기기는 `stepChunk` 가 끝에서 멈추고, 인용 대목은 같은 칸이면 돌아가며, 확인 중 재클릭은 `checking` 으로 무시한다. `aria-busy` 는 "처리 중"을 알리고 `cursor: progress` 로 보인다. 이유 문구는 `role="alert"` 로 읽히고 `aria-describedby` 로 버튼에 이어진다. (§2.20·§2.24)

**Q8. 이 논문으로 딥리서치는 왜 바로 시작하지 않나? 질문 초안에서 조사는 어떻게 다뤘나?**
A. 딥리서치 한 번은 분 단위의 시간과 GPU 를 쓰는데, 제목·키워드로 기계가 만든 질문은 사용자가 궁금한 것과 다를 수 있다. 그래서 초안을 논문 검색 입력창에 딥리서치 칩을 켠 채 채우고 초점을 글 끝에 둔다 — 고쳐 쓰고 보내게. 랜딩의 예시 질의를 누르면 입력창만 채우게 한 round04c 의 결정과 같다. 초안이 든 주소(`?draft=`)는 채운 뒤 `draft` 만 뗀다. 남기면 새로고침·뒤로 가기마다 고쳐 쓰던 글을 덮는다. 조사는 **붙이지 않는 틀**로 피했다 — "「제목」에서 출발해, 키워드 관련 선행 연구는 …" 처럼 제목·키워드 바로 뒤에 받침에 따라 바뀌는 을/를·와/과가 오지 않는다. 길이는 코드포인트로 세어 잘라 이모지가 반쪽이 되지 않게 하고, 서버 질문 한도 안에 드는지 테스트가 확인한다. vue-router 의 쿼리 해석을 거친 왕복(특수문자·이모지)도 테스트한다. (§2.19)
