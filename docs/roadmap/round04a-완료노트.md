## 3. 라이브에서 발견해 고친 버그 — 종합이 절 1개만 만들었다 (`451f348`)

**증상**: 하위질문 3개에 근거 10편을 모았는데 보고서는 절 1개, 논문 1편, 향후 과제 1개. Step 7 의 무결성 검사(미해석 마커)는 `set()` 으로 통과했다 — 검사가 **무결성만 보고 구성을 보지 않았다.**

**원인**: 전체를 한 번의 호출로 맡긴 종합 프롬프트의 JSON 예시가 "섹션 1 · 논문 1 · 과제 1" 모양이었고, gemma-3-12b 가 그 개수를 그대로 베꼈다. 동시에 spec §4-1 위반이었다 — "불릿을 그 논문의 근거만 넣고 생성하면 인용이 구조로 정해진다"인데, 어느 절·어느 논문을 실을지를 모델이 고르고 있었다.

**수정**:
- 하위질문마다 호출 1회. 소제목은 하위질문 그대로, 논문 목록은 그 하위질문의 근거 순서대로 최대 5편(`PAPERS_PER_SECTION`)을 코드가 정한다(`synthesizer.build_section`). 모델은 도입·요약·향후 과제 **문장만** 쓴다.
- 모델이 빠뜨린 요약은 빈 요약으로 싣고 한계에 "요약을 생성하지 못한 논문 N편". 일부 절 파싱 실패는 "서술을 생성하지 못한 절 N개"로 보고하고 넘어가며, **전부 실패하면 예외** — 서술 0줄짜리 보고서를 completed 로 두면 `stage=explored` 재시도 기회가 사라진다.
- 수정본을 배포 전에 **같은 잡의 `state_snapshot` 으로 종합만 드라이런**(DB 쓰기 없음, 워킹트리 코드를 gzip+base64 로 stdin 스크립트에 박아 `nl-lib-fastapi` 에서 실행)해 절 3 · 논문 9/10 · 요약 12/12 를 확인한 뒤 배포했다. 탐색 비용 없이 같은 근거로 전후를 비교할 수 있어 유용했다.
- 그 드라이런에서 모델이 **대표 논문 요약에도 `[E7]` 을 달았다.** 요약은 `bind_markers` 를 거치지 않으므로 지어낸 번호가 검증 없이 나갈 수 있다 → `citations.strip_markers` 로 전부 걷어낸다(인용은 칩이 구조로 이미 가짐). 프롬프트에도 금지를 명시.
- plan Task 11 Step 7 에 구성 검사(절 수·논문으로 실린 근거·요약 속 마커)를 추가.

## 4. 결정

- **실행 모델은 비동기 Celery + SSE 중계 + DB 영속의 결합.** 동기 SSE 는 탭을 닫으면 소실되고, 순수 비동기는 시연에서 기다리는 그림이 안 남는다(spec §2-1).
- **LangGraph 미도입.** 분기가 "한 번 더 돌까"와 "승인 대기" 둘뿐이라 상태 dataclass + async 함수로 충분하다. 단계 함수는 나중에 노드로 그대로 꽂을 수 있게 짰다(spec §2-2).
- **진행 기록 2계층.** 굵은 단계는 `research_steps`(영구), 잔이벤트는 Redis pub/sub(휘발). 재접속 시 Postgres 로 뼈대를 복원하고 Redis 로 이어받는다(spec §2-3).
- **인용 2갈래.** 대표 논문 요약은 구조적 인용(모델이 고르지 않음), 도입·향후 과제는 `[E#]` 마커 + 전수 검증. 지어낸 번호는 1건부터, 무근거 서술은 3건부터 한계에 보고.
- **종합은 하위질문별 호출이고 절·논문 구성은 코드가 정한다** — §3. 모델에게 구조를 맡기면 예시의 개수를 베낀다.
- **절당 대표 논문 5편 상한 유지.** "대표 핵심 논문"이 spec 의 뼈대이고, 이번 실측에서 근거 1편(6편 중 6번째)이 이 상한으로 빠졌다.
- **`status` 와 `stage` 분리.** 종합이 실패하면 `stage=explored` 와 `state_snapshot` 이 남아 `POST /retry` 가 탐색을 건너뛰고 종합부터 다시 한다.
- **원문 보기는 자체 PDF(`/api/books/{cnts_id}/pdf`).** `uci`·`url` 이 논문 236,513편 전부 0건이라 외부 링크 분기는 운영에서 죽은 코드다.
- **비동기 테스트는 `asyncio.run(...)` 관례.** `pytest-asyncio` 는 설치하지 않는다 — 플러그인 없이 `@pytest.mark.asyncio` 를 쓰면 코루틴이 실행되지 않고 통과로 처리된다.

## 5. 라이브에서만 드러난 함정

`docs/ops/recurring-gotchas.md` 에 반영(13·14·15번).

- **13** — `services.search.pipeline` 을 모듈 최상단에서 import 하면 torch 가 없는 로컬에서 pytest collection 이 통째로 죽는다. 함수 본문 안에서 import.
- **14** — 운영 스키마는 Alembic 이 아니라 `create_all` 이 만든다. `alembic_version` 이 `0003` 인데 `0004` 객체가 전부 실재해 `upgrade head` 가 `DuplicateColumn` 으로 죽는다. 객체 확인 후 `stamp`.
- **15** — LLM 은 프롬프트 JSON 예시의 **개수**를 베낀다. 예시에 항목이 하나면 출력도 하나다. 구성(몇 개·무엇을)은 코드가 정하고 모델에게는 채울 칸만 준다. 검증 스크립트도 무결성뿐 아니라 구성을 봐야 잡힌다.
- **취소 API 는 즉시 `canceled` 를 반환하지만 워커는 진행 중인 하위질문을 마저 돈다.** `status` 만 보고 "끝났다"고 판단하면 `running` 인 step 을 보게 된다. 취소 검증은 잠시 뒤 step 이 `done` 으로 닫혔는지와 이후 step 이 없는지로 한다. (설계대로의 동작이라 함정 목록에는 넣지 않았다.)

## 7. 이월

- **재개(retry) 경로 라이브 미검증** — 종합 실패가 자연발생하지 않았다. 단위 테스트로만 덮여 있다.
- **도입 문단의 "문장마다 `[E#]`" 지시가 연결 문장에도 인용을 붙인다** — 실측: `본 절에서는 … 분석한다 [E1]`. 허위 인용이 무표기 연결 문장보다 나쁘지만, 지시를 풀면 무근거 서술 임계(3건)에 더 자주 걸린다. 대회 이후 판단.
- **한계 문구와 실린 논문 수 불일치** — 한계는 "근거 6편"인데 절에는 상한 5편만 실린다. 사용자가 세어 보면 어긋난다.
- **기본 파라미터 실측 없음** — 설계값 5~7분(하위질문 6·재탐색 3) 미측정. 시연 전 1회 필요.
- **시연 질문·파라미터 미정** — 이번 질문은 세 하위질문 모두 `insufficient` 라 시연에 부적합하다. 근거가 두터운 분야로 고르고, planner 가 비결정적이므로 **미리 돌려둔 보고서를 여는 방식**을 권한다(plan Step 10).
- **`alembic stamp 0004`·`0005` 실행 여부 확인 필요** — 잡이 정상 동작하므로 테이블은 있다(`create_all`). 스탬프를 맞췄는지는 이 노트 작성 시점에 확인하지 않았다.
- **`create_all` 과 Alembic 의 이중 스키마 관리 정리** — 함정 14번의 근본 원인. 대회 이후.
- **원본 PDF 가 없는 논문의 원문 보기 404** — round04b 몫(spec §4-3).
- **[보안] `app/api/admin.py` Milvus expression injection** — round01 이월 유지. 대회 이후.
