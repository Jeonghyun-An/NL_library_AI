# round04c 교본 (4) — 화면: 걸러낸 것을 보이기·배치 자동 전환

> 이 교본 하나로 round04c 전체를 클론코딩할 수 있어야 한다. 코드는 저장소 파일을 그대로 수록했다(`GIT_WORKFLOW.md` §개발 가이드 문서).

전체 개요·검증·Q&A 는 [00-개요.md](00-개요.md) 참조.

## 이 챕터의 자리

round04b 가 만든 딥리서치 화면(진행 패널·탐색 타임라인·보고서·Word·PDF 내보내기) 위에 round04c 의 결과를 얹는다. 두 갈래다.

1. **무관 제외를 보이기**(spec §4 화면·§11) — 타임라인 회차 줄의 "무관 N편 제외 ▾" 펼침, 카운터의 "제외" 칸, 보고서 한계 뒤 접힌 "관련성이 낮아 제외한 논문 (N)", 서론의 걸러낸 수, 문서 부록, 끈 잡의 "무관 의심 N편(제외 안 함)".
2. **운영 확인 뒤 사용자 요청 화면 수정**(2026-09-30) — 제외 설명 문구(`a303325`), 배치 자동 전환(`2e3d87a`, round04b spec §7-5), 예시 질의는 입력창만 채움(`2d8320d`), 운영 API 미리보기 설정(`9bba9c4`).

모든 파일이 round04b 끝(`d845b8b`) 대비 diff 다(`git diff d845b8b 9bba9c4 -- <경로>` 출력 그대로). 저장소(git 인덱스)에는 이 파일들이 모두 LF 로 들어 있다(`git ls-files --eol` 의 `i/lf`). 작업 트리의 줄바꿈은 `core.autocrlf=true` 와 체크아웃 이력에 따라 파일마다 다를 수 있다 — safeguards plan 은 계획 당시 작업 트리에서 `researchDraft.ts`·`pages/research/[id].vue` 를 CRLF 로 적었다. 따라 칠 때는 파일의 지금 줄바꿈을 지킨다(Edit 도구로 고친다).

**원칙 셋.**

- **목록을 만드는 순수 함수는 한 곳**(`researchReport.ts` 의 `excludedFromTrail`·`excludedFromSubqs`·`excludedPaperLine`)이고, 타임라인·보고서 화면·문서가 같은 목록과 같은 한 줄 문구를 쓴다. 문구 상수(`EXCLUDED_TITLE`·`EXCLUDED_WHY`)도 화면과 문서가 같이 쓴다 — `a303325` 의 문구 수정이 세 곳에 한 번에 닿은 이유다.
- **옛 잡은 그대로 보인다.** 새 칸이 없는 회차·trail 은 `null`·빈 목록으로 받고, `null` 이면 그리지 않는다. 카운터의 제외 칸도 옛 잡에는 없다.
- **인터랙티브함 우선**(round04b spec §7-4 — 기획자 시연에서 배치 A 가 덜 인터랙티브해 보인다는 피드백). 자기점검이 실제로 걸러낸 장면이 눌러 펼쳐 보여야 한다. 움직임은 `prefers-reduced-motion` 이면 끈다.

컴포넌트(`.vue`)에는 단위 테스트가 없다 — 순수 로직은 Vitest, 컴포넌트는 `nuxi typecheck`·`npm run build` 로 본다(plan 의 검증 방식). 실제 화면(키보드·스크린리더)은 단위 테스트 밖이다.

### 2.18 `researchEvents.ts` — 문구 셋·이벤트 합치기·카운터 합치기

**문구 함수 셋.**

| 함수 | 값 | 그리지 않을 때 |
|---|---|---|
| `excludedLabel(n)` | `무관 N편 제외` — 타임라인 회차 줄과 문서 부록이 같이 쓴다 | 0·`null`(옛 잡) |
| `flaggedLabel(n)` | `무관 의심 N편(제외 안 함)` — 끈 잡. 켠 잡의 "제외"와 헷갈리지 않게 빼지 않았음을 밝힌다 | 0(켠 잡)·`null`(그 전 잡) |
| `showsExcludedCounter(view)` | 제외 수를 받았거나 **잡 파라미터에 `exclude_off_topic` 이 있으면** 칸을 그린다 | 둘 다 없음(옛 잡) |

`showsExcludedCounter` 의 파라미터 조건은 §11 최종 리뷰(`fb0fd27`)에서 들어왔다. 값을 받고서야 칸을 그리면 첫 검색이 끝날 때 카운터가 셋에서 넷으로 늘며 줄이 흔들린다. 새 잡은 API 가 잡을 만들 때 기본 파라미터를 합쳐 저장하므로(02 챕터 §2.15) `params` 에 그 키가 있다 — 옛 잡과 새 잡을 가르는 확실한 표지다.

**이벤트 합치기.** `applyCritique` 가 점검 이벤트의 `excluded`·`excluded_papers`·`flagged` 로 회차를 **바로** 채운다. 뒤따르는 진행 저장 step 이벤트도 같은 값을 싣지만 저장에 실패하면 오지 않는다(02 챕터 §2.10 ⑥). `toRoundView`(저장본)·`blankRound`·`roundsFromQueries`(회차 기록 없는 옛 잡)도 새 칸을 `null`·빈 목록으로 채운다. `toExcludedPaperView` 는 회차 기록과 trail 이 같은 모양으로 받게 하는 변환이다(제목 앞뒤 공백 정리).

**카운터 합치기(`reconcileCounters`) — "줄지 않는다" 전제가 깨졌다** (`b68f287`). round04b 는 라이브 카운터와 저장본 카운터를 **필드별 큰 값**으로 합쳤다. 한 시도 안에서 검토·채택·재검색 수는 늘기만 한다는 전제였다. 무관 제외로 `evidence_adopted` 가 줄 수 있게 되면서 이 규칙이 틀린 값을 남긴다. 테스트의 장면이 이렇다 — 점검 전 counters 이벤트(채택 20)를 받고 스트림이 끊긴 사이 자기점검이 3편을 빼고 탐색이 닫혔다(저장본 17). 종합 단계 이벤트는 카운터를 싣지 않으므로, 큰 값을 남기면 **종합 내내(실패하면 새로고침 전까지) 20 이 남아** 다시 연 화면(17)과 달랐다.

고친 규칙: 저장본을 쓴 단계가 **닫혔고** 그 뒤로 열린 탐색 단계가 라이브·저장본 어디에도 없으면 저장본을 그대로 쓴다. 닫을 때 쓴 값이라 그 단계의 어떤 counters 이벤트보다 새롭다. 다음 하위질문의 탐색 단계가 열려 있으면 지금처럼 큰 값을 남긴다 — 다음 하위질문은 첫 점검 뒤에야 저장본에 카운터를 쓰므로 그 전까지는 라이브가 앞선다. 남은 한계도 주석에 적었다 — 도는 단계 안에서는 여전히 큰 값이라, 그 사이 지운 뒤의 저장본이 오면 지우기 전 수가 다음 counters·step 이벤트까지 남는다.

### 2.19 `researchReport.ts` — 서론의 걸러낸 수·제외 목록·한 줄 문구

**서론 — "편"이 아니라 "건"** (`6b2ea56` → `83101cd`). `reportIntro`(최종본, '~다')와 `draftIntro`(초안, '~습니다') 끝에 `droppedNote` 가 "(하위질문별로 무관하다고 본 N건은 걸러냈다)"를 붙인다. 채택 수만 적으면 무관 제외로 결과가 줄어든 것처럼 읽힌다(spec §11-0 사용자 우려). 처음 문구는 "(무관한 N편은 걸러냈다)"였는데 §11 최종 리뷰가 고쳤다 — 제외 수는 하위질문별 판단의 수라(02 챕터 §2.8) "편"으로 적으면 검토·채택 수와 더해 맞아야 할 서로 다른 논문 수로 읽힌다. 운영 첫 잡이 그 예다 — 검토 121·채택 48·제외 91건으로 48 + 91 > 121 이다(00-개요 §3-5).

**문구 상수.** `EXCLUDED_TITLE`("관련성이 낮아 제외한 논문")과 `EXCLUDED_WHY`. `EXCLUDED_WHY` 는 운영 확인 뒤 "근거에서 뺀 논문입니다" → "근거에서 **제외한** 논문입니다" 로 바뀌었다(`a303325`) — 펼침 버튼("무관 N편 제외")·섹션 제목("…제외한 논문")과 같은 말로 맞췄다. 논문마다의 이유는 없다 — critic 이 논문마다 이유를 쓰게 하면 출력 토큰·파싱 위험이 늘어(spec §11-1) 고정 문구 하나만 둔다.
