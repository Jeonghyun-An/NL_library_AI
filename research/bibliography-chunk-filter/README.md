# 참고문헌 목록 조각 거르기 — 운영 근거 회귀 확인 (2026-10-14)

딥리서치 보고서·이어가기의 근거 대목이 논문 끝 참고문헌 목록 조각인 문제(인용칩에 서지 목록이 뜨고 '겹치는 대목 문장을

머리(`Ⅵ. 참고문헌`)는 번호 뒤 마침표에서 잘려 대목 끝에 `Ⅵ.` 이 매달렸다 — 번호까지 뗀다. ③ 짧은 조각 갈래의 자리 수를 학위
논문 꼴을 빼고 센 수와 넣고 센 수 중 큰 쪽으로 센다: 떨어진 두 꼴(`20(1),`·`(2010).`) 사이에 `석사학위논문.` 이 끼면 40자 안으로
이어져 한 자리로 묶여, `c21ce10` 에서 걸리던 105자 학위논문 조각(합성 테스트)을 놓쳤다. 903개에서 `c21ce10` 보다 자리가 준
청크가 22개(그중 짧은 `KCI_FI001722941__0022`·`KCI_FI001002172__0037` 은 3 → 2 로 문턱에 걸쳤다)에서 0개가 됐다. 위 사사 각주
꼴과 함께 다시 판정해도(운영에서 GET 으로 다시 받은 903개, 원문·synthesizer 꼴 둘 다) 참고문헌 169·풀려남 0·꼬리를 뗀 11개와
뗀 글, `result.txt`·`result_thesis_tail.txt`, 학위논문 꼴 일치 133개가 글자 하나 바뀌지 않았다.

## 남은 것

- 놓침: 서지 꼴 한 종류뿐인 목록(`KCI_FI002065605__0042`·`KCI_FI002065605__0043`·`KCI_FI002537295__0024` — 0026·0035 는
  10-15 학위논문 꼴로 걸린다), 꼴이 한 자리에 몰린 짧은 영문 조각(`KCI_FI002180204__0066`), `<br>` 로 항목이 이어진 영문 IEEE
  목록(`KCI_FI002267397__0032` — `<br>[30]` 의 번호 꼴은 앞이 공백이 아니라 세지 못한다), 한국어 저자-연도 꼬리 + 영문 초록.
  지금보다 나빠지지는 않는다.
- 짧은 조각 갈래는 출처 줄 두 개뿐인 300자 이하 조각(서술 0)도 거른다. 근거로서의 값은 거의 없다.
- 본문 한 문장 + 참고문헌인 청크(`KCI_FI000965838__0050`·`KCI_FI001267084__0022`)는 걸려 맺음 한 문장을 잃는다. 머리 뒤 몫이
  0.6 에 못 미쳐 본문으로 남는 청크는 이제 대목에서 꼬리를 떼므로, 이 둘도 거르는 대신 꼬리만 떼는 쪽을 따로 견줄 수 있다.
- 머리 갈래의 청크 맨 앞 머리(`_HEAD_START`, 앞 60자 안)는 같은 줄에 서지 항목이 이어도 머리로 보므로, 문장 속
  `References [3] and [4] used the same scale (Kim, 2012, p. 45). …` 로 시작하는 영문 본문은 청크째 걸린다(합성 예 — 운영
  903개에는 없다). 같은 줄 갈래를 빼도 903개의 169개 판정은 같지만 한 항목짜리 `참고문헌 김철수 (2010). …` 조각을 놓친다.
- 꼬리 떼기는 모델에 넘기는 대목(딥리서치 절 생성·이어가기 passages)에만 쓴다. critic 발췌(`critic.py` 앞 N자)와 인용칩
  팝오버 원문에는 꼬리가 그대로 있다.
- 영어 논문 비중이 큰 질의는 표본이 적다. 배포 뒤 예시 질문 1~2개로 근거 수·소요 시간(critic insufficient → 재검색)을 본다.
